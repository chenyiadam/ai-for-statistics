# 第20章 案例、工具链与资源总表

> **本章定位**：本章是全书的索引性附录，不引入新的理论，只把前面十九章中可复制的资产集中在一起：提示词模板、SKILL.md 骨架、数学证明案例模板、复现命令，以及五张交叉索引总表（开源项目、论文、工具链、云平台与硬件、学习资源）。
> **关键词**：提示词模板、SKILL.md、证明案例模板、复现命令、资源总表

## 本章导读

前十九章的内容在使用时会遇到一个实际问题：需要某一条命令或某一个模板时，要回想它出现在哪一章。本章解决的是检索问题，而不是知识问题。

20.1 到 20.4 是"可复制资产"，每项都以代码块给出，可直接粘贴后改写：提示词模板取自第 6 章的模板库与第 11 章的形式化工作流；SKILL.md 骨架遵循第 7 章的 Agent Skills 规范；数学证明案例模板是第 11 章工作流的标准化文档形式；复现命令按工具分组，覆盖形式化验证、推理部署、环境锁定与云平台四类场景。

20.5 到 20.9 是五张交叉索引总表，每行给出"名称、用途一句话、链接、出处章节"。出处章节指该资源在本书中被讨论的位置，读者可据此回到正文查看上下文。表中条目以本书前十九章实际出现过的资源为主，少量条目为便于检索而补充，均只给出官方主页或仓库地址。

三条使用说明。第一，链接指向的多为活跃的开源项目与官方站点，其地址、许可与功能可能变化，遇到失效时以项目的官方主页为准。第二，总表不评价资源的优劣，也不保证其当前状态；选择工具时应结合第 9 章的选型框架与第 18 章的合规要求。第三，凡涉及价格、配额与政策的具体数值，一律以服务方的当期公布为准，本表不列具体价格。

## 20.1 提示词模板

下面十个模板按用途排列，出处章节标在注释首行。使用时的通用约定：变量用 `{{ }}` 占位，运行前由脚本渲染；把"输出格式"写成结构化的字段而非自由文本，便于后续程序解析与批量比对；对需要数值结论的任务，要求模型同时给出依据与不确定性，而不是只给出一个数字。

### 模板 1：统计检验方法选择（出处：6.11.5）

```text
# 角色与任务
你是统计学审稿人。给定一项研究的数据描述与研究问题，选择合适的检验方法，
并说明选择依据与前提假定。

# 输入
数据描述：{{data_desc}}
研究问题：{{question}}
显著性水平：{{alpha}}

# 输出格式（严格遵守，便于程序解析）
1. 变量类型判定：因变量（类型/分布）、自变量（类型）、是否配对/重复测量
2. 候选方法：列出 2–3 个候选及其核心假定
3. 假定检验：对每个候选，写明需要检验的假定（正态性、方差齐性、独立性、
   样本量是否足够），以及检验该假定的具体方法
4. 推荐方法：给出首选与备选，说明若首选假定不满足时的切换路径
5. 效应量与区间：给出应当报告的效应量与置信区间类型
6. 不适用警告：明确列出本数据不适合的方法，并说明原因

# 约束
- 不要推荐需要假定而数据明显不满足的方法。
- 若信息不足以判定，列出缺失的信息，不要猜测。
- 区分探索性分析与确认性检验。
```

## 20.2 SKILL.md模板

下列三个骨架遵循 Agent Skills 开放标准（规范见 agentskills.io），字段、目录结构与三级加载机制的完整说明见第 7 章 7.7 节。三个骨架分别对应科研中最常见的三类任务：数据处理、文献工作、形式化验证。

共同约定：文件夹名用 kebab-case；`SKILL.md` 文件名区分大小写；frontmatter 必填 `name` 与 `description`，`description` 同时回答"做什么"与"何时用"，并写入真实触发短语；正文控制在 500 行以内，超出部分移入 `references/`；确定性工作一律写成脚本由智能体执行，不让模型即兴生成计算过程。

### 骨架 A：数据处理类

```markdown
---
name: stat-data-clean
description: 清洗与质控结构化数据（CSV/Parquet），处理缺失值、异常值与编码不一致，
             输出清洗日志与质控报告。当用户提到"数据清洗""缺失值""质控"
             "编码不一致"或上传了原始数据表时使用。
version: 0.1.0
allowed-tools: Bash, Read, Write
---

# 数据清洗与质控

## 何时使用
用户提供了原始数据表并需要进入分析前的清洗与质控阶段。

## 环境
- Python 3.10+；包：pandas, numpy, pyarrow, scipy
- 安装：uv pip install -r scripts/requirements.txt

## 执行流程
1. 用 `scripts/profile.py <input>` 生成数据画像（行列数、类型、缺失率、唯一值数）。
2. 读取 `references/codebook.md`，逐变量核对取值域与编码规则；不匹配项写入
   `qc_issues.csv`。
3. 对含缺失的变量判断缺失机制（MCAR/MAR/MNAR），判断依据写入报告，
   不得默认 MCAR。
4. 用 `scripts/clean.py --input <input> --rules <rules.yaml>` 执行清洗，
   输出 `clean.parquet` 与 `clean_log.csv`（每样本一行处理记录）。
5. 用 `scripts/qc_report.py` 生成 `qc_report.md`：清洗前后对比、
   删除样本数、插补变量清单、敏感性分析待办。

## 硬约束
- 不得在未运行脚本的情况下给出清洗结论。
- 删除样本必须记录原因并可追溯；删除比例超过 5% 时必须提示用户确认。
- 不得在原数据文件上原地覆盖；所有产出写入新目录。
- 随机过程（插补、划分）必须固定种子并写入报告。

## 输出
- `clean.parquet`、`clean_log.csv`、`qc_report.md`
```

### 骨架 B：文献类

```markdown
---
name: lit-review-update
description: 按主题增量检索文献（arXiv/Semantic Scholar）、去重、结构化抽取并生成
             综述更新表。当用户提到"文献更新""检索最新论文""综述进展"
             "这个方向最近有什么工作"时使用。
version: 0.1.0
allowed-tools: Bash, Read, Write, WebFetch
---

# 文献增量检索与结构化抽取

## 何时使用
需要对某一研究主题做定期（每周/每月）文献追踪，或撰写综述前建立候选集。

## 环境
- Python 3.10+；包：requests, pandas, pyyaml
- 可选：Zotero MCP（检索本地文献库、批量导入、生成引用格式）

## 执行流程
1. 从 `references/topics.yaml` 读取检索式（关键词组、分类、时间窗）。
2. 运行 `scripts/search_arxiv.py --topic <name> --since <YYYY-MM-DD>`，
   产出候选列表 `candidates.csv`（含标题、作者、摘要、链接、日期）。
3. 用 `scripts/dedup.py` 与已有库（`library.csv` 或 Zotero）去重，
   按 DOI/标题相似度两级判定。
4. 对新增条目按 `references/extract_prompt.md` 的字段做结构化抽取，
   只抽取原文明确出现的信息，缺失字段标记为 missing。
5. 生成 `update_<date>.md`：新增条目数、按主题分组的表格、
   与既有工作的关系标注。

## 硬约束
- 不得编造文献条目、标题、作者、期刊或链接；检索不到就报告为空。
- 每条结论必须附原文依据（摘录或段落定位）。
- 无法判断相关性时标记为"待人工判断"，不得自行剔除。

## 输出
- `candidates.csv`、`update_<date>.md`、`library_update.bib`
```

# Lean 4 命题形式化与验证

## 何时使用

## 执行流程

## 20.3 数学证明案例模板

### 20.3.1 六必填区块

一份可归档的数学证明案例文档包含六个必填区块。设计目的是把"得到一个证明"的过程拆成可分别审计的环节：区块一与二由人负责（命题与假设），区块三到五由人或 AI 完成、由机器验证，区块六由人复核。缺任何一个区块，该案例都无法被第三方评估。

| 区块 | 名称 | 内容 | 由谁负责 | 常见缺陷 |
|---|---|---|---|---|
| 一 | 命题 | 自然语言命题与来源（教科书/论文/自拟） | 人 | 命题含歧义术语，量化范围不明 |
| 二 | 假设清单 | 逐条列出假设，标注在 Mathlib 中的对应形式与检索词 | 人 + 检索 | 假设被隐含使用而未列出 |
| 三 | 引理分解 | 3–6 个引理的陈述与证明思路，标注哪些已存在于 Mathlib | 人或 AI | 分解过粗，一步无法验证 |
| 四 | 形式化 | Lean 代码：theorem 陈述与证明 | 人或 AI | 形式化与自然语言命题不等价 |
| 五 | 验证命令 | 编译、sorry 检查、公理检查的命令与预期输出 | 机器 | 只跑 build 而不检查 sorry |
| 六 | 复核记录 | 语义比对结论、复核人、日期、发现的问题、置信度 | 人 | 复核人与作者为同一人 |

### 20.3.3 填写要点

区块一要求逐字写出命题，是因为形式化阶段最容易发生的错误不是证明错，而是证了一个不同的命题——例如把"几乎必然收敛"写成"依概率收敛"，或把条件期望的可测性前提省略。区块二的"未使用假设"一栏专门用于暴露此类偏差：若声明的假设未被使用，通常意味着形式化比原命题更弱。

区块五的公理检查不可省略。含 `sorry` 的文件可以编译通过，但其中的定理只是被声明而未被证明；`#print axioms` 输出中的 `sorryAx` 是唯一的机器信号。第 17 章 17.5.3 给出了完整的检查命令与目录结构。

区块六要求复核人与作者分离，理由与第 17 章 17.7.3 的独立复现者相同：同一人对自己的形式化做语义比对时，会系统性地重复当初的误解。

## 本章小结

1. 十个提示词模板分别对应统计分析中最常复用的十类任务：检验选择、数据清洗、文献抽取、代码审查、同行评审、定理推导检查、推导加代码验证、自我纠错、多视角验证、命题形式化。
2. SKILL.md 的三种通用骨架（数据处理、文献、形式化验证）遵循同一套规范：frontmatter 的 `description` 是唯一的路由依据，正文写编号步骤，确定性工作一律脚本化，并写明禁止行为；完整规范见第 7 章。
3. 数学证明案例文档的六必填区块把证明过程拆为可分别审计的环节，其中"验证命令"区块的 `sorry` 检查与公理检查不可省略，"复核记录"区块要求复核人与作者分离。
4. 复现命令按工具分为十五组，覆盖 Lean 工具链、证明搜索、推理服务、本地运行、模型下载、环境锁定、数据版本、容器镜像、云端操作、MCP 配置、实验追踪、可执行报告与复现校验。
