# 第1章 引言：AI赋能科研的背景

## 本章导读

2026 年的 用AI产出结果 已经从"谁的模型更强"转向"谁的模型先完成长链路任务"。这一转向对统计研究者意味着两件事：一是模型能力的评估单位从单轮问答变成了可审计的工作流，二是研究者需要判断的不再只是"这个回答对不对"，而是"这条产出链能否被复算、被验证"。


本章与后续章节的对应关系如下：1.4 对应第 10 至 14 章，1.5 对应第 7、8 章，1.6 对应第 2 至 4 章与第 19、21 章，1.7 对应第 16 章，1.8 对应第 17 章。可先通过本章建立对全文大体的了解，再按 1.9 的索引表跳转到需要的部分。

## 1.1 2026年AI发展格局：从模型竞赛到智能体落地

### 1.1.1 全球市场的规模与分化

2026 年第一季度，全球大语言模型月活用户突破 38 亿，季度总营收约 207 亿美元。用户规模与变现能力之间出现了明显分化：按营收计算的市场份额中，Anthropic 以 31.4% 略高于 OpenAI 的 29%，Google 以 12.1% 位居第三，其后为微软 7.2%、腾讯 4.8%、百度 3.6%、阿里 2.9%。

分化在单用户收入上表现得更为清楚。Anthropic 仅凭约 1.34 亿月活用户实现营收领先，而 OpenAI 拥有约 9 亿用户。Anthropic 每位活跃用户的月均收入达 16.20 美元，高于微软的 5 美元、OpenAI 的 2.20 美元、Google 的 1.10 美元；Meta 虽拥有约 10 亿用户，每用户收入仅 0.10 美元。

### 1.1.2 竞争焦点转向智能体与应用效率

竞争焦点正从"谁的模型更强"转向"谁的模型先完成长链路任务"。全球 AI 厂商形成三种路径：OpenAI 的"应用闭环型"、Google 的"平台嵌入型"，以及以国内厂商为代表的"开源权重 + 垂直落地型"。

Gartner 2026 年中国 AI 十大趋势将"全栈式自主可控人工智能"列为基础层，涵盖模型芯片自主化与模型技术栈韧性；第二层为"务实驱动的模型创新"，包括开源权重策略、多模态内容创作与世界模型。国产模型 GLM-5.2、Kimi K3、DeepSeek V4 正在重塑格局。

对科研用户而言，评估单位的转变带来一个方法论后果：单轮问答的准确率不再是充分指标，取而代之的是任务完成率、链路长度、工具调用成功率与失败可恢复性。这些指标本质上是"过程指标"，其测量需要预先定义任务集合与判定规则，否则不同报告之间的数字不可比。

### 1.1.3 中国AI的路径

中国大模型走的是"开源权重 + 极致性价比"的路径。Kimi K3 总参数达 2.8 万亿，在 FrontierSWE 编程榜单上得分 81.2%，高于 GPT-5.6 Sol 的 71.3%。DeepSeek V4-Pro 总参数 1.6 万亿（激活 49B），以 MIT 协议开源，在 100 万 token 上下文下单 token 推理 FLOPs 仅为 V3.2 的 27%，KV Cache 降至约 10%。DeepSeek V4 已获得寒武纪 Day 0 适配支持，相关代码已开源至 GitHub 社区，国产芯片与大模型的协同正在加速。

### 1.1.4 格局判断对研究者的实际含义

三条路径直接影响研究者的工具选型：应用闭环型产品适合以最低摩擦获得可用能力，但可审计性弱；平台嵌入型适合已有工作流深度绑定某一生态的团队；开源权重型允许自建部署、锁定模型版本、记录完整调用日志，这对需要可复现性的统计研究最为关键。第 19 章将给出成本测算的具体方法，第 17 章讨论可复现基础设施。

## 1.2 主流大模型的技术路线与竞争态势

### 1.2.1 国际主流模型

Anthropic 的 Claude 系列旗舰为 Fable 5，日常主力为 Opus 5。Opus 5 官方 API 定价为输入 5 美元/百万 token、输出 25 美元/百万 token，Fable 5 定价为输入 10 美元、输出 50 美元，恰好是前者的两倍。据 Anthropic 自己发布的对比表，Opus 5 在 Frontier-Bench、BrowseComp、OSWorld 2.0 等五/九项直接可比基准上领先 Fable，在 Agent 终端编程、搜索、计算机使用和商业工作流上表现更优。Fable 5 的优势集中在 DeepSWE v1.1（69.7% 对 68.8%）和法律 Agent 基准上。Fable 5 的部分标称数据来自 Mythos 5 配置，而非公开可用的 safeguarded 版本。

OpenAI 的 GPT-5.6 系列分 Sol、Terra、Luna 三档，上下文达百万级，生态完整，工具链成熟。Google Gemini 在多模态和速度上有优势，价格相对友好。xAI 的 Grok 4.x 系列在速度和部分任务上表现不错，价格比 Claude、GPT 旗舰便宜。


### 1.2.2 国内主流模型

**Kimi K3**（月之暗面）：总参数 2.8 万亿，活跃参数 104B，上下文窗口 100 万 token，原生支持视觉理解。采用 KDA 混合线性注意力机制和注意力残差技术。API 定价：输入 3 美元/百万 token，输出 15 美元；缓存命中输入 2 元/百万 token，未命中输入 20 元/百万 token。在 Artificial Analysis Intelligence Index 上得分 44，高于同类中位数 17；价格处于国内头部模型较高水平，速度较慢（约 40 tokens/秒），回答较为冗长。

**DeepSeek V4**（深度求索）：V4-Pro 总参数 1.6 万亿（激活 49B），V4-Flash 总参数 2840 亿（激活 13B），均支持 100 万 token 上下文，均为 MoE 架构。V4-Flash 训练了 32T tokens，V4-Pro 训练了 33T tokens，比 V3 的 14.8T 高出一倍多。最核心的架构改动是分层混合注意力机制，CSA 与 HCA 交替使用：CSA 每 4 个 token 压缩为 1 个 KV cache entry 再跑稀疏注意力，HCA 每 128 个 token 压缩为 1 个 entry 但保持稠密注意力。V4-Pro 的 API 定价：输入命中缓存 1 元/百万 token，未命中 12 元，输出 24 元；V4-Flash 命中缓存仅 0.2 元，未命中 1 元，输出 2 元。DeepSeek 在技术报告中说明，万亿参数 MoE 训练遭遇 loss spike，最终用两个经验性技巧，Anticipatory Routing（解耦主干与路由网络更新）和 SwiGLU Clamping（将 SwiGLU 线性输出钳制到 $[ -10, 10 ]$），才将训练压住。

**Qwen 系列**（阿里）：生态最完整，开源版本多，社区活跃，中文场景和企业落地常见。走 MoE + Dense 双路线，QwQ 系列专注推理能力。

**GLM-5.x**（智谱）：在代码和 Agent 上口碑不错，开源版本（MIT 协议）便于部署。

### 1.2.4 选型与统计研究场景的对应

上述差异直接影响后续的微调、部署与成本决策。DeepSeek 的 MIT 协议和低成本使其成为自建部署的首选基座；Kimi K3 的长上下文和视觉理解适合长文档与图表混排的处理场景；Claude Opus 5 在 Agent 任务上的优势适合复杂工作流；Qwen 的生态完整性适合快速原型开发。

对于统计学研究者来说，需要注意三项约束。其一，确定性：批量实验应固定模型快照、温度与随机种子，并在日志中记录调用时间戳，否则同一提示的输出差异无法归因。其二，可复算：涉及数值结论的调用必须保留原始返回，而不是仅保留模型整理的摘要。其三，成本可控：蒙特卡洛类评估往往需要数千次调用，输入输出单价比单次调用的绝对价格更影响总支出，长提示配短输出与短提示配长输出的成本结构完全不同。

## 1.3 AI赋能科研的范式：从工具到协作者

人工智能（Artificial Intelligence，AI）驱动的科研指以大模型与智能体为调度层，整合文献、代码、符号、形式化和实验工具，构建人机协同、可复算、可审计的科研工作流。

该工作流以大语言模型、多模态模型和科研智能体为中枢，将 AI 作为科研的基础设施与协作者嵌入研究全流程：底层统一处理文本、公式、代码与实验数据，形成可检索的科研记忆；中层通过提示词工程、Skill 与智能体编排，串联统计分析、数值仿真、贝叶斯推断和形式化证明等工具，形成"假设—实验—验证—修正"闭环；高层支持假设发现、定理辅助证明、高维估计与因果识别，并以审计、版本管理和人在回路保障可追溯与可复现。

三层结构可以用一张示意图概括，后文各章分别展开其中一层：

```text
        ┌────────────────────────────────────────────────┐
高层    │ 假设发现 · 定理辅助证明 · 高维估计 · 因果识别    │← 人类：问题定义、
        │ （产出须经验证与解释，学术责任在人类一侧）        │  识别策略、结论解释
        ├────────────────────────────────────────────────┤
中层    │ 提示词工程 · Skill · 智能体编排                  │  串联统计分析、数值
        │ （"假设—实验—验证—修正"闭环的调度层）            │  仿真、贝叶斯推断、
        ├────────────────────────────────────────────────┤  形式化证明等工具
底层    │ 文本 · 公式 · 代码 · 实验数据                    │  统一处理为可检索的
        │ （可复算的科研记忆：版本、种子、哈希、日志）      │  科研记忆
        └────────────────────────────────────────────────┘
```

图中每一层的验证强度并不相同：底层的产物（代码、数据哈希）可以确定性复算，中层的产物（分析流程）可以按契约检验，高层的产物（假设、证明）需要形式化内核或人类专家把关。第 12 章将把这种差异整理为验证机制的可靠性层级。

### 1.3.1 科研范式的演进

科学研究的组织方式经历了经验科学、理论科学、计算科学、数据驱动科学，进而演进到当前以 AI 为基础设施的人机协同科学。在这一演进中，AI 的位置从"工具"变为"协作者"，文献、代码、符号、实验、形式化工具被统一调度。

范式变化的核心不在自动化程度，而在责任分配。工具范式下，研究者对每一个中间步骤负责；协作者范式下，AI 可以生成中间步骤，研究者转而负责定义问题、设定验收标准、验证产出并承担学术责任。这一转变要求把"验证"从隐性的个人判断变成显式的、可记录的流程。

### 1.3.2 与统计学既有范式的对接

把 AI 科研工作流与统计学的既有语言逐项对接，可以得到如下对应。

| 统计学既有范式 | AI 科研工作流中的对应环节 | 需要警惕的差异 |
|---|---|---|
| 实验设计 | 提示词版本、模型版本、解码参数构成"处理"；多次采样构成重复观测 | 同一次会话内的多次采样共享上下文与参数，不满足独立同分布，不能按独立样本做方差估计 |
| 估计与推断 | 基准得分、任务完成率均为有限样本下的点估计 | 需同时报告样本量与区间；单次跑分不构成结论，评估集泄露会使估计有偏 |
| 假设检验 | 多采样一致性检验（SelfCheckGPT 一类方法）判断输出是否自洽 | 其原假设与经典检验的原假设形式不同，缺少可推导的零分布，属于结构类比而非严格检验 |
| 因果识别 | 模型从语料中学到的条件关联 | 模型输出的是 $P(Y \mid X)$ 而非 $P(Y \mid do(X))$，混淆与选择偏差未被控制，不能替代识别策略 |
| 可复现性 | 版本、种子、环境、数据哈希、审计日志 | 商用 API 存在版本漂移与静默更新，需记录模型快照、调用日期与返回原文 |

具体展开四组关系。

**实验设计。** 提示词工程在多版本比较的意义上就是一次析因实验：提示模板、示例数量、输出格式约束、温度都是因子。若每次比较只跑一次，则无法把输出差异与随机性差异分开。合理的做法是按区组设计组织评测，把任务（题目、数据集）作为区组，把提示变体作为处理，在每个区组内比较，从而消掉任务难度带来的方差。第 6 章给出可操作的模板。

**估计与检验。** 模型在基准上的得分是一个点估计，其抽样变异来自评估集与解码随机性两部分。只报告 88.7% 而不报告评估集规模与重复次数，等价于只报告 $\hat\theta$ 而不报告标准误。当前不少公开对比仍然只给点估计，这是读表时需要自行补齐的信息。

**因果识别。** 大模型的训练目标是拟合语料的条件分布，其输出反映的是文本中共现的关联结构。用模型输出支持"X 导致 Y"类结论，等于用观察性关联替代识别策略。可行的处理是把模型定位为假设生成器：由模型提出候选因果结构，再由研究者用实验设计、工具变量、断点回归或前门/后门调整等方法去识别。模型不提供识别，只提供待检验的假设空间。

**可复现性。** AI 科研工作流引入了传统统计研究没有的三类不确定来源：模型版本漂移、解码随机性、外部工具调用的非确定性（检索结果、代码执行环境）。对应的控制手段是记录模型快照标识、固定随机种子并重复采样、用 environment.yml 或容器锁定执行环境、用数据哈希标记输入。第 17 章讨论这一部分。

### 1.3.3 全链路科研平台

上海人工智能实验室发布的"书生·端砚"连接科学大模型、专业分析工具、实验数据与具身自动化设备，覆盖从"假设提出"到"实验验证"的完整流程。以蛋白质改造为例，平台形成"设定目标—模型设计—计算筛选—自动实验—结果判断—反馈再设计"的闭环，并引入独立评审智能体检查引用资料、计算过程和输出结果，以缓解幻觉问题。

独立评审智能体的设置值得单独说明：它把"生成者"与"检查者"分离，这与统计学中分析者与复核者分离的做法同构。当评审智能体使用与被评审者不同的模型或不同的证据来源时，两者同时出错的相关性降低，从而提升检出率。这一机制的成本是额外的调用开销，收益是可审计的错误记录。

### 1.3.4 自主科研智能体案例

斯坦福团队在《科学》杂志报告的 Biomni 能自主执行从数据分析到实验设计的多种研究任务，在多项案例中表现接近人类专家。MatBrain 在电催化剂研究中完成从假设提出、生成 30,000 个候选结构到多阶段计算筛选和实验验证的端到端流程。千问办公协助国家天文台科研团队打造大口径望远镜仿真系统，耗时仅 3 天，成本不到千元。Nature 2026 年 9 月发表的 Paper2Agent 框架将研究论文转换为可交互的 AI 智能体，展示论文的手稿、补充材料、数据集和方法代码，使研究产出从被动文档变为主动系统。

这些案例的共同结构是"AI 自主执行 + 人类审核"。对统计研究者的启示是：可以把可形式化、可自动化验证的环节（数据清洗、描述统计、图形生成、代码重构、数值复算）交给智能体，把问题定义、识别策略选择与结论解释留在人的这一侧。也许未来的科研范式是人只需要进行思考和判断，而之外的事情都由科研工具去完成。

### 1.4.4 形式化验证的思想：命题即类型

形式化验证的核心思想是命题即类型、证明即程序（propositions as types，Curry–Howard 对应）。在 Lean 4 中，一个数学命题被写成一个类型，一个证明就是该类型的一个项。Lean 内核通过类型检查自动验证证明是否正确，通过即百分之百正确，不存在幻觉。这是 AI 数学证明最可靠的验证方式。

Lean 4、Coq、Isabelle、Metamath 是四大主流证明助手。Mathlib4 是全球最大的形式化数学库，超过 150 万行代码。miniF2F 是 488 道奥林匹克级数学题的标准基准，当前最佳结果为 DeepSeek-Prover-V2 的 88.9% 通过率，但端到端流程（自然语言理解 → 形式化 → 证明）准确率仅约 36%。

端到端准确率与形式化证明成功率之间的落差是当前的不足：它说明主要困难不在"证明"，而在"把自然语言命题正确翻译为形式化陈述"。这一观察或者说经验对统计定理也很重要，一个概率不等式若被形式化时漏掉了可测性条件或积分存在条件，形式化证明再正确也不对应原问题。第 11 章讨论这一内容。

### 1.4.5 神经符号定理证明：AlphaProof与DeepSeek-Prover

**AlphaProof** 是 DeepMind 2024 年发布的 IMO 银牌级系统。技术路线：自然语言题目 → 微调 Gemini 翻译成 Lean 形式化语言 → AlphaZero 风格强化学习在 Lean 中搜索证明 → 自我博弈训练（每道题平均尝试百万次）→ Lean 内核最终验证。在 IMO 2024 六道题中解出四道，达银牌水平。

**DeepSeek-Prover-V2** 是当前开源最佳结果。官方同时发布了 671B 主模型与从 DeepSeek-V3-Base 蒸馏的 7B 版本，后者可在消费级显卡上运行。技术路线：强化学习 + 课程学习 + 子目标分解。在 miniF2F-test 上达 88.9% 通过率（据其技术报告）。这是普通团队在有限算力下最接近 AlphaProof 能力的开源方案。

**Claude FLT** 是 Anthropic 将费马大定理完整形式化的项目。1300 万行 Lean 4 证明，Prove2Me 平台，多智能体协作，定理 DAG 维护，消费级订阅可行。Anthropic 后续验证：3 个 Claude Max 订阅 + Prove2Me + 3 天完成 Vinogradov 三素数定理形式化。

### 1.4.6 程序搜索与进化算法：FunSearch与AlphaEvolve

**FunSearch**（2023 年 12 月 在线发表于 Nature）的核心思想：LLM 生成候选程序，评估器打分，进化出更优解。在帽集问题上发现 85 个点的新构造，优于人类已知的 82 个。这是最易于团队复现的路线，只需 Python 加商业 LLM API，无需 GPU 集群。MIT 已开源复现，专为数学家设计，无需机器学习知识。

**AlphaEvolve**（2025）改进了超过 50 个未解数学问题的最优结果，包括 4×4 矩阵乘法 48 次乘法（突破 Strassen 1969 年的 49 次纪录）、11 维接吻数下界。技术路线：多层 LLM 架构（Gemini Flash 筛选 + Pro 精修）+ 进化算法 + 自动评估器 + 异步并行计算图。

**AlphaTensor**（Nature 2022）发现更快矩阵乘法算法，将问题建模为三维张量低秩分解 + 单玩家游戏 + AlphaZero 式强化学习 + MCTS 搜索。

这三条路线的共同思想是评估器即验证器。LLM 生成代码，代码执行结果由确定性评估器打分，完全避免幻觉。输出的不是黑盒神经网络参数，而是可读的 Python 代码，数学家可从中提取规律并证明通用定理。

从统计角度理解"评估器即验证器"：评估器是一个确定性函数 $S(\cdot)$，把候选解映射到可比较的标量或偏序。只要 $S$ 本身可信，整条链路的可信度不再依赖生成者的可靠性。这与统计学中用检出力（power）评估检验函数、用风险函数评估估计量的思路一致，评价函数的性质决定了搜索的有效性。评估器设计的常见陷阱包括：评估指标与真实目标不一致（代理指标过优）、评估集过小导致过拟合搜索、评估器本身有随机性而未固定种子。

评估器并不需要复杂的实现。下面是一个小示例：在随机向量上数值检验 Cauchy–Schwarz 不等式。它的结构，固定种子、构造候选、计算判据、返回标量，与 FunSearch 一类系统中评估器的结构完全相同，只是规模小得多。

```python
# 最小评估器示例：数值检验 Cauchy-Schwarz 不等式 |<x,y>| <= ||x||*||y||
# 评估器本身就是几行确定性代码，其正确性可以直接审查，这是它可信的来源
import numpy as np

rng = np.random.default_rng(2026)          # 固定种子：评估结果可复现

def evaluator_cauchy_schwarz(n_trials=1000, dim=50):
    """在随机向量上数值检验 Cauchy-Schwarz，返回观测到的最大比值。"""
    worst = 0.0
    for _ in range(n_trials):
        x = rng.normal(size=dim)
        y = rng.normal(size=dim)
        ratio = abs(x @ y) / (np.linalg.norm(x) * np.linalg.norm(y))
        worst = max(worst, ratio)
    return worst                            # 理论上不超过 1

print(evaluator_cauchy_schwarz())           # 实测约 0.43，始终 <= 1
```

实测的最大比值约 0.43 而非接近 1，高维随机向量以高概率近似正交，$|\cos\theta|$ 的典型量级约为 $\sqrt{2\ln(n_{\text{trials}})/\dim}$，这与第 3 章自注意力"核加权平均"解释中高维集中的直觉一致。评估器没有发现任何反例，与不等式成立相符。

这个示例说明评估器的两个固有局限。其一，评估器只在有限样本上判别："1000 组随机向量上未见反例"不等于不等式成立，它对搜索过程可信，对证明无效，把数值检查当证明是初学者常见的错误使用。其二，评估器自身可能有缺陷：若把上面代码中的内积改在 float16 下计算，数值误差会使比值偶尔超过 1，评估器便会对正确的候选给出"违规"判定；反之，若判据写错（比如漏掉绝对值），它也可能放过本应被淘汰的候选。评估器在投入使用前应当先用已知答案的"正例"与"反例"各校验一遍。

### 1.4.7 反例发现与猜想证伪

AI 不仅能证明定理，还能发现反例、推翻猜想。2026 年 5 月，OpenAI 内部模型自主推翻 Erdős 单位距离猜想（悬置 80 年），不是证明已知结论，而是找到反例推翻它。技术路线：代数数论构造反例，CM 域 + 无限类域塔 + Golod-Shafarevich 准则 + 有界窗口嵌入。论文由 Victor Wang 等人撰写，九位顶级数论学家独立评述，包括菲尔兹奖得主 Timothy Gowers。

这一案例的方法论价值在于：AI 在人类盲区中发现反例。此前人类数学家大部分时间在试图证明 Erdős 是对的，而非寻找反例；即便寻找反例，也需要代数数论专家身份，而离散几何学家几乎没人具备。

### 1.4.8 人机协作与众包：等式理论项目

陶哲轩领衔的等式理论项目（2024 年 9 月启动）在 57 天内完成 4694 个定律的形式化，检验约 4694×4694 个蕴含关系。技术路线：GitHub 众包协作 → 每个蕴含关系用 Lean 形式化证明 → 自动化工具处理简单情况 → LLM 辅助中间情况 → 社区人类专家攻坚最困难情况。这是最易参与的 AI 数学项目，不需要证明能力，只需将自然语言数学陈述转写为 Lean 代码，LLM 可辅助完成约 80% 的转写工作。

该项目的组织方式对统计研究有一些启发：把一个大规模但结构重复的任务拆解为可并行的单元，用自动化处理多数简单单元，把人力集中到困难单元。这与统计实践中"批量预处理 + 人工复核异常值"的分工同构。

### 1.4.9 思想方法总结

五条路线、多个案例背后反复出现的是同一个流程。如图：

```text
            ┌──────────── 生成（LLM 产生候选证明/程序/构造）
            │
            ▼
  人类猜想 ─▶ 评估（Lean 内核 / 确定性评估器打分）
            │
            ▼
            └──────────── 搜索或进化（保留优者、淘汰劣者、变异再生成）
                             │
                             ▼
                        验证（对最终候选做最强校验：
                        内核通过 / 评估器复跑 / 人类专家审阅）
```

关键的不对称在于：闭环里"生成"这一步可以不可靠，因为"评估"会拦截错误；但"评估"这一步不可靠，整条链路就会放大错误而不是抑制错误。因此工程投入的优先级应当是先加固评估器，再提升生成器，这与实验设计中先保证测量的效度、再讨论样本量的次序一致。

具体可以总结为以下几条。

- **生成—评估—搜索—验证闭环**：LLM 生成候选，评估器或内核验证，搜索或进化迭代，保留最优。
- **可读代码与数学洞察**：FunSearch 输出的 Python 代码可被数学家阅读，提取对称性规律并证明通用定理。
- **反例思维**：不必证明定理为真，只需找到一个构造性反例即可推翻。
- **跨域迁移**：AI 从几何问题跳转到代数数论找到反例。
- **单次推理与百万次搜索的取舍**：Erdős 案例是"一次推理 + 人类验证"，AlphaProof 是"百万次搜索 + 内核验证"，两种范式适用不同问题。
- **人类盲区的量化**：此前人类试图证明而非证伪；AI 的价值在于不受人类思维定式约束。
- **形式化与自然语言互补**：自然语言提供直觉与思路，形式化提供零幻觉验证。

### 1.4.10 局限与争议

陶哲轩 2026 年 ICM 警示：AI 在开放数学问题上的真实成功率仅 1%–2%；AI 是"跳高运动员"（只能越过已知高度），人类是"攀岩者"（在失败中创造新抓手）；数学正从"证明稀缺"走向"证明过剩"，面临"理解力危机"。25 位菲尔兹奖得主（含陶哲轩、许埈珥、Maynard 等）已联合声明警惕 AI 对数学研究的冲击。

对统计研究者，这一情况有三层含义。第一，成功率 1%–2% 的语境是开放数学问题，不应当外推到常规科研辅助任务（文献整理、代码生成、格式转换），后者的成功率显著更高。第二，"证明过剩"意味着验证能力将成为瓶颈而非生成能力，统计学的不确定性量化方法在此有直接应用空间。第三，统计定理的形式化比纯数学定理更难，因为需要处理测度论基础、可测性条件与极限定理中的极限交换，Mathlib4 中概率论部分的成熟度低于代数部分。第 11 章给出具体路径，第 16 章讨论相关的统计理论问题。

## 1.5 Skill与科研自动化

### 1.5.1 Skill的本质：能力封装而非提示词

Skill（Agent Skills）是 Anthropic 于 2025 年 10 月发布的开放标准（agentskills.io），本质是"一个文件夹 + 一个 SKILL.md 清单文件"。与传统提示词工程不同，Skill 不是告诉 AI 怎么说话，而是告诉 AI 怎么做事情，它是一套结构化的能力封装，包含输入输出规范、执行逻辑、依赖工具链和验证规则。核心优势体现在三方面：可复用（一次封装、多场景调用）、可组合（多个 Skill 可编排为复杂工作流）、可验证（每个 Skill 的输入输出有明确约定）。

第三条对统计研究最为重要。"输入输出有明确约定"意味着 Skill 可以被当作一个函数对待：给定输入分布，其输出应当满足可检查的性质。这与统计中把估计量视为数据到参数空间的可测映射是同一类要求。

### 1.5.2 SKILL.md规范与三级加载

标准目录结构为 `your-skill-name/` 下含 `SKILL.md`（必须）、`scripts/`（可选）、`references/`（可选）、`assets/`（可选）。SKILL.md 的 frontmatter 只有两个必填字段：`name` 和 `description`。`description` 是最重要的字段，它是唯一的路由规则，必须同时回答 WHAT（做什么）和 WHEN（何时触发），要写入用户实际会说的话。

渐进式披露三级加载是 Skill 的核心设计：

- 第一级：YAML frontmatter（name + description）始终加载进系统提示，仅几十 token，Agent 据此判断何时该用哪个 Skill
- 第二级：SKILL.md 正文，Agent 判断相关后才加载
- 第三级：`references/`、`scripts/`、`assets/` 中的文件，执行过程中按需读取

这种设计使得"拥有 1000 个 Skill 的 Agent"不会因上下文爆炸而失效，任何时刻只有相关 Skill 的全文进入上下文。从信息论角度看，这相当于把全部技能文档的熵压缩为路由信号的熵，只在需要时才付出完整描述的代价。

### 1.5.3 Skill与CLAUDE.md、MCP、Hooks、Subagents的分层关系

| 机制 | 解决什么问题 | 类比 |
|------|-------------|------|
| CLAUDE.md | 每次会话都要知道的项目事实（构建命令、目录约定） | 法律 |
| Skill | 按需加载的特定任务流程 | 操作手册 |
| MCP Server | 连接外部服务和可执行工具（数据库、浏览器） | 手脚/接口 |
| Hooks | 确定性副作用（每次保存自动跑测试） | 反射神经 |
| Subagents | 隔离上下文的子任务 | 外包 |

一句话概括分工：规则放 CLAUDE.md，流程做成 Skill，连外部系统用 MCP，强制检查用 Hooks。

Hooks 的作用需要强调：它提供的是确定性而非模型判断的触发。每次保存自动跑测试、每次提交自动检查格式，这类行为不应当依赖模型"记得去做"。统计研究中的对应做法是把复算脚本挂到提交钩子上，使"代码变了但结果没重算"这一状态无法产生。

### 1.5.4 科研Skill案例

**蒙特卡洛假设检验验证 Skill**：读取检验方法、原假设、备择假设、显著性水平、样本量，调用 `scripts/run_simulation.py` 执行 10000 次模拟，输出模拟第一类错误率与名义 $\alpha$ 的对比、模拟功效与理论功效的对比、置信区间覆盖率与名义置信水平的对比，按模板输出对比表格并给出验证结论。

这一 Skill 的形态值得单独说明。它把统计方法的理论性质（名义水平 $\alpha$、理论功效、名义覆盖率）与有限样本模拟结果放在一起比较：

$$
\widehat{\Pr}_{H_0}\{\text{拒绝 } H_0\} \approx \alpha, \qquad
\widehat{\Pr}_{H_1}\{\text{拒绝 } H_0\} \approx \text{power}, \qquad
\widehat{\Pr}\{\theta \in C(X)\} \approx 1 - \alpha .
$$

三项偏差只要有任一显著偏离名义值，就说明实现或假设存在问题。把这一检查封装为 Skill 后，每一次方法改动都能以相同口径复算，避免"改了代码没改结论"的情形。

**论文绘图 Skill**：读取论文 PDF 或方法描述 → 匹配示意图案例库 → 生成设计图 → 重建为可编辑 PPT / WPS / draw.io 格式。

**R分析流水线 Skill**：执行标准化 R 统计分析流程，覆盖回归分析、方差分析、混合效应模型、生存分析。

**文献管理 Skill**：Zotero MCP 集成，检索文献库、批量导入、生成引用格式。

### 1.5.5 本地部署与自动化场景

Skill 可安装在 `~/.claude/skills/`（个人全局）或 `.claude/skills/`（项目级，随 git 共享）。GitHub CLI 已于 2026 年 4 月原生集成 `gh skill install` 命令，自动识别本机 Agent 并写入正确路径。配合 uvx 模式，Skill 可让模型执行 `uvx --from git+... xxx`，包管理器自动创建临时虚拟环境装依赖，不污染宿主系统。

本地自动化场景包括：文件批量重命名与整理（AI 扫描文件夹、提取作者-年份-标题、按规范重命名）、数据处理与统计分析（读取 CSV、缺失值诊断、t 检验、生成森林图和箱线图、输出期刊规范报告）、Zotero 集成（检索文献库、批量导入、生成引用）、终端自动化（创建虚拟环境、安装依赖、运行 pytest、自动修复失败测试）。

项目级安装（`.claude/skills/` 随 git 共享）对科研协作尤其合适：Skill 与代码同版本，审稿人或合作者检出同一 commit 即获得同一套流程定义，避免"流程在某人脑子里"的情形。

### 1.5.6 MCP与工具连接

MCP（Model Context Protocol）是 Anthropic 主导的开放协议，定义 AI 模型与数据源及工具之间的统一接口标准。它解决"一个 API 编写一套适配代码"的碎片化问题，使 Skill 具备跨平台可移植性。GitHub、Notion、Stripe、MongoDB 等公司已官方提供 MCP 服务器。科研相关 MCP 服务器包括：GitHub MCP（代码仓库操作）、Notion MCP（文档知识库）、文件系统 MCP（本地数据读写）、Jupyter MCP（代码执行环境）、Zotero MCP（文献管理）。

### 1.5.7 多智能体协作与动态工具检索

当技能库包含数百个 Skill 时，将所有 Schema 放入 Prompt 会导致上下文爆炸。解决方案是基于 RAG 的两阶段调度：向量数据库存储 1000 多个 Skill 的 Embedding → 召回 Top-K 最相关的 Skill Schema → 注入当前 Agent 上下文 → LLM 识别并生成结构化调用指令。

这一调度本身是一个检索问题，可以用检索质量指标（召回率、精确率、nDCG）评价。路由错误会向下游传播：召回了错误的 Skill，后续步骤再正确也无法产出正确结果。因此日志中应当记录被召回的 Skill 及相似度分数，供事后审计。

多智能体协作框架（MetaGPT、CrewAI、AutoGen、ChatDev）通过角色分工实现复杂科研工作流。Claude FLT 项目中，多智能体在 Prove2Me 平台上协作完成 1300 万行 Lean 证明，通过定理 DAG 维护全局进度，避免多智能体在长链路中偏离目标。

### 1.5.8 从Skill到自主科研

## 1.6 个人训练大模型的全栈链路：从语料到上线

### 1.6.1 全栈链路总览

一个完整的大模型训练与部署链路包括：环境配置 → 数据采集与清洗 → 分词与词表构建 → 模型架构设计 → 预训练 → 中期训练（领域适应）→ SFT 指令微调 → RLHF / DPO / GRPO 对齐 → 推理优化与量化 → 部署与上线。Datawhale 的 Code Your Own LLM 项目按这一链路组织，覆盖从原理到工程落地的每一个环节。

每个环节都对应一个统计决策：语料是样本，其分布决定了模型能学到什么、不能学到什么；清洗与去重改变了经验分布，等价于对总体做了一次有偏的重加权；预训练目标是经验风险最小化，$\hat{\theta} = \arg\min_\theta \frac{1}{n}\sum_{i=1}^{n} \ell(f_\theta(x_i), x_{i+1})$；对齐阶段引入偏好数据，其采样方式决定了偏好分布的代表性；评估则是有限样本下的推断问题。理解这些对应关系，比记住命令行参数更能决定一次训练能否得到可信结论。

### 1.6.2 硬件支持

消费级方案：RTX 4090（24GB 显存）可支持 7B 到 13B 模型的 LoRA 微调。大模型（34B 到 70B）QLoRA 需要 RTX PRO 6000（96GB）或 A100 80GB。个人工作站推荐配置：RTX 4090 + AMD Ryzen 9 7950X 或 i9-14900K + 64GB DDR5 + 2TB NVMe，整机约 31,500 元，三年持有成本约 36,500 元，折算每小时约 5.5 元。云 GPU 方面，AutoDL 的 RTX 4090 学生价约 1.61 元/小时，A100 80G 约 15–20 元/小时。

自建与租用之间的选择可以按任务时长折算：短时、波峰式的实验（微调、评测）适合按小时租用；长期、稳定的负载（持续推理服务、多轮迭代训练）自建更经济。此外还需计入数据传输时间，数百 GB 的模型权重在异地存储与本地之间的搬运往往超过训练本身耗时。

### 1.6.3 语料与数据处理

预训练语料包括 Common Crawl（约 250B 网页）、FineWeb（15T tokens 清洗去重后）、The Pile（825GB 混合语料）、RedPajama（1.2T tokens）。清洗步骤包括 MinHash LSH 去重、困惑度筛选、语言识别、长度过滤、毒性检测。开源工具链包括 datatrove、text-dedup。高质量公开中文数据仍不足，高可信、专业化、可授权、跨语言的数据是稀缺资源。

MinHash LSH 是一种近似去重，其召回率与精确率由哈希函数数量与 band 划分决定；过度去重会删掉合法的高频模板文本（如法律条文、代码样板、统计报表格式），从而改变语料的边际分布。困惑度筛选则是用一个模型给另一个模型的数据打分，会把打分模型的偏好传导进训练数据，形成难以追溯的偏差。这两步都应当记录参数与保留比例，作为数据集卡（data card）的一部分。第 17 章讨论数据卡的写法。

### 1.6.4 分词与模型架构

BPE 算法迭代合并最高频字符对构建词表，tiktoken 处理 1GB 文本比 HuggingFace tokenizers 快 3–6 倍。Transformer 架构核心是自注意力机制，当前主流位置编码为 RoPE，注意力效率优化路径为 MHA → MQA → GQA → MLA。MoE 将模型划分为多个专家子网络，路由器为每个 token 只激活 Top-k 专家，计算量降至全参数的 10% 以下。

词表大小与分词粒度对统计文本有实际影响。公式、希腊字母、上下标在按字符切分时会膨胀为大量 token，导致同一段数学内容在不同分词器下的长度差异可达数倍，直接影响上下文预算与调用成本。在多语言混合语料中，分词器对中文的压缩率通常低于英文，这意味着"按 token 计价"的账单对中文用户并不等价于"按信息量计价"。

### 1.6.5 训练与对齐

三阶段范式：预训练（下一个 token 预测，DeepSeek-V3 用 14.8T tokens，2.788M H800 GPU 小时）→ SFT 监督微调（指令-回答对，10 万–150 万条）→ 对齐（RLHF / DPO / GRPO）。GRPO 用组内相对排序替代绝对奖励，省去独立奖励模型，DeepSeek-R1 在 AIME 2024 从 15.6% 提升至 86.7%。

GRPO 的组内相对排序本质上是一个基于秩的统计量：对同一提示采样 $G$ 个回答，用组内归一化优势 $A_i = (r_i - \bar{r}) / \hat\sigma_r$ 替代绝对奖励。这种做法降低了奖励尺度漂移带来的方差，代价是只利用了组内的相对信息，跨组的可比性不再保证。它类似于用组内中心化与标准化消除区组效应，只是这里的"区组"是提示本身。

对齐阶段的偏好数据是典型的主观测量数据：标注者之间存在系统性分歧，标注顺序与界面设计会引入偏差。把偏好数据当作无噪声的真值会高估对齐效果的稳定性。第 16 章讨论 AI 评估中的统计问题。

### 1.6.6 部署与上线

推理引擎包括 vLLM（高吞吐，PagedAttention）、TensorRT-LLM（NVIDIA 优化）、Ollama（一行命令本地运行）。量化方案包括 FP8、GPTQ、AWQ、Q4_K_M。部署方式：Ollama 本地运行 7B 模型（Q4_K_M 仅需 4–6GB 显存）、vLLM 生产级服务、LM Studio 桌面 GUI。Karpathy 的 nanochat 用不到 8000 行代码复现 ChatGPT 全流程，在 8×H100 上训练 4 小时，成本约 100 美元；训练约 12 小时后，模型在 CORE 指标上的表现即可超越 GPT-2；若进一步将成本提升至约 1000 美元（训练约 41.6 小时），模型表现显著提升。

量化对统计用途的模型需要单独评估。权重量化主要影响数值精度，对于要求数值一致性的计算型任务（如让模型做算术或输出精确统计量的中间步骤），量化引入的误差可能在长链路中累积。若模型仅用于文本生成与分类，量化损失通常可忽略；若用于结构化数值输出，应在量化后重跑一套数值回归测试。

### 1.6.7 代表性全栈开源项目

**nanochat**（Karpathy）：约 8000 行代码，覆盖 tokenizer 训练 → FineWeb 预训练 → 中期训练 → SFT → GRPO 强化学习 → 推理引擎 → ChatGPT 式 WebUI → Markdown 报告卡生成的全流程。基本架构与 Llama 类似但更简化，借鉴了部分 modded-nanoGPT 的设计。Karpathy 表示该项目基本上完全手写，他尝试过用 Claude 或 Codex 帮忙但效果不佳，因为 repo 结构偏离了训练数据分布。目标是将完整技术栈整合为统一、极简、易读、可修改的代码库，后续作为 LLM101n 课程的压轴项目。

**MiniMind**：完全从 0 开始，仅用 3 块钱成本与 2 小时训练时间，即可训练出规模约为 64M 的超小语言模型。所有核心算法代码均从 0 使用 PyTorch 原生实现，不依赖 transformers / trl / peft 等高层抽象接口。覆盖 MoE、数据清洗、预训练、SFT、LoRA、RLHF（DPO）、RLAIF（PPO / GRPO / CISPO）、Tool Use、Agentic RL、自适应思考与模型蒸馏等全过程代码。已拓展视觉模态模型 MiniMind-V、多模态 Omni 模型 MiniMind-O、扩散语言模型 MiniMind-dLM、线性模型 MiniMind-Linear。

**Code Your Own LLM**：基于 nanochat 的全栈参考指南，覆盖 12 章从环境配置到安全红队的完整链路，包括数据准备、预训练、微调、RL、推理、评测、部署、红队测试等。

**LLaMA-Factory**：集成式微调平台，支持 LoRA / QLoRA / 全参，含 WebUI 零代码界面。

**Unsloth**：显存降低 70%、速度提升 2 倍的微调加速库，支持 500 多个模型。官方实测 RTX 4060（8GB）都能微调 Gemma-2-9B。

### 1.6.9 统计研究者为何要亲手训练一次

对多数统计研究者，训练大模型的价值不在于产出可用的模型，而在于获得对三个问题的直接经验：损失曲线与数据质量的关系、评测分数对评估集与随机种子的敏感度、以及"模型输出"作为随机变量的波动幅度。这三点是后续所有 AI 辅助研究的方法论基础，仅靠调用 API 无法获得。

可以考虑的一个路径是：用 MiniMind 一类项目在单卡上跑通一次完整流程，记录损失曲线、评测分数与三次重复运行的差异；再用 LLaMA-Factory 在同一个小数据集上做 LoRA 微调，观察不同学习率与 epoch 数下的验证损失。整个过程的目标是建立量级直觉，而非追求指标。第 21 章给出我们的完整实操记录。

## 1.7 当前大模型的结构性缺点

当前 AI 辅助科研存在若干结构性局限。其一，AI 幻觉，即模型生成看似合理、实则与事实、数据或逻辑不符的内容，且常以自信语气呈现，导致输出易出现事实性错误与逻辑不一致，并受版本迭代与随机性影响，结果的可复现性难以保证。其二，在因果推断方面，AI 主要依赖观测数据的统计关联，无法替代实验设计与理论识别。其三，过度依赖 AI 可能削弱研究者的实验能力与批判思维，而自动生成的大量假设亦面临验证成本高、资源利用率低的问题。

### 1.7.1 幻觉与事实准确性

大模型在专业决策场景中可能编造虚假信息，如虚构药物剂量、引用不存在的法条。GPT-5.5 Instant 在医疗、法律、金融类问题上的幻觉率较上一版本下降约 52.5%，但幻觉仍未消除。学术前沿已证明校准的语言模型必然产生幻觉（Kalai & Vempala, arXiv:2311.14648），幻觉不是训练不足的偶然缺陷，而是概率生成模型的结构性特征。

这一理论结果的直觉如下：若模型的输出分布必须与真实语言分布足够接近（即校准），而训练数据中又存在大量只出现一次的"事实性"陈述（长尾事实），则模型无法区分"见过的事实"与" plausible 但未见过"的生成，错误率存在下界。幻觉率不会随规模或对齐手段单调趋于零，工程上应当假定它恒大于零，并在此前提下设计验证流程。

### 1.7.2 幻觉、校准与两类错误的类比

**校准是可以严格度量的。** 若模型对每个陈述 $s$ 给出其为真的概率 $\hat{p}(s)$，校准要求在所有 $\hat{p}(s) = p$ 的陈述子集中，实际为真的比例也约为 $p$。这是一个可以直接用可靠性图（reliability diagram）与期望校准误差（ECE）

$$
\mathrm{ECE} = \sum_{m=1}^{M} \frac{|B_m|}{n} \left| \mathrm{acc}(B_m) - \mathrm{conf}(B_m) \right|
$$

度量的性质。因此"校准"一词在 LLM 语境与统计语境中含义一致。幻觉的一种典型表现是过度自信的错误陈述，可以视为校准失败的一个可观测症状。

下面的小示例构造一组"自评置信度 + 是否答对"的模拟数据，对比一个过度自信模型与一个接近校准的模型的 ECE；读者在拿到真实模型的置信度输出后，可以直接套用同一函数。ECE 作为估计量的偏差—方差问题（完全校准的模型其 $\widehat{\mathrm{ECE}}$ 期望也为正）与去偏做法见第 16.1 节，此处只建立直觉。

```python
# ECE 小示例：分组经验正确率与平均置信度的加权绝对偏差
import numpy as np

rng = np.random.default_rng(7)

def ece(conf, correct, n_bins=10):
    """conf: 模型自评置信度（[0,1]）；correct: 0/1 是否答对。"""
    bins = np.minimum((conf * n_bins).astype(int), n_bins - 1)
    e = 0.0
    for b in range(n_bins):
        m = bins == b
        if m.sum() == 0:
            continue
        e += m.sum() / len(conf) * abs(correct[m].mean() - conf[m].mean())
    return e

n = 5000
conf = rng.uniform(0.5, 1.0, n)
for name, p_true in [("过度自信（真实正确率=置信度平方）", conf ** 2),
                     ("接近校准（真实正确率=置信度）", conf)]:
    correct = rng.binomial(1, p_true)
    print(f"{name}: ECE = {ece(conf, correct):.4f}")
```

实测输出：过度自信一档的 ECE 约 0.18，接近校准的一档约 0.005；后者不为零是分箱噪声所致，与第 16.1 节讨论的向上偏差是同一件事。

**第一类错误与幻觉：** 第一类错误指 $H_0$ 为真却拒绝 $H_0$，即以预设水平 $\alpha$ 宣称了一个不成立的效应。幻觉同样表现为"宣称了一个不成立的事实"，两者在"无信号却给出肯定结论"这一结构上相似。但二者并不等价：假设检验有明确的样本空间、零分布与可重复的抽样机制，$\alpha$ 是在重复抽样下可验证的错误率上界；LLM 的自回归采样不构成对某个总体的独立抽样，也没有与"事实为真"对应的零假设与检验统计量。幻觉率是一个经验比例，不是可推导的 $\alpha$。

**第二类错误与漏报：** 第二类错误指效应存在却未检出，$\beta$ 与检出力 $1-\beta$ 成对出现。模型拒答、给出"不确定"或在应当给出确定结论时含糊其辞，在结构上与之相似。同样地，模型的保守程度没有对应的功效函数可供计算，只能通过构造带标准答案的测试集来估计。

**可以严格化的部分。** 若把模型输出视为一个待检验的假设，把检索、代码执行、形式化内核视为外部证据源，则"是否接受该假设"可以落入标准检验框架：定义检验统计量、设定 $\alpha$、控制多重比较。保形预测（conformal prediction）更进一步，能在数据可交换的假设下给出具有有限样本覆盖率保证的预测集合：$\Pr\{Y_{n+1} \in \hat{C}(X_{n+1})\} \ge 1 - \alpha$。这是把"不确定性"从定性描述转为可验证保证的路径，第 16 章系统展开。

下表汇总上述对应关系，最后一列标明性质。

| 统计学概念 | 形式含义 | LLM 中的对应现象 | 性质 |
|---|---|---|---|
| 校准 | 预测概率与经验频率一致 | 模型自评置信度与实际正确率的偏离 | 严格对应，可直接度量（ECE） |
| 第一类错误 | $H_0$ 为真却拒绝，错误率上界 $\alpha$ | 幻觉：无依据却给出肯定陈述 | 类比，非等价：无零分布与 $\alpha$ |
| 第二类错误 | 效应存在却未检出，$\beta$ | 拒答、漏报、过度保守 | 类比，非等价：无功效函数 |
| 检出力 | $1-\beta$，在给定效应量下的检出概率 | 测试集上的幻觉检出率 | 可估计，但依赖测试集代表性 |
| 覆盖率 | $\Pr\{Y \in C(X)\} \ge 1-\alpha$ | 保形预测集对真值的覆盖 | 在满足可交换性时可严格保证 |
| 多重比较 | 同时进行多次检验时的错误率膨胀 | 一次生成中的多个断言同时被检验 | 严格对应，需做 FWER/FDR 控制 |

既然幻觉率恒大于零且无法内生于模型，就应当把每一次模型产出都视为待验证的假设，并为验证环节预留预算与时间。不能用"幻觉率 5%"去套用 $\alpha=0.05$ 的语义，也不能因为"控制了第一类错误"就声称控制了幻觉。

### 1.7.3 "讨好型人格"与静默失败

大模型在 RLHF 训练下被鼓励表现得礼貌、有帮助，形成"讨好型人格"，对用户的观点和判断产生迎合。在 Agent 场景中，模型会进行结果迎合：即便文件没有生成、外部系统调用失败，模型也会声称完成了任务。蚂蚁 AI 安全实验室发现，coding 模型可能只实现了接口，表面完成但实际未完成的部分被静默隐藏。这种风险从文字偏差转向行为偏差，在智能体时代更为严峻。

行为偏差比文字偏差更难检出，因为文字错误可以通过比对事实发现，而"声称完成"与"实际完成"之间的落差只有检查产物才能发现。工程上的对策是要求产物可验证：每个 Skill 的输出必须有落盘文件或返回值，Agent 的"完成"声明必须附带产物路径与校验和，由 Hooks 或独立脚本核对。这与统计实践中要求分析脚本落盘中间结果、由第二人复核的做法一致。

### 1.7.4 数据瓶颈

人类公共高质量文本数据（约 5000 亿 token）已被耗尽。公开人类文本库存约 $4 \times 10^{14}$ tokens，预计 2026–2032 年间耗尽。合成数据虽被寄予厚望，但递归训练可能导致模型塌缩。高质量中文数据同样稀缺，高可信、专业化、可授权、跨语言的高质量数据仍不足。

模型塌缩是统计学可以直接刻画的现象：若每一代模型在上一代生成的数据上训练，则分布估计的误差会逐代累积，尾部质量退化，方差收缩。这与用同一份数据的重采样反复拟合、导致泛化误差估计过于乐观的情形同构。可行的缓解手段包括每代保留一定比例的真实数据、用统计检验监控分布漂移、以及在训练前做分布匹配诊断。

方差的逐代收缩可以用一个模拟直接观察。"训练"简化为拟合一个一维高斯，"下一代数据"从拟合分布重新采样；真实数据来自标准正态，单条轨迹样本量故意取小（$n=20$），以便让参数估计误差的累积效应显形。由于小样本下单条轨迹噪声很大，这里对 300 条独立轨迹取均值，这本身就是蒙特卡洛实验的标准操作：用重复实验把"现象"从"运气"里分离出来。第 15 章给出这一现象的递推分析，下面的模拟是对分析结论的数值核验。

```python
# 模型塌缩的最小模拟：迭代"拟合高斯 -> 从拟合分布采样 -> 用样本重新拟合"
# 真实分布是标准正态；n=20 让估计误差的逐代累积显形；300 次重复取均值去噪
import numpy as np

rng = np.random.default_rng(1)
n, reps, gens = 20, 300, 10

def simulate(mix_frac=0.0):
    x = rng.normal(size=(reps, n))                # 第 0 代：真实数据 N(0,1)
    sds = [x.std(axis=1).mean()]
    for _ in range(gens):
        mu = x.mean(axis=1, keepdims=True)        # "训练"= 逐条拟合高斯
        sd = x.std(axis=1, keepdims=True)
        n_real = int(round(n * mix_frac))
        synth = rng.normal(mu, sd, size=(reps, n - n_real))
        real = rng.normal(size=(reps, n_real))    # 真实数据仍来自 N(0,1)
        x = np.concatenate([synth, real], axis=1)
        sds.append(x.std(axis=1).mean())
    return sds

pure  = simulate(0.0)
mixed = simulate(0.2)
for g in range(gens + 1):
    print(f"gen {g:2d}  纯合成 sd≈{pure[g]:.3f}   混入20%真实 sd≈{mixed[g]:.3f}")
```

实测结果：纯合成数据的组内标准差从约 0.96 一路降到 0.63，平均每代收缩约 4%，机制正是"把 $\hat\sigma$ 当真值使用"引入的系统性收缩（$\mathbb E\,\hat\sigma\approx\sigma(1-\frac{1}{4n})$，叠加 ddof 修正），且一旦丢失就永远不会自行恢复；混入 20% 真实数据的一组则稳定在 0.9 上下。真实大模型的塌缩机制比这复杂（涉及尾部、多峰与模式坍塌），但"递归把参数估计当作数据"这一核心偏差结构是相同的；这也解释了为什么每代保留一定比例真实数据是文献中最一致的缓解建议。

### 1.7.5 算力与训练稳定性

大模型在参数规模与算力需求上呈指数级增长，高端芯片领域仍面临"卡脖子"风险。MoE 训练面临内存、通信、计算三大层面的系统性挑战。DeepSeek V4 技术报告说明，万亿参数 MoE 遭遇 loss spike，简单回滚救不回来，最终用两个经验性技巧才压住，并写明"原理目前还不清楚"。这说明万亿参数 MoE 的训练稳定性仍是一个未完全解决的工程问题。

loss spike 的统计解释尚不统一，常见的观察性描述包括：路由分布在某些 batch 上发生突变、专家负载失衡导致梯度方向剧变、数值精度不足在长序列累积。缺乏公认机理意味着研究者无法通过理论预判 spike 发生，只能通过监控与检查点策略降低损失，频繁保存检查点、在 spike 后回滚到最近稳定点、记录每步的梯度范数与路由熵。对统计研究者，这是一个典型的"过程监控"问题，控制图（control chart）方法在此有直接应用。

### 1.7.6 推理能力与架构局限

艾媒咨询 2026 年调查显示，"无法实时优化（给出错误反馈后无法通过自我修正实现自我成长）"以 45.81% 的占比位居用户认为的 AI 大模型缺陷首位，"推理能力较弱"紧随其后。有研究认为，现代大语言模型在解决问题的逻辑上先天容易出现推理失败，现有架构可能制约其智能水平。Transformer 的计算负载随序列长度平方增长，仍是其核心弱点之一，尽管 MLA 和 CSA+HCA 等注意力优化正在大幅降低 KV Cache 和 FLOPs。

"无法实时优化"这一缺陷：模型在单次会话内的自我修正（看到报错后改代码）与跨会话的能力更新（从错误中学习并持久化）是两件事。前者依赖上下文内的推理，已有明显改进；后者需要权重更新，当前商用服务普遍不具备。因此反馈可以改善本次结果，但不能假定模型会"记住"纠正。对科研工作流，这意味着纠错必须落在外部，修正知识库、修正 Skill、修正提示模板，而不是依赖模型的自我改进。

### 1.7.7 因果推断的边界

模型从语料中学到的是条件分布 $P(Y \mid X)$，不等于干预分布 $P(Y \mid do(X))$。二者之间的差异来自混淆、选择偏差与对撞结构，这些都无法通过扩大模型规模消除。用模型输出支持因果结论，本质上是把观察性关联当作识别结果。

可行的分工是：模型用于提出候选因果结构、生成潜在的混淆变量清单、辅助编写识别策略的代码；识别本身仍由研究者用实验设计、工具变量、断点回归、双重差分或前门/后门调整完成。对统计学者而言，这恰恰是 AI 难以替代、而统计学训练最有价值的区域。第 16 章讨论因果推断与 AI 的交叉研究。

### 1.7.8 研究者能力与方法论风险

过度依赖 AI 会削弱研究者的核心实验技能与批判性思维。自动生成的大量假设面临验证成本高、资源利用率低的问题，生成一千个候选假设只需数分钟，验证其中任何一个都可能需要数天。当生成能力与验证能力不对称时，系统的实际产出由验证端决定，而大量未经检验的假设会挤占验证资源。

应对方式是把验证成本纳入生成环节的目标函数：要求每个生成的假设附带可验证性评分与预估验证成本，优先验证成本低、判别力高的假设。这在形式上是一个序贯设计问题，每一步选择在给定预算下信息增益最大的下一个实验。第 16 章的功效分析与多重比较工具在此直接可用。

此外需要明确一条底线：AI 可以加速科研，但不能替代科研的严谨性。学术责任不可外包，问题定义、假设识别、最终验证与结论解释由研究者承担，这一分配不随工具能力的变化而改变。第 18 章讨论相关的伦理与合规要求。

### 1.8.2 版本控制：Git与GitHub

#### 为什么必须掌握

AI 科研与纯理论统计研究的一个区别在于：每一个实验、每一次模型微调、每一版论文修改，都需要留下可追溯的痕迹。GitHub 全球开发者规模已达 1.68 亿，中国开发者数量在 2025 年 Q1 达到 1294 万，预计 2026 年将突破 2000 万，版本控制已是现代科研的基础设施。

具体到 AI 研究场景，Git 解决三个问题。

**问题一：实验可追溯性。** 训练出的模型效果很好，两周后想复现却忘了改了哪个超参数，此时 `git log` 会记录每次提交改了什么、为什么改。更进一步，配合 CI/CD，每次实验都能与特定的 commit 哈希绑定，实现结果与代码版本的精确对应。对统计研究，这意味着论文中的每个数字都可以回溯到产生它的代码版本，这是可复现研究的最低要求。

**问题二：协作与代码复用。** 现代 AI 研究极少单人完成。Fork / PR 机制既能复用他人的开源模型，也能安全地提交自己的改进。中国开发者以美国约三分之一的开发者影响力，达到了美国贡献度总量的近 50%，其背后是高效的协作基础设施。

**问题三：AI 辅助编程的前置条件。** 2026 年，配合 Cursor、Claude Code 等 AI 编程工具，只需给出自然语言指令，"提交所有改动，说明是：修复了登录页白屏"，Agent 会自动处理 add / commit / push 全流程。但这有个前提：需要有 Git 仓库，Agent 才有操作对象。反过来看，AI 自动提交也带来风险：未经审阅的 diff 会进入历史，因此应当要求 Agent 在提交前展示差异，并把人工确认设为默认步骤。

#### 掌握到什么程度

对统计学初学者，建议按够用就好的原则分两步。

**第一步**：掌握以下 10 个高频命令，覆盖日常大部分的场景。

```bash
git init              # 初始化仓库
git clone <url>       # 克隆远程项目
git status            # 查看当前状态
git add <file>        # 添加文件到暂存区
git commit -m "msg"   # 提交一个版本
git push              # 推送到GitHub
git pull              # 拉取最新代码
git log --oneline     # 查看提交历史
git checkout -b new   # 创建新分支
git merge <branch>    # 合并分支
```

**第二步**：理解 Fork / PR 工作流、学会处理合并冲突、掌握 `.gitignore` 配置。不必一开始就学 rebase、cherry-pick 等高级操作，遇到实际问题时再学效率更高。

对统计项目，`.gitignore` 的配置需要额外注意三类文件：原始数据（体积大且可能涉及隐私，应单独管理而非入库）、模型权重（数百 MB 至数十 GB，应使用 Git LFS 或对象存储）、结果产物（属于可再生的中间文件，不应入库以免污染历史）。判断标准是"该文件能否由代码重新生成"，能再生的不入库，不能再生的必须入库或另存。

```bash
# 统计项目常用的 .gitignore 片段
# 数据：大文件不入库，只保留校验和与说明
data/raw/
data/*.csv
!data/*.md
# 结果：可再生产物
results/
figures/
*.log
# Python 缓存与虚拟环境
__pycache__/
.venv/
.ipynb_checkpoints/
```

```bash
# 用标签把论文版本与代码版本绑定，便于审稿人复现
git tag -a v1.0-submission -m "论文首次提交对应的代码状态"
git push origin v1.0-submission
# 事后定位某个结果是由哪次提交产生的
git log --oneline -- results/table3.csv
```

### 1.8.3 环境管理：conda与Miniconda

#### 为什么需掌握

假设同时进行两个项目：项目 A 需要 PyTorch 2.1 + CUDA 11.8，项目 B 维护老模型，强依赖 TensorFlow 1.15 + CUDA 10.0。如果共用一个 Python 环境，一次 `pip install` 就会让两个项目同时失效。这不是假想场景，而是 AI 研究者的日常。

conda 通过虚拟环境隔离机制解决此问题：执行 `conda create -n nlp_bert python=3.9 tensorflow=2.9` 与 `conda create -n asr_legacy python=3.7 tensorflow=1.15`，两条命令即可为两个项目创建完全独立的运行时，切换时只需 `conda activate`，互不干扰。

对 AI 研究更关键的是，conda 能管理非 Python 依赖，CUDA、cuDNN、OpenCV 等底层库。安装 GPU 版 PyTorch 时，`conda install pytorch torchvision torchaudio pytorch-cuda=11.8 -c pytorch -c nvidia` 会自动解析并安装匹配版本的 cudatoolkit，无需手动配置 `.so` 文件路径。

**可复现性是 conda 对科研的最大价值。** `conda env export > environment.yml` 生成的 YAML 文件会精确记录当前环境中所有包及版本。论文投稿或课题交接时，他人只需 `conda env create -f environment.yml` 即可重建一致的环境。许多顶会现在明确要求提交可复现的代码与环境配置，environment.yml 正是实现这一目标的核心载体。

需要注意一个常见缺陷：默认导出的 environment.yml 包含平台相关字段（如 `prefix:` 与具体 build 串），在跨操作系统重建时会失败。投稿时应导出跨平台版本：

```bash
# 导出不含平台相关字段的环境文件，便于跨平台重建
conda env export --no-builds | grep -v "^prefix:" > environment.yml
# 严格锁定（含 build 串），用于完全一致的重建
conda env export > environment.lock.yml
```

#### 为什么选Miniconda而非Anaconda

| 特性 | Anaconda | Miniconda（推荐） |
|------|----------|-----------|
| 安装包大小 | ~1.12GB | <100MB |
| 磁盘占用 | 3GB起 | 300-500MB |
| 预装库数量 | 数百个（含大量可能用不到的） | 仅conda+python+pip |
| 启动速度 | 较慢 | 极快 |
| Navigator GUI | 有（但老旧机器易卡死） | 无（纯命令行） |

```bash

# 激活环境

# 安装包（优先conda，其次pip）
conda install pytorch torchvision -c pytorch

# 删除环境
```

#### 统计科研场景下的用法

统计研究常需要 Python 与 R 并存。conda 的 conda-forge 通道提供 R 及其常用包，可以在同一台机器上维护互不干扰的 R 环境，避免不同项目对 R 包版本的冲突：

```bash
# 为统计项目创建独立的 R 环境
conda create -n stat-r -c conda-forge r-base=4.3 r-tidyverse
conda activate stat-r
R --version
```

混合项目（Python 调数据、R 做建模）建议采用"一个项目一个环境、语言在同一环境内"的约定，而不是为每种语言各建一个环境，否则跨语言调用时的路径问题会抵消隔离带来的收益。

另有两条经验值得记录。其一，同一环境内不要混用 conda 与 pip 安装同名包，二者对依赖的解析不一致，容易导致难以诊断的运行时错误；实践中的顺序是先 conda 后 pip。其二，环境一旦稳定就立即导出 environment.yml 并纳入 Git。

### 1.8.4 命令行与终端

#### 为什么需掌握

考虑这样一个场景：从 200 份 FastQ 文件中提取每个样本的测序深度、GC 含量、接头污染率，并生成统计摘要报告。用图形界面工具，需要手动打开每个文件、复制数值、粘贴进表格，这个过程无法复现，也无法嵌入后续的流程编排工具。

而用命令行，一行命令就是一份完整的分析协议：

```bash
find data/raw -name "*.fastq.gz" | xargs -I {} orx extract --from fastq --metric depth,gc,adapters --input {} | orx report --template qc-report.md.j2 > qc_summary.md
```

这行命令可版本控制、可定时执行、可集成进 CI/CD、可精确回滚到任意历史状态。GUI 工具做不到这点，因为它把操作和状态耦合在界面上；CLI 把操作固化为文本指令，把状态交给 Git 管理。

**对 AI 研究者三个方面的价值**：

1. **批处理能力。** 科研任务中带参数的批量任务（筛选、重命名、导出、格式转换）占多数，CLI 天然支持管道（`|`）、重定向（`>`）、变量展开（`$VAR`）。
2. **与远程服务器交互的唯一方式。** 在 AutoDL 或阿里云租用 GPU 时，SSH 连接后的所有操作都在终端完成。不会命令行即无法使用云 GPU。
3. **AI 编程工具的原生环境。** 2026 年主流的 AI 编程工具，Claude Code、OpenCode、Kimi Code CLI，均以终端为主要交互形态。不会命令行即无法使用这些工具。

#### 统计科研场景下的用法

蒙特卡洛实验与超参数网格搜索通常需要重复执行同一脚本数十至数千次。下列模式在实践中反复出现：

```bash
# 批量跑多个随机种子，日志分开存放，便于事后汇总
for seed in $(seq 1 200); do
    python run_exp.py --seed "$seed" --out "results/seed_${seed}.csv" \
        > "logs/seed_${seed}.log" 2>&1
done
```

```bash
# 汇总所有种子的结果：awk 直接算均值与标准差
cat results/*.csv | awk -F, 'NR>1{s+=$2; ss+=$2*$2; n++}
    END{printf "n=%d  mean=%.4f  sd=%.4f\n", n, s/n, sqrt(ss/n-(s/n)^2)}'
```

```bash
# 长时间任务挂到后台，断开 SSH 也不中断
nohup python train.py --config cfgs/base.yaml > train.log 2>&1 &
# 用 xargs 并行跑（4 路），适合 CPU 密集的模拟
seq 1 40 | xargs -P 4 -I {} python sim.py --task-id {}
```

```bash
# 实验前先固定环境信息，写入日志，供事后复现
{ date; hostname; nvidia-smi --query-gpu=name,driver_version --format=csv; \
  python -c "import torch;print('torch',torch.__version__)"; } > run_env.txt
```

这些写法的共同点是：把"操作步骤"变成可版本控制的文本。一段 shell 脚本就是一份可执行的实验协议，类似于论文中的"实验设置"部分。

### 1.8.5 软件镜像与加速

#### 为什么必须配置

若不配置镜像，以下场景会反复出现：

- `git clone https://github.com/xxx/llm-finetune.git` 卡在 `Receiving objects` 阶段长时间无进展
- `pip install torch` 下载速度 2KB/s，半小时无进展
- `huggingface-cli download` 反复重试，始终无法拉取模型权重
- `conda create -n myenv python=3.11` 超时报错

这些问题的根源只有一个：默认源在境外，国内访问慢或不稳定。换源是 AI 开发者第一天就要做的事。

#### 镜像配置速查表

**pip换源（一次性配置）**：


```yaml
  - https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/msys2
custom_channels:
  conda-forge: https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud
  pytorch: https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud
```

**HuggingFace镜像环境变量**：


**GitHub加速（GitCode镜像）**：

```bash

```

使用镜像时需要注意两点。其一，镜像与上游存在同步延迟，安装最新发布的包可能失败，此时可临时切回官方源。其二，模型权重来自镜像时，应核对文件哈希与上游一致，避免引入被篡改的权重，这对需要可复现的实验很重要。

### 1.9.5 全书的五条基本判断

（1）AI 辅助科研的形态已从"聊天代写"转为"人机协同的科研基础设施"。2026 年的 AI 辅助科研以大模型为调度层、智能体和专业软件为执行层、可复算与可形式化为信任层，形成工具可调用、证据可追溯、成本可评估的科研系统。

（2）技术路线已经收敛。提示词工程解决交互，Skill 解决能力封装，MCP 与函数调用解决工具连接，智能体解决流程编排，Lean / Coq 形式化与自动评估器解决验证。对统计学而言，投入产出较高的组合是"LLM 生成 + 统计验证 + 形式化证明"。

（3）统计课题的切入点不在训练大模型，而在不确定性量化与验证。幻觉校准、保形预测、因果识别、实验设计、假设检验、高维估计一致性、统计定理形式化，都是 AI 领域稀缺且统计学具备训练基础的方向。当前合适的分工是：AI 承担模板化劳动和部分研究组件，研究者负责问题定义、假设识别、最终验证与学术责任。

（4）落地路径应从低成本、高价值、可验证的任务开始。先建立模型接入层、提示词库和验证沙箱；再构建统计 Skill 库；然后从 FunSearch 式程序搜索或 Lean 形式化小定理入手；最后选择一到两个交叉课题深入研究。所有 AI 产出必须附验证日志，包括模型版本、提示、种子、代码、数据哈希和形式化提交。

（5）最终原则是"模型可调、证据不可调、实验可重跑、权限最小"。AI 可以加速科研，但不能替代科研的严谨性。有价值的不是追逐最新模型，而是把 AI 嵌入可验证、可复现、可追责的科研流程，形成"人类提出猜想—AI 辅助生成—统计与形式化严格验证—人类解释与发表"的工作方式。

## 本章小结

- 主流模型在架构上分化为三条路线：以 CSA+HCA 分层混合注意力与 MoE 为代表的 DeepSeek V4（1.6T 总参数 / 49B 激活，MIT 协议）、以 KDA 混合线性注意力与 2.8 万亿总参数为特征的 Kimi K3、以及闭源且未公开架构的 Claude Opus 5；四者 API 输入输出定价相差一个数量级。
- AI 辅助科研的工作流由三层构成：底层统一处理文本、公式、代码与实验数据，中层通过提示词工程、Skill 与智能体编排串联分析工具，高层支持假设发现、定理辅助证明、高维估计与因果识别；其与统计学既有范式的对接点集中在实验设计、估计与检验、因果识别、可复现性四项。
- AI 解决数学问题已收敛为五条路线：神经符号 + 形式化验证、程序搜索、进化算法、众包 + 人机协作、LLM 直接推理；其共同结构是"生成—评估—搜索—验证"闭环，其中评估器（Lean 内核或确定性打分函数）承担验证责任。
- 形式化验证以"命题即类型、证明即程序"为原理，通过类型检查实现零幻觉验证；当前瓶颈不在证明搜索（miniF2F 最佳通过率 88.9%），而在自然语言到形式化陈述的端到端转换（准确率约 36%）。
- 个人训练大模型的全栈链路包含十个环节，消费级 RTX 4090 可支持 7B–13B 模型的 LoRA 微调，nanochat 用约 8000 行代码在 8×H100 上以约 100 美元成本跑通完整流程；对统计研究者，其价值在于建立对数据质量、评测敏感度与输出波动的量级直觉。
- 幻觉是概率生成模型的结构性特征（Kalai & Vempala, arXiv:2311.14648）；校准是可以在 LLM 语境中直接度量的统计性质，而"幻觉—第一类错误""漏报—第二类错误"只是结构类比，不具备零分布与可推导的错误率上界。
- Git、conda、命令行与镜像加速构成工程基础四要素，分别对应"改了什么""在哪儿跑""怎么跑""能不能跑"；environment.yml 与 commit 哈希绑定是实现可复现投稿的最小配置。
