## 本章导读

## 21.1 实践目标与总体设计

### 21.1.1 四个实践与三条主线的对应

全书的三条主线在第十九章之前是分开叙述的：原理线回答"模型是什么"，工具线回答"怎么驱动模型干活"，研究线回答"AI 结论如何被验证"。这三条线在本章合流，因为一个真实的研究任务通常同时涉及三者——例如要验证"某稳健估计量在小样本下的表现"，既要跑蒙特卡洛（工具线），也要理解所用基座模型的生成机制（原理线），还要对 AI 给出的推导与代码做验证（研究线）。

四个实践的对应关系如下：

- **21.2 全栈训练**对应原理线。产出是一个自己训出来的模型权重与一个可调用的推理端点。走完这条链路之后，第二至五章中关于 token、注意力、损失函数、对齐目标的说法不再是纸面概念，而是可以直接打开权重文件核对的张量。
- **21.3 科研 Skill** 与 **21.4 Agent 与 MCP** 对应工具线。21.3 解决"把一段稳定的科研流程固化下来"，21.4 解决"让模型调用外部世界的数据与服务"。两者的区别在于：Skill 沉淀的是**做法**（步骤、阈值、输出契约），MCP 提供的是**能力**（检索、读写、执行）。
- **21.5 统计问题求解**对应研究线。它是本章的核心，也是全书的落点：把前三条主线产出的能力用于一个真实的统计推断问题，并明确划分哪些环节交给 AI、哪些环节必须由人承担。

### 21.1.2 实践环境与工具选型

四个实践对硬件的要求差异很大。下表给出一套分层配置：最低配置保证链路能跑通（结果规模受限），推荐配置保证在合理时间内得到有意义的结果。

| 组件 | 最低配置 | 推荐配置 | 说明 |
|---|---|---|---|
| GPU | 单卡 8 GB 显存（如 RTX 4060） | 单卡 24 GB（RTX 3090/4090、A10） | 21.2 低算力路线最低可到 8 GB；标准路线 LoRA 微调 7B 级模型建议 24 GB |
| 云 GPU | 按量计费的 A10/A100 单卡 | 同上，按小时租用并设预算上限 | 第 19 章给出算力成本模型，本章按"小时数 × 单价 × 1.3 冗余系数"预留 |
| CPU / 内存 | 8 核 / 32 GB | 16 核 / 64 GB | 语料清洗与分词器训练是 CPU 与内存密集环节 |
| 磁盘 | 100 GB 可用 | 500 GB 可用（SSD） | 语料、checkpoint、量化产物需要多份副本 |
| 操作系统 | Linux（Ubuntu 22.04） | 同左 | Windows 下建议用 WSL2；CUDA 与部分算子的编译在原生 Windows 上问题较多 |
| Python | 3.10 | 3.11 | 依赖锁文件随附在复现仓库中 |
| PyTorch | 2.x（与 CUDA 版本匹配） | 以官方安装页给出的匹配组合为准 | 版本与 CUDA 的对应关系以 PyTorch 官方安装页为准 |
| 推理服务 | Ollama（本地小模型） | vLLM（并发服务） | 21.2.13 给出两者的部署命令 |
| 形式化工具 | Lean 4（可选） | Lean 4 + Mathlib | 21.5.6 的可选环节，装不上不影响其他实践 |

软件选型遵循一条原则：**优先选有活跃维护、且失败时错误信息可读性好的工具**。全栈训练链路长，任何一环报错都会中断，错误信息含糊的工具会把排查成本抬高数倍。

API 密钥与预算的管理按第 19 章的做法：密钥写入 `.env` 并加入 `.gitignore`，不在代码中硬编码；云 GPU 与 API 均设置硬性预算上限，到达上限自动告警而非自动续费。

### 21.1.3 验证与记录规范

四个实践共用同一套记录字段，与第 17 章 17.5 节的验证日志一致。每次运行至少记录下列字段；缺失任一字段的实验结果不进入最终报告。

| 字段 | 取值形式 | 用途 |
|---|---|---|
| 代码版本 | Git commit 哈希 | 定位产生该数字的精确代码 |
| 环境 | `environment.yml` 或 Docker 镜像摘要 | 排除环境导致的差异 |
| 数据版本 | sha256（语料 / 数据集 / 模拟输入） | 确认输入未变 |
| 模型标识 | 权重路径 + 权重 sha256 + 配置名 | 区分基座与微调产物 |
| 提示词 | 内容哈希 + 版本号 | 提示词变更可归因 |
| 随机性 | 全局种子、采样温度、top-p | 复现与方差解释 |

| 成本 | GPU 小时数 × 单价、API token 数与费用 | 21.6 的横向对比 |
| 验证方式 | 所用检验/基准/人工抽查的说明 | 判断结论强度 |
| 失败记录 | 失败现象、原因、处置、是否重跑 | 防止选择性报告 |

随机性控制上有一条容易忽略的要求：**蒙特卡洛类实验必须报告重复次数与蒙特卡洛标准误**。只给一个点估计（如"拒绝率 6.2%"）而不给重复次数与标准误的结果无法判断其是否真的偏离名义水平，这一点在 21.5 中会被反复使用。

## 21.2 实践一：大模型从零到上线的全栈训练

### 21.2.1 目标与规模选择

本实践的目标不是训出一个能与商业模型竞争的模型，而是完整走一遍链路并亲手核对每一环：语料如何被切成 token、token 如何被映射成向量、损失如何下降、对齐如何改变输出分布、量化如何损失精度、服务如何把权重变成可用端点。规模的选择标准是"能在单卡上跑完，且每一环的产出可被肉眼检查"。

规模与显存的关系可以用一个粗略的公式估算。设模型参数量为 $N$，采用 AdamW 优化器与 bf16 混合精度，训练时每个参数大约占用：bf16 权重 2 字节、fp32 主权重 4 字节、梯度 4 字节（fp32）或 2 字节（bf16）、Adam 的一阶与二阶动量共 8 字节。因此优化器与权重部分约为

$$
M_{\text{states}} \approx 16\text{--}20 \ \text{bytes} \times N ,
$$

再加上激活值与临时缓冲。按此估算，1 亿参数的模型全参训练约需 2 GB 上显存（不含激活），7 B 参数模型全参训练则需要 100 GB 量级，单卡不可行。LoRA 只训练低秩适配器，优化器状态可忽略，7 B 模型的 LoRA 微调在 24 GB 卡上配合梯度检查点可以跑通。

MiniMind 项目给出的规模参考（据该项目 README，2025 年）：最小版本 64 M 参数，约为 GPT-3 的 1/2700；单张 RTX 3090 约 2 小时、电费成本约 3 元即可完成一次完整训练，覆盖预训练、SFT、LoRA、RLHF/RLAIF、蒸馏等全链路。这个量级适合作为第一次全栈训练的入口：失败重跑的代价是一次咖啡的时间。

### 21.2.2 两条可选路线

| 维度 | 低算力路线（MiniMind / nanochat） | 标准路线（LLaMA-Factory + 基座 LoRA） |
|---|---|---|
| 基座 | 从零初始化，自己定义架构 | Qwen / DeepSeek 等开源基座 |
| 参数量 | 26 M–200 M | 0.5 B–8 B（LoRA 只训适配器） |
| 硬件门槛 | 单卡 8 GB 可跑，24 GB 舒适 | 单卡 24 GB 起 |
| 时间 | 2–4 小时（MiniMind 64M 约 2 小时） | 数据准备 1 天 + 微调数小时 |
| 数据 | 项目自带数 GB 级小规模语料 | 需自建或选用数万条指令数据 |
| 学到的东西 | 全部环节，包括 tokenizer 与架构细节 | 数据工程、微调超参、评测对比 |
| 结果可用性 | 只能作为演示与教学 | 可实际用于特定领域任务 |
| 主要风险 | 环境琐碎，脚本随版本变动 | 基座许可、数据许可、显存不足 |

两条路线的选择取决于读者的目的。若目的是理解原理（本书原理线的收尾），选低算力路线；若目的是得到一个能用的领域模型，选标准路线。两者并不互斥：先用低算力路线把链路走通，再用标准路线做一件有用的事，是成本最低的顺序。

### 21.2.4 语料获取与清洗

语料决定模型的上限。低算力路线可直接使用项目自带的高质量小规模语料（MiniMind 提供 `pretrain_hq.jsonl`、`sft_mini_512.jsonl`、`dpo.jsonl`、`rlaif-mini.jsonl` 等，见 21.2.16）；标准路线需要自建语料。

清洗环节的标准步骤与每一步的统计记录如下。

| 步骤 | 做法 | 必记统计量 |
|---|---|---|
| 长度过滤 | 丢弃过短（如少于 64 字符）与超长（超过窗口）文档 | 过滤前后文档数、token 数 |
| 语言识别 | 用 fasttext 语言识别模型或简单字符比例规则保留目标语言 | 各语言占比、被判为非目标语言的比例 |
| 去重 | MinHash + LSH 做近似去重，或精确哈希去重 | 重复率（被删文档数 / 总文档数） |
| 质量过滤 | 用一个小模型算困惑度或用规则（广告、模板、乱码）过滤 | 各分数区间的文档分布 |
| 有害内容过滤 | 关键词表 + 分类器 | 命中率与人工抽检结果 |
| 脱敏 | 邮箱、手机号、密钥的正则替换 | 命中条数 |

每一步都要记录"过滤前后"的文档数与 token 数，并把过滤脚本与阈值写进仓库。这样做的理由与统计中的数据清洗文档相同：阈值是研究者的自由度，不记录就等于给了自己事后调整结果的余地。

```bash
# datatrove 提供了 MinHash 去重等流水线组件，具体入口以官方文档为准
pip install datatrove
# 建议做法：先跑一个小样本（如 1 万篇）验证流水线正确，再全量跑

# 清洗结果的记录（示例脚本，输出进入 manifest）
python - <<'PY'
import json, hashlib, pathlib
p = pathlib.Path("data/pretrain_clean.jsonl")
n_doc = n_tok = 0
h = hashlib.sha256()
for line in p.open("rb"):
    h.update(line); n_doc += 1
    n_tok += len(json.loads(line)["text"])
print(json.dumps({"docs": n_doc, "chars": n_tok, "sha256": h.hexdigest()[:16]}))
PY
```

一个常被忽视的统计问题：**去重必须在质量过滤之前还是之后**会改变重复率的定义。若先做质量过滤，重复率是在"已过滤集合"上定义的，与先去重得到的数字不可比。两种顺序都可以，但报告时必须写明顺序。

### 21.2.5 分词器训练

分词器决定"模型看到的单位"。统计学者容易低估这一环的影响：中文的字符级切分会让序列变长、注意力代价上升；词表过大则 embedding 与输出层参数膨胀。

```bash
# 语料落盘为纯文本，每行一篇文档
python scripts/dump_corpus.py --input data/pretrain_clean.jsonl --output data/corpus.txt

# SentencePiece BPE（词表 32K；中文场景 character_coverage 取接近 1）
spm_train --input=data/corpus.txt \
          --model_prefix=tok32k --vocab_size=32000 \
          --model_type=bpe --character_coverage=0.9995 \
          --normalization_rule_name=identity
```

```python
# 分词器体检：压缩率、UNK 率、中文切分与数值切分
# 前置条件：需先用上一块命令训练出 tok32k.model，并准备 data/sample.txt；
# 预期输出：一个 bytes/token 压缩率数字、一个接近 0 的 unk 率，以及两行切分结果。
import sentencepiece as spm
sp = spm.SentencePieceProcessor(model_file="tok32k.model")
texts = open("data/sample.txt", encoding="utf-8").read().split("\n")[:2000]
n_char = sum(len(t) for t in texts)
n_tok  = sum(len(sp.encode(t)) for t in texts)
print(f"bytes/token = {n_char/n_tok:.3f}")            # 压缩率，越大越好
print(f"unk rate    = {sum(t.count('<unk>') for t in map(sp.encode, texts))/n_tok:.5f}")
print(sp.encode("样本均值的渐近方差为 σ²/n", out_type=str)[:20])   # 中文与公式切分检查
print(sp.encode("p-value = 0.0321", out_type=str)[:12])            # 数值是否被切碎
```

分词器的验收标准：字符/token 压缩率落在合理区间、UNK 率接近 0、中文词不被切成孤立字、数值不被切得过度破碎（数值被切碎会显著损害模型的算术与读表能力）。可对比 16 K / 32 K / 64 K 三档词表的压缩率与参数量，把对比表存档。

对统计学者而言，一个值得单独检查的点是**数值与符号的切分方式**。若 tokenizer 把 "0.0321" 切成四个 token，模型在做数值比较与读表任务时的表现会明显变差，而这类任务恰是科研场景常见的需求。发现问题时，可在 BPE 训练前对数字做预处理（按位切分并加前缀），这是多数开源分词器的通行做法。

### 21.2.6 模型定义与参数量核算

低算力路线采用类 Llama 的精简架构：RMSNorm 预归一化、RoPE 旋转位置编码、SwiGLU 前馈、可选的多查询注意力（MQA/GQA）以压缩 KV Cache。参数量可解析计算。设词表 $V$、隐藏维 $d$、层数 $L$、前馈隐藏维 $h$，则（不共享 embedding 与输出头时）

$$
N \approx 2Vd + L\left(4d^2 + 3dh\right),
$$

其中 $4d^2$ 来自注意力四个投影矩阵（若用 GQA 则 K/V 部分按分组数缩小），$3dh$ 来自 SwiGLU 的三个矩阵。

```python
# 三个自设配置的核算示例：键名直接写超参，打印值为按上式核算的结果
def n_params(V, d, L, h, tie_embeddings=False, n_kv_head_ratio=1.0):
    attn = 2 * d * d + 2 * d * d * n_kv_head_ratio      # q,o 满秩；k,v 按 GQA 缩放
    ffn  = 3 * d * h                                    # SwiGLU: gate/up/down
    head = d * V if tie_embeddings else 2 * d * V       # 词嵌入与输出头
    return head + L * (attn + ffn)

for name, (V, d, L, h) in {
    "V=6400,  d=512,  L=8,  h=2048":   (6400, 512, 8, 2048),
    "V=6400,  d=768,  L=16, h=2048":   (6400, 768, 16, 2048),
    "V=32000, d=1024, L=12, h=2816":   (32000, 1024, 12, 2816),
}.items():
    print(f"{name:28s} {n_params(V,d,L,h)/1e6:8.2f} M")
```

笔者实测上述代码的输出为：三行分别约 40.11 M、123.08 M、219.68 M。需要说明的是，若把键名换成开源仓库宣称的型号名（如某 64 M 版本），核算值往往对不上官方口径——是否共享词嵌入、是否把 RMSNorm 等组件计入、GQA 分组方式如何折算，都会改变结果。因此对比规模时应当用同一路径重算，而不是直接引用宣传数字。

核算参数量的意义在于：它把"模型大小"这个模糊说法变成可核对的算术，使得显存估算、训练时长估算与仓库声明的规模可以互相校验。若三者对不上，通常意味着配置被改过或权重与配置不匹配——这是部署阶段最常见的错误来源。

### 21.2.7 预训练

预训练的超参没有普适最优值，但有几条稳健的经验规则：小模型（百 M 级）峰值学习率在 $10^{-3}$ 量级，B 级模型降到 $10^{-5}\text{--}2\times10^{-5}$；warmup 取总步数的 1%–3%；学习率按余弦衰减到峰值的 10% 左右；梯度裁剪取 1.0；批次用 token 数而非样本数来定义（如每步 0.5 M–1 M token），这样序列长度变化不会影响单步的信息量。

```bash
# 低算力路线（MiniMind）：脚本名与参数以仓库 README 当前版本为准
python train_pretrain.py --epochs 1 --batch_size 32 --lr 1e-3 \
    --max_seq_len 512 --dtype bfloat16 --use_wandb 0 \
    --save_dir ./out/pretrain --log_interval 50
```

```python
# loss 曲线的判读（把日志读出来做三段统计，便于发现异常）
# 前置条件：需要一份含 step,loss,lr,gnorm 四列的训练日志 CSV；
# 预期输出：head/mid/tail 三段各一行，loss_mean 递减、gnorm_max 收敛。
import pandas as pd
df = pd.read_csv("out/pretrain/train_log.csv")           # 字段: step,loss,lr,gnorm
df["seg"] = pd.cut(df.step, bins=3, labels=["head", "mid", "tail"])
print(df.groupby("seg", observed=True).agg(loss_mean=("loss","mean"),   # observed=True 消除 pandas 对分类分组的告警
                            loss_std=("loss","std"),
                            gnorm_max=("gnorm","max")))
# 关注三项：loss 是否单调下降；局部是否出现 spike（相邻步涨幅超过 3 倍标准差）；
# 梯度范数是否出现数量级跳变（提示数值不稳定）
```

预训练的验收标准：

| 检查项 | 期望 | 异常时的常见原因 |
|---|---|---|
| loss 曲线 | 单调下降后在末期走平，无持续 spike | 学习率过高、数据中有脏样本、混合精度溢出 |
| 梯度范数 | 稳定在同一量级，无数量级跳变 | 梯度裁剪未生效、异常样本、损失实现有误 |
| 生成样例 | 能给出语法通顺、主题连贯的续写 | tokenizer 与模型不匹配、数据配比失衡 |
| 困惑度 | 在留出验证集上不高于训练集过多 | 过拟合、数据泄露（去重不彻底） |
| checkpoint | 可独立加载并复现同一 loss | 只存了权重未存配置、EMA 未同步 |

loss 的绝对值没有跨项目可比性（词表、数据、归一化方式都会影响），因此不要拿"loss 降到 2.3"这类数字作为目标，只用它做自身前后对比。

#### 21.2.7.1 补充：无 GPU 环境下的训练循环最小骨架

正式的预训练需要 GPU，但"训练循环"这个概念本身不需要。笔者在等待 GPU 资源时，用下面的骨架在同一台笔记本的 CPU 上把前向、反向、梯度裁剪、参数更新与学习率调度这一循环完整走了一遍：loss 单调下降、梯度范数收敛到稳定量级、学习率按余弦退火——真实训练日志里该有的行为，这里都会出现，只是规模缩小了几个数量级。代码只依赖 torch（CPU 版即可），固定种子，普通笔记本上数秒内可跑完。

```python
# train_loop_toy.py：CPU 上的训练循环最小骨架
# 目的：为没有 GPU 的读者保留一条体验"前向、反向、裁剪、更新、日志"完整循环的路径
import time

import torch
import torch.nn as nn

torch.manual_seed(20260101)                     # 固定种子：权重初始化与数据都可复现

# 数据：模拟一个带异方差的回归问题，n=4096，特征 20 维
n, d = 4096, 20
g = torch.Generator().manual_seed(20260102)
X = torch.randn(n, d, generator=g)
beta = torch.randn(d, generator=g)
y = X @ beta + 0.5 * X[:, 0] ** 2 * torch.randn(n, generator=g)   # 误差方差随 x0 增大

# 模型：两层前馈网络（远小于语言模型，但训练循环的部件齐全）
model = nn.Sequential(nn.Linear(d, 64), nn.GELU(), nn.Linear(64, 1))
opt = torch.optim.AdamW(model.parameters(), lr=3e-3, weight_decay=0.01)
sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=300, eta_min=3e-4)
EPOCHS = 300

t0 = time.time()
for epoch in range(1, EPOCHS + 1):
    model.train()
    opt.zero_grad()
    loss = ((model(X).squeeze(1) - y) ** 2).mean()      # 前向 + 均方误差
    loss.backward()                                     # 反向传播
    gnorm = torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # 梯度裁剪，返回裁剪前范数
    opt.step()                                          # 参数更新
    sched.step()                                        # 学习率余弦退火
    if epoch % 50 == 0 or epoch == 1:
        print(f"epoch {epoch:4d}  loss {loss.item():.4f}  "
              f"gnorm {gnorm.item():.3f}  lr {sched.get_last_lr()[0]:.2e}")
print(f"训练完成，耗时 {time.time() - t0:.1f} s（CPU）")
```

笔者的一次实测输出（torch 2.3.0，CPU；耗时与具体机型有关，以实机为准）：

```text
epoch   50  loss 3.0085  gnorm 4.425  lr 2.82e-03
epoch  100  loss 0.6077  gnorm 0.180  lr 2.32e-03
epoch  150  loss 0.5783  gnorm 0.038  lr 1.65e-03
epoch  200  loss 0.5644  gnorm 0.034  lr 9.75e-04
epoch  250  loss 0.5565  gnorm 0.034  lr 4.81e-04
epoch  300  loss 0.5522  gnorm 0.034  lr 3.00e-04

```

对照 21.2.7 的验收标准逐项检查：loss 是否单调下降（是）；梯度范数是否稳定在同一量级（是，收敛到 0.034 附近）；学习率是否按计划衰减（是，从 3.0e-03 余弦退火到 3.0e-04）。loss 的下限不为零，是因为数据生成时的噪声方差本身不为零，这部分是不可约误差，与模型拟合好坏无关。跑通这个骨架之后，再去读 21.2.7 的真实训练命令，日志里每一列的含义就都见过实物了。

### 21.2.8 中期训练：领域适应

中期训练（mid-training，也称退火阶段）指在预训练末期用特定领域语料做一次高权重、低学习率的继续训练。它的统计含义可以表述为：预训练分布 $P_{\text{pre}}$ 与目标使用分布 $P_{\text{target}}$ 之间存在分布偏移，中期训练通过重新加权经验分布，把模型参数从"在 $P_{\text{pre}}$ 上最优"推向"在混合分布上更均衡"。这与统计学中的重要性加权是同一类操作。

对统计学者，这一步的实践价值最大：可混入的材料包括统计教材与讲义、R/Python 统计分析代码、论文中的 LaTeX 公式与表格、公开数据集的说明文档。配比建议：领域语料 30%–50%，通用语料保留 50%–70%（完全替换为领域语料会带来灾难性遗忘与多样性下降）。

```bash
# 中期训练：降低学习率、拉长序列、提高领域语料权重（参数以官方文档为准）
python train_pretrain.py --resume ./out/pretrain/ckpt_last.pt \
    --data_mix "domain:0.4,general:0.6" \
    --lr 1e-4 --max_seq_len 1024 --epochs 1 --save_dir ./out/mid
```

中期训练的验收方式是**对照**：在领域验证集与通用验证集上分别算困惑度，与退火前比较。理想结果是领域困惑度下降而通用困惑度基本不动；若通用困惑度大幅上升，说明配比或学习率需要回调。这类"两边都测"的做法与模型选择中的训练/验证/测试三分是同一个道理。

### 21.2.9 SFT 指令微调

SFT 把"续写能力"转成"按指令作答的能力"。数据格式采用对话式 JSONL，并在损失计算上只对回答部分计 loss（prompt 部分做掩码），否则模型会去学习"生成 prompt"这一无用目标。

```jsonl
{"conversations":[{"role":"user","content":"解释异方差稳健标准误的作用"},{"role":"assistant","content":"在误差方差非齐次时，OLS 系数的常规标准误不再一致……"}]}
```

```bash
# 低算力路线
python train_sft.py --load_from ./out/mid/ckpt_last.pt --epochs 2 \
    --batch_size 16 --lr 5e-5 --max_seq_len 512 --save_dir ./out/sft

# 标准路线：LLaMA-Factory + 基座 LoRA（配置字段以官方文档为准）
pip install -e ".[torch,metrics]"
llamafactory-cli train examples/train_lora/qwen_lora_sft.yaml
llamafactory-cli export examples/merge_lora/qwen_lora_sft.yaml
```

| LoRA 参数 | 常用取值 | 影响 |
|---|---|---|
| `r`（秩） | 8 / 16 / 32 | 越大容量越高，过拟合风险与显存同步上升 |
| `alpha` | 通常取 $2r$ | 与 $r$ 共同决定缩放系数 $\alpha/r$ |
| `dropout` | 0.05–0.1 | 小数据上有助于抑制过拟合 |
| `target_modules` | `q_proj,v_proj`（最小）/ 全部线性层 | 覆盖面越大越接近全参微调 |
| 学习率 | $1\text{e-}4 \sim 2\text{e-}4$ | 高于全参微调约一个数量级 |

SFT 的验收标准：给出训练集中未出现的指令，模型能按要求的格式作答；多条同义指令的输出一致性可接受；对训练集内指令不得逐字复现（复现说明过拟合）。建议构建 20–30 条"留出指令集"，人工评分并存档，这套留出集在后续每次改动后复用，形成可比的纵向记录。

### 21.2.10 对齐训练（DPO / GRPO）

SFT 只教"怎么答"，对齐教"多个答案里偏好哪一个"。DPO 的目标是

$$
\mathcal{L}_{\text{DPO}}(\theta) = -\log \sigma\!\left(
\beta \log \frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)}
-\beta \log \frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}
\right),
$$

其中 $y_w$ 为偏好回答、$y_l$ 为被拒回答、$\pi_{\text{ref}}$ 是冻结的参考策略、$\beta$ 控制偏离参考策略的强度。这个目标函数在结构上与 Bradley–Terry 配对比较模型同源：它拟合的是"人类偏好排序"这一二分类事件的对数似然，只是在策略空间而非参数空间上参数化。统计学者看到这一层会对它的性质有更清晰的预期——偏好数据的噪声、标注者不一致、样本量不足，都会以与配对比较模型相同的方式影响估计。

GRPO 则去掉了价值网络，在同一 prompt 的一组采样回答内用相对优势（减去组均值、除以组标准差）构造优势估计，显存开销低于 PPO，适合算力受限的场景。

```bash
# 偏好数据格式（chosen / rejected 对）
# {"prompt": "...", "chosen": "...", "rejected": "..."}

python train_dpo.py --load_from ./out/sft/ckpt_last.pt \
    --beta 0.1 --lr 5e-7 --epochs 1 --save_dir ./out/dpo
```

偏好数据的构造成本高于 SFT 数据。小规模实践可用规则化方式生成：让 SFT 模型对同一 prompt 采样 $k$ 个回答，用一个更强模型或人工规则（长度合规、格式合规、是否含编造引用）打分，取最高与最低构成偏好对。这样生成的偏好对带有明确的构造规则，便于事后审计——若偏好对是人工随意写的，对齐结果无法解释。

对齐的验收标准：在留出指令集上比较 SFT 与对齐后模型的格式合规率、编造引用率、拒答率与有用性评分。对齐不是"分数一定提高"，而是"在可控的代价下改变行为分布"；若对齐后有用性明显下降而格式改善有限，通常说明 $\beta$ 过大或偏好数据质量不足。

### 21.2.11 模型评估

小规模模型的公开基准分数参考价值有限，因此评估采用"公开基准子集 + 自建领域集 + 人工检查"三层。

```bash
# 自建统计问答集（示例两条，实际建议 30–50 条，含数值题与概念题）
# {"q": "n=25 时 t 检验与 z 检验的差异是什么？", "a_ref": "要点列表", "type": "concept"}
# {"q": "给定样本 3,1,4,1,5，求样本方差（n-1 校正）", "a_ref": "3.2", "type": "numeric"}

python eval_model.py --ckpt ./out/dpo/ckpt_last.pt \
    --bench data/stat_qa.jsonl --out runs/eval_dpo.json
```

| 评估层 | 指标 | 判读方式 |
|---|---|---|
| 公开基准子集（C-Eval / CMMLU 子集） | 准确率 | 与同参数量开源模型对比，只做参照不做目标 |
| 自建领域集 | 数值题正确率、概念题要点覆盖率 | 与基座、SFT、对齐三个版本同口径对比 |
| 生成质量 | 人工评分（1–5）：相关性、正确性、格式、是否编造 | 双人独立评分，记录分歧 |
| 稳定性 | 同一 prompt 采样 5 次的一致性 | 统计答案一致的次数 |

评估环节最需要防的是**测试集污染**：自建领域集若不慎与 SFT 数据重合，分数会被系统性抬高。做法是在构造 SFT 数据时预留留出集，并对两者做 n-gram 重叠检查。这与统计建模中训练/测试分离是同一要求，只是在语言数据上"重叠"的形式更隐蔽（改写、翻译、模板化都算重叠）。

### 21.2.12 量化与推理优化

量化用精度换显存与带宽。常见方案的取舍如下（显存数字为量级估计，实际以实测为准）。

| 方案 | 显存量级（7 B 模型） | 需要校准集 | 特点 |
|---|---|---|---|
| fp16 / bf16 | 约 14 GB | 否 | 精度基准，单卡 24 GB 可推理 |
| INT8（动态/权重量化） | 约 7 GB | 否（动态） | 实现简单，精度损失通常较小 |
| GPTQ / AWQ（INT4） | 约 3.5–4 GB | 是 | 需要代表性校准集，校准集偏移会带来额外损失 |
| GGUF + llama.cpp | 2–8 GB（按量化档位） | 是 | 便于 CPU 与本地部署 |

```bash
# 导出为 Transformers 格式，再转 GGUF（脚本名以 llama.cpp 仓库当前版本为准）
python export_model.py --ckpt ./out/dpo/ckpt_last.pt --out ./out/hf
python llama.cpp/convert_hf_to_gguf.py ./out/hf --outfile ./out/model-f16.gguf
./llama.cpp/build/bin/llama-quantize ./out/model-f16.gguf ./out/model-q4_k_m.gguf Q4_K_M
```

量化验收必须做**同口径对比**：量化前后在同一评测集上跑分，同时测量首 token 延迟、吞吐与显存峰值。只报"显存降到 1/4"而不报精度损失是不完整的结论。对小模型而言，INT4 在数值题上的退化往往比在生成题上更明显，这一点在科研场景（含计算与读表）中需要特别留意。

### 21.2.15 踩坑记录与经验总结

| 现象 | 常见原因 | 处置 |
|---|---|---|
| loss 出现 spike 后不回落 | 学习率过高、脏样本、bf16 溢出 | 降低峰值学习率、检查异常样本、启用梯度裁剪与 loss 缩放 |
| 显存不足（OOM） | 批次过大、序列过长、激活未释放 | 开梯度检查点、缩批次配梯度累积、缩短序列 |
| 生成全是重复片段 | 数据去重不彻底、温度过低、模型欠训练 | 复查去重率、调高温度与重复惩罚、增加训练步数 |
| 载入 checkpoint 后 loss 对不上 | 只存权重未存配置、词表被换过 | 权重与配置同目录保存，载入时校验词表哈希 |
| 量化后数值题崩坏 | 校准集不具代表性、量化档位过低 | 用领域样本做校准集，对比 q8 与 q4 再定档 |
| 端口被占用 / 服务起不来 | 上次进程未退出 | 用 `lsof -i:8000` 定位并结束残留进程 |
| tokenizer 与模型不匹配 | 换了词表但沿用旧 embedding | 词表变更必须重训或做 embedding 重映射 |

踩坑记录的价值不在于清单本身，而在于它记录了"哪些操作在此环境下确实可行"。这类隐性知识在正式论文中不出现，却决定了复现的成败，因此应与代码一起开源。

### 21.2.17 常见失败与排查

以下是笔者在练习这个实践时遇到过的报错，按出现环节排列，供遇到同样问题时对照排查。

- `torch.cuda.OutOfMemoryError: CUDA out of memory`——显存不足。可能原因是批次过大、序列过长或激活未释放。排查步骤：先把 batch size 减半并配合梯度累积保持等效批次，确认没有中间张量被变量引用滞留显存，仍不够再开梯度检查点。
- `loss 出现 nan`——数值溢出。可能原因是学习率过高、bf16 溢出或数据里有异常样本。排查步骤：把峰值学习率降一个数量级复跑；检查梯度裁剪是否生效；对前几百个样本逐条检查异常大的文本或重复片段。
- `ModuleNotFoundError: No module named 'flash_attn'`——可选注意力实现未安装。这是可选依赖而非必需依赖。排查步骤：查仓库 README 的依赖说明，改用默认注意力实现即可跑通，不必为了"装齐"而强行编译。
- `OSError: [Errno 98] Address already in use`——端口被占用。可能原因是上次的服务进程没有退出。排查步骤：用 `lsof -i:8000`（Linux）或 `netstat -ano | findstr 8000`（Windows）定位进程，结束后再启动。
- 加载 checkpoint 后 loss 与训练末尾对不上——权重与配置不同源。可能原因是换了词表沿用旧 embedding，或只存了权重没存配置。排查步骤：校验 tokenizer 与权重的哈希是否与训练日志记录一致，确认配置文件与权重在同一目录、同一版本。

## 21.3 实践二：科研Skill开发、部署与开源

### 21.3.1 目标与 Skill 选择

Skill 的本质是一个包含 `SKILL.md` 的文件夹，它告诉 Agent 三件事：什么时候用、按什么步骤做、可以调用哪些脚本。与提示词相比，Skill 的区别在于**可版本化、可测试、可分发**；与脚本相比，它的区别在于把"何时调用"这一判断也写进了产物。

本节选择"回归诊断与稳健性检查"作为实例，理由是它同时满足三个条件：第一，它是统计学者每周都会做的重复劳动；第二，它有明确的阈值与判定规则，适合脚本化，而解释部分又需要语言模型，适合保留在 SKILL.md 中；第三，它的输出契约清晰（一个 JSON），便于写测试。

另一个可替换的实例是"保形预测区间 Skill"（对给定回归或分类模型输出满足边际覆盖率的预测区间）。它与回归诊断 Skill 的骨架完全一致，只是脚本内容换成 conformal 的分割/交叉拟合与覆盖率校验。读者可按同一模板替换脚本实现。

### 21.3.2 Skill 设计：输入输出契约

设计 Skill 的第一步不是写 SKILL.md，而是写契约。契约先于实现，可以避免"脚本写完了才发现输出无法被下游解析"的返工。

| 契约项 | 回归诊断 Skill 的取值 |
|---|---|
| 触发条件 | 用户要求做回归诊断、稳健性检验、异方差检验、共线性检查、影响点检查，或给出一份回归结果要求"检查是否可靠" |
| 输入 | 数据文件路径（CSV/Parquet）、模型公式（patsy 语法）、可选的聚类变量、显著性水平（默认 0.05） |
| 前置校验 | 文件存在、公式可解析、样本量大于待估参数个数加 2、缺失值比例低于 50% |
| 不可由脚本决定的部分 | 是否剔除影响点、是否改用其他模型、结论如何表述——这些交由模型与用户判断 |
| 输出 | 单个 JSON 对象，含 `meta`、`sample`、`fit`、`robust_se`、`diagnostics`、`influence`、`recommendations` 七段 |
| 失败行为 | 输入错误时返回非零退出码与可读错误信息；诊断异常（如矩阵奇异）时返回警告字段而非静默跳过 |
| 副作用 | 除 `--out` 指定路径外不写任何文件；不修改输入数据 |

一个设计原则是：**脚本负责确定性计算与阈值判定，SKILL.md 负责流程编排与解释**。把阈值写进脚本而不是写进提示词，是为了让判定可复现；把解释留给模型，是因为解释需要结合上下文。

```markdown
# 回归诊断与稳健性检查

## 何时使用
- 用户给出一份回归结果或数据集，询问"结果是否可靠""需不需要稳健标准误""有没有影响点"。
- 用户在论文写作或审稿阶段需要一套完整稳健性检查表格。
- 出现上述触发关键词的任意组合时激活。

## 何时不使用
- 因变量为二值且用户明确要求 Logistic/Probit：本 Skill 的脚本针对线性模型，广义线性模型需另写脚本。
- 数据为时间序列且用户关心自相关结构：脚本的 Durbin-Watson 只做提示，不能替代 HAC 标准误。
- 样本量小于待估参数个数加 2：直接报错，要求用户简化模型。

## 执行流程
1. 确认输入：数据文件路径、模型公式、聚类变量（可选）、显著性水平（默认 0.05）。缺失信息只问一次，不反复追问。
2. 调用脚本：
   `python scripts/regression_diagnostics.py --data <path> --formula "<formula>" [--cluster <col>] [--alpha 0.05] --out <path>.json`
3. 读取脚本输出的 JSON，逐段核对：
   - `sample`：样本量、缺失处理、被剔除的观测数。
   - `fit`：OLS 系数、常规标准误、t 值与 p 值。
   - `robust_se`：常规 / HC0 / HC1 / HC2 / HC3 / 聚类稳健标准误的并列对比。
   - `diagnostics`：异方差检验、残差正态性、共线性。
   - `influence`：高杠杆点、Cook 距离超限点、学生化残差超限点。
   - `recommendations`：脚本给出的规则化建议。
4. 生成人读报告，包含四部分：(a) 结论摘要；(b) 稳健标准误对比表；(c) 诊断结果与触发的阈值；(d) 需要用户决策的事项。
5. 列出所有"需要用户判断"的点，不做越权决定。

## 输出契约
报告必须包含下列要素，且每条结论后标注依据字段（如 `diagnostics.breusch_pagan.p_value = 0.003`）：
- 推荐使用的标准误类型及理由。
- 若聚类变量给定：簇数 $G$ 与 $G < 40$ 时的警告。
- 若 `n < 50`：必须提示小样本下稳健标准误仍可能水平失真，建议 bootstrap（见第 21 章 21.5 节）。
- 若存在影响点：报告剔除前后系数变化，但不自动剔除。

## 禁止行为
- 不得修改输入数据文件。
- 不得自行剔除观测点或改变模型设定。
- 不得把统计显著表述为因果效应。
- 不得在脚本未输出某字段时凭印象补写数值；缺失即写"脚本未输出"。
- 不得声称某检验"通过"或"总体可靠"这类整体性判断。

## 示例
输入："检查一下 data/wage.csv 中 lwage ~ educ + exper + tenure 的回归是否可靠，按 firmid 聚类。"
执行：脚本输出 JSON；报告给出稳健标准误对比表、簇数、BP 检验结果、影响点清单，并提示需要用户决定的事项。
```

SKILL.md 的编写有几条经验规则：`description` 用一句话写满触发场景，中英文关键词并列（中文语料触发与英文语料触发都要覆盖）；正文步骤编号连续，每步对应一个可检查的动作；"禁止行为"一节不可省略，它是 Skill 质量的主要差异所在；文件控制在 500 行以内，超出部分拆到 `references/`。

### 21.3.4 脚本开发

```python
#!/usr/bin/env python3
"""回归诊断与稳健性检查。

用法：
    python regression_diagnostics.py --data data.csv --formula "y ~ x1 + x2" \
        [--cluster g] [--alpha 0.05] [--out diag.json]

输出：JSON；默认打印到 stdout，指定 --out 时同时落盘。退出码 0 正常，2 为输入错误。
"""
from __future__ import annotations

import argparse
import hashlib
import json
import platform
import sys
from pathlib import Path

import numpy as np
import pandas as pd
import statsmodels
import statsmodels.formula.api as smf
from statsmodels.stats.diagnostic import het_breuschpagan, het_white
from statsmodels.stats.outliers_influence import OLSInfluence, variance_inflation_factor
from statsmodels.stats.stattools import durbin_watson, jarque_bera

VERSION = "0.3.0"


def sha256(path: Path) -> str:
    h = hashlib.sha256()
    h.update(path.read_bytes())
    return h.hexdigest()


def se_table(res, data: pd.DataFrame, cluster: str | None, terms: list[str]) -> dict:
    """并列输出多种标准误，用于判断结论对方差估计方式的敏感度。"""
    kinds = ["nonrobust", "HC0", "HC1", "HC2", "HC3"]
    out = {}
    for k in kinds:
        if k == "nonrobust":
            # 常规标准误直接取 fit() 默认结果：nonrobust 不是 get_robustcov_results
            # 的合法 cov_type，传进去会直接报错
            se, pv = res.bse, res.pvalues
        else:
            r = res.get_robustcov_results(cov_type=k, use_t=True)
            se, pv = r.bse, r.pvalues
        out[k] = {"se": dict(zip(terms, np.asarray(se).ravel().tolist())),
                  "p": dict(zip(terms, np.asarray(pv).ravel().tolist()))}
    if cluster is not None:
        r = res.get_robustcov_results(
            cov_type="cluster", use_t=True,
            groups=data[cluster].astype("category").cat.codes.to_numpy())
        out["cluster"] = {"se": dict(zip(terms, np.asarray(r.bse).ravel().tolist())),
                          "p": dict(zip(terms, np.asarray(r.pvalues).ravel().tolist())),
                          "n_groups": int(data[cluster].nunique())}
    return out


def main() -> int:
    ap = argparse.ArgumentParser()
    ap.add_argument("--data", required=True)
    ap.add_argument("--formula", required=True)
    ap.add_argument("--cluster", default=None)
    ap.add_argument("--alpha", type=float, default=0.05)
    ap.add_argument("--out", default=None)
    args = ap.parse_args()

    path = Path(args.data)
    if not path.exists():
        print(f"[error] 数据文件不存在: {path}", file=sys.stderr)
        return 2
    df = pd.read_csv(path) if path.suffix == ".csv" else pd.read_parquet(path)

    n_raw = len(df)
    cols = [c.strip() for c in args.formula.split("~")[1].split("+") if c.strip()]
    used = [args.formula.split("~")[0].strip()] + cols + ([args.cluster] if args.cluster else [])
    missing = [c for c in used if c not in df.columns]
    if missing:
        print(f"[error] 数据中缺少变量: {missing}", file=sys.stderr)
        return 2

    df = df[used].dropna().reset_index(drop=True)   # 重置索引，避免影响点位置与标签错位
    n_drop = n_raw - len(df)
    mod = smf.ols(args.formula, data=df)
    res = mod.fit()
    exog_names = list(res.model.exog_names)
    p = len(exog_names)
    n = int(res.nobs)
    if n < p + 2:
        print(f"[error] 样本量 {n} 不足，需至少 {p + 2}", file=sys.stderr)
        return 2
    # 异方差检验
    bp_lm, bp_p, bp_f, bp_fp = het_breuschpagan(res.resid, res.model.exog)
    white_lm, white_p, _, _ = het_white(res.resid, res.model.exog)
    jb, jb_p, skew, kurt = jarque_bera(res.resid)

    # 共线性：对设计矩阵各列计算 VIF，截距列不报告
    X = res.model.exog
    vif = {}
    for j, name in enumerate(exog_names):
        if name.lower() in ("intercept", "const"):
            continue
        try:
            vif[name] = float(variance_inflation_factor(X, j))
        except Exception:
            vif[name] = None

    # 影响点
    infl = OLSInfluence(res)
    h = np.asarray(infl.hat_matrix_diag)
    cooks = np.asarray(infl.cooks_distance[0])
    stud = np.asarray(infl.resid_studentized_external)
    lev_thr, cook_thr = 2.0 * p / n, 4.0 / n
    infl_points = [int(i) for i in np.where((h > lev_thr) | (cooks > cook_thr) | (np.abs(stud) > 3))[0]]

    # 剔除影响点后的系数变化（只报告，不执行剔除）
    refit = {}
    if infl_points:
        r2 = smf.ols(args.formula, data=df.drop(df.index[infl_points])).fit()
        refit = {"n_dropped": len(infl_points),
                 "coef_change_pct": {k: float(100 * (r2.params.get(k, np.nan) / res.params.get(k, np.nan) - 1))
                                     for k in res.params.index if abs(res.params.get(k, 0)) > 1e-12}}

    recs = []
    if bp_p < args.alpha:
        recs.append({"code": "USE_ROBUST_SE",
                     "text": f"Breusch-Pagan 检验 p = {bp_p:.4g} < {args.alpha}，"
                             f"建议报告 HC3 稳健标准误（n < 50 时改用 wild bootstrap）。"})
    if args.cluster is not None:
        G = int(df[args.cluster].nunique())
        txt = f"已按 {args.cluster} 聚类，簇数 G = {G}。"
        if G < 40:
            txt += " G < 40 时聚类稳健标准误在小样本下可能过度拒绝，建议 wild cluster bootstrap。"
        recs.append({"code": "CLUSTER_ROBUST", "text": txt})
    if vif and max(v for v in vif.values() if v is not None) > 10:
        recs.append({"code": "COLLINEARITY", "text": "存在 VIF > 10 的变量，系数估计对设定敏感。"})
    if infl_points:
        recs.append({"code": "INFLUENTIAL", "text": f"检出 {len(infl_points)} 个影响点，剔除后系数变化见 influence.refit。"})
    if jb_p < args.alpha and n < 50:
        recs.append({"code": "SMALL_SAMPLE", "text": f"残差非正态（Jarque-Bera p = {jb_p:.4g}）且 n = {n}，"
                                                    f"依赖渐近正态的推断不可靠。"})
    caveats = ["本脚本只做诊断，不做模型选择",
               "统计显著不等于因果效应",
               "Durbin-Watson 仅作提示，不能替代 HAC 标准误"]

    payload = {
        "meta": {"skill": "regression-diagnostics", "version": VERSION,
                 "python": platform.python_version(), "statsmodels": statsmodels.__version__,
                 "numpy": np.__version__, "data_sha256": sha256(path)[:16],
                 "formula": args.formula, "alpha": args.alpha},
        "sample": {"n_raw": n_raw, "n_used": n, "n_dropped_missing": int(n_drop)},
        "fit": {"params": {k: float(v) for k, v in res.params.items()},
                "bse": dict(zip(exog_names, res.bse.tolist())),
                "pvalues": dict(zip(exog_names, res.pvalues.tolist())),
                "r2": float(res.rsquared), "n_params": p},
        "robust_se": se_table(res, df, args.cluster, exog_names),
        "diagnostics": {"breusch_pagan": {"lm": float(bp_lm), "p_value": float(bp_p)},
                        "white": {"lm": float(white_lm), "p_value": float(white_p)},
                        "jarque_bera": {"stat": float(jb), "p_value": float(jb_p),
                                        "skew": float(skew), "kurtosis": float(kurt)},
                        "durbin_watson": float(durbin_watson(res.resid)),
                        "vif": vif},
        "influence": {"leverage_threshold": lev_thr, "cooks_threshold": cook_thr,
                      "n_flagged": len(infl_points),
                      "index_sample": infl_points[:20], "refit": refit},
        "recommendations": recs,
        "caveats": caveats,
    }
    s = json.dumps(payload, ensure_ascii=False, indent=2)
    if args.out:
        Path(args.out).write_text(s, encoding="utf-8")
    print(s)
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

脚本的解析能力有明确边界：当前版本只处理由 `+` 连接的简单公式，含交互项、变换函数（`np.log(x)`）或分类变量（`C(g)`）的公式需要扩展变量解析逻辑。边界要写在文档里而不是留给用户去试错。

脚本里有两处笔者在练习中踩过的坑，值得写明。其一，`robust_se` 段的"常规"一列不能通过 `get_robustcov_results(cov_type="nonrobust")` 获得——statsmodels 不接受这个协方差类型，会直接报错；常规标准误应当直接取 `fit()` 默认结果里的 `bse` 与 `pvalues`，只有 HC 系列与 cluster 才走 `get_robustcov_results`。其二，缺失值剔除后对索引做了 `reset_index`，否则影响点的位置编号与 DataFrame 标签可能错位，剔除"影响点"时会删错行。修复后笔者在本机（Python 3.10.20、statsmodels 0.15.0）用三组合成数据跑通了 21.3.5 的全部测试用例。

脚本的三个设计要点值得说明。第一，`meta` 段记录了 Python、NumPy、statsmodels 版本与数据哈希，这是第 17 章环境指纹要求在脚本层面的落实：同一份诊断三个月后重跑，若数字变了，先查版本。第二，所有阈值（$2p/n$、$4/n$、$|t|>3$、VIF $>10$、$G<40$）都写成常量并体现在输出里，便于审计，而不是埋在代码中。第三，脚本只给建议（`recommendations`）不改模型，"剔除影响点"只报告剔除后的变化量，决定权留给人。

### 21.3.5 本地测试

测试分两层：脚本层的单元测试针对统计性质，Skill 层的触发测试针对路由。

```python
# tests/test_smoke.py：用两个已知 DGP 验证诊断是否被正确触发
import json
import subprocess
import sys
from pathlib import Path

import numpy as np
import pandas as pd

HERE = Path(__file__).parent
SCRIPT = HERE.parent / "scripts" / "regression_diagnostics.py"


def run(csv: Path, formula: str, cluster: str | None = None) -> dict:
    cmd = [sys.executable, str(SCRIPT), "--data", str(csv), "--formula", formula]
    if cluster:
        cmd += ["--cluster", cluster]
    out = subprocess.run(cmd, capture_output=True, text=True, check=True)
    return json.loads(out.stdout)


def case_heteroskedastic():
    """乘性异方差：BP 检验应当检出。"""
    rng = np.random.default_rng(20260101)
    n = 200
    x1, x2 = rng.normal(size=n), rng.normal(size=n)
    y = 1.0 + 0.5 * x1 + 0.3 * x2 + np.exp(x1) * rng.normal(size=n)
    p = HERE / "case_hetero.csv"
    pd.DataFrame({"y": y, "x1": x1, "x2": x2}).to_csv(p, index=False)
    d = run(p, "y ~ x1 + x2")
    assert d["diagnostics"]["breusch_pagan"]["p_value"] < 0.05, "异方差未被检出"
    assert any(r["code"] == "USE_ROBUST_SE" for r in d["recommendations"])


def case_collinear():
    """近共线：VIF 应当超过 10。"""
    rng = np.random.default_rng(20260102)
    n = 200
    x1 = rng.normal(size=n)
    x2 = x1 + rng.normal(scale=0.01, size=n)      # 与 x1 几乎共线
    y = 1.0 + 0.5 * x1 + 0.0 * x2 + rng.normal(size=n)
    p = HERE / "case_collinear.csv"
    pd.DataFrame({"y": y, "x1": x1, "x2": x2}).to_csv(p, index=False)
    d = run(p, "y ~ x1 + x2")
    assert max(v for v in d["diagnostics"]["vif"].values() if v) > 10, "共线性未被检出"
    assert any(r["code"] == "COLLINEARITY" for r in d["recommendations"])


def case_clustered():
    """聚类结构：簇数被正确记录，小簇数触发警告。"""
    rng = np.random.default_rng(20260103)
    G, m = 20, 10
    g = np.repeat(np.arange(G), m)
    u = rng.normal(scale=1.0, size=G)[g]           # 簇随机效应
    x = rng.normal(size=G * m)
    y = 1.0 + 0.4 * x + u + rng.normal(size=G * m)
    p = HERE / "case_cluster.csv"
    pd.DataFrame({"y": y, "x": x, "g": g}).to_csv(p, index=False)
    d = run(p, "y ~ x", cluster="g")
    assert d["robust_se"]["cluster"]["n_groups"] == G
    assert any(r["code"] == "CLUSTER_ROBUST" for r in d["recommendations"])


if __name__ == "__main__":
    for f in (case_heteroskedastic, case_collinear, case_clustered):
        f()
        print("ok:", f.__name__)
```

| 测试用例 | 构造方式 | 断言 |
|---|---|---|
| 异方差 | 误差标准差取 $\exp(x_1)$ | BP 检验 p 值小于 0.05，且触发 `USE_ROBUST_SE` |
| 共线性 | $x_2 = x_1 + N(0, 0.01^2)$ | 最大 VIF 大于 10，且触发 `COLLINEARITY` |
| 聚类 | 20 个簇，每簇 10 个观测，含簇随机效应 | 簇数记录为 20，且触发 `CLUSTER_ROBUST` |
| 输入错误 | 公式引用不存在的列 | 退出码为 2，错误信息可读 |
| 小样本 | $n = 12$、参数 3 个 | 正常输出且触发 `SMALL_SAMPLE` 提示 |

### 21.3.11 常见失败与排查

以下是笔者在开发与调试这个 Skill 时遇到的问题，多数与路径、环境和输出契约有关。

- `FileNotFoundError`，但文件确实存在——相对路径基准不一致。Agent 客户端启动脚本的 `cwd` 未必是项目根目录。排查步骤：在脚本入口临时打印 `Path.cwd()` 确认基准，随后把路径统一改为相对于 Skill 根目录的写法。
- `ModuleNotFoundError: No module named 'statsmodels'`——触发 Skill 的会话用了另一个解释器。开发环境装了依赖，不代表目标环境也装了。排查步骤：在目标环境里运行 `python -c "import statsmodels"` 核验；README 写明安装命令；发布前做一次干净环境测试。
- 下游解析报 `KeyError: 'vif'` 之类的字段缺失——脚本异常分支没有返回该字段，或模型改写了 JSON。排查步骤：先在命令行直接运行脚本看原始输出，确认是脚本问题还是编排问题；若脚本正常，在 SKILL.md 中强调"原样引用脚本输出，不得改写字段"。
- 测试用例断言失败（如"异方差未被检出"）——种子变动或断言与脚本版本脱节。排查步骤：检查测试数据是否用固定种子重新生成；断言的阈值是否与脚本当前版本一致；两处应同步维护，改动任一方都要重跑全部用例。
- 输入"画一个散点图"也被触发——`description` 里的关键词过宽（如只写了"数据""分析"）。排查步骤：收窄描述，加入"何时不使用"一节，用三到五句真实语句重试路由。

## 21.4 实践三：Agent与MCP工具集成开发

### 21.4.1 目标与场景选择

MCP（Model Context Protocol，模型上下文协议）定义了 Agent 与外部工具之间的通信方式：服务器暴露工具（tools）、资源（resources）与提示模板（prompts），客户端通过标准协议发现并调用。与直接在 Agent 代码里写函数相比，MCP 的价值在于解耦——同一个服务器可以被不同客户端复用，工具的实现语言与运行环境对客户端透明。

本节选择的场景是"文献检索、摘要抽取与引用导出"，它是科研工作中重复率最高、最容易出错的一段流程：从 arXiv 检索相关论文、抽取结构化元数据、生成 BibTeX 并写入本地文献库。这一段流程的错误模式很典型——编造的 arXiv 编号、作者名截断、日期格式不一致，而这些都是可以被程序化校验的。

### 21.4.2 Agent 架构设计

| 模块 | 职责 | 本节实现 |
|---|---|---|
| 规划 | 把用户请求拆成工具调用序列 | 由模型在 ReAct 循环中完成，不写死流程 |
| 记忆 | 保存已检索过的论文与用户偏好 | 本地 JSONL 文件（`notes/`） |
| 工具 | 检索、抽取、导出 | MCP 服务器暴露的四个工具 |
| 执行 | 调用工具并处理返回 | MCP 客户端（Agent 宿主） |
| 审批 | 写文件、发请求前的人工确认 | 客户端侧的写操作审批节点 |

设计上有一条原则：**写操作必须有审批节点，读操作不必**。检索是幂等的，重复执行没有副作用；写入文献库与覆盖文件不可逆，需要人工确认。这个划分与第 18 章关于自主性的边界一致。

### 21.4.3 MCP 服务器实现

```python
#!/usr/bin/env python3
"""文献检索 MCP 服务器（stdio 传输）。

依赖：pip install "mcp[cli]" requests feedparser
运行：python lit_server.py            # 由客户端以子进程方式启动

前置条件：需要先安装 mcp 包；本文件由客户端以子进程方式启动，不单独产生输出。
"""
import json
import urllib.parse
import urllib.request
import xml.etree.ElementTree as ET
from datetime import datetime, timezone
from pathlib import Path

from mcp.server.fastmcp import FastMCP

ROOT = Path(__file__).parent / "library"
ROOT.mkdir(exist_ok=True)
NOTES = ROOT / "notes.jsonl"
mcp = FastMCP("lit-server")

ATOM = "{http://www.w3.org/2005/Atom}"


def _query_arxiv(query: str, max_results: int = 10) -> list[dict]:
    url = "http://export.arxiv.org/api/query?" + urllib.parse.urlencode({
        "search_query": f'all:"{query}"',
        "start": 0, "max_results": max_results,
        "sortBy": "submittedDate", "sortOrder": "descending"})
    with urllib.request.urlopen(url, timeout=20) as r:
        xml = r.read()
    root = ET.fromstring(xml)
    out = []
    for e in root.findall(f"{ATOM}entry"):
        aid = e.findtext(f"{ATOM}id", "").strip()
        out.append({
            "arxiv_id": aid.rsplit("/abs/", 1)[-1],
            "title": " ".join(e.findtext(f"{ATOM}title", "").split()),
            "authors": [a.findtext(f"{ATOM}name", "") for a in e.findall(f"{ATOM}author")],
            "published": e.findtext(f"{ATOM}published", "")[:10],
            "summary": " ".join(e.findtext(f"{ATOM}summary", "").split()),
            "url": aid,
        })
    return out


@mcp.tool()
def search_arxiv(query: str, max_results: int = 10) -> str:
    """检索 arXiv 最新论文，返回结构化元数据列表。"""
    if max_results > 50:
        max_results = 50
    papers = _query_arxiv(query, max_results)
    return json.dumps({"count": len(papers), "papers": papers}, ensure_ascii=False)


@mcp.tool()
def get_paper(arxiv_id: str) -> str:
    """按 arXiv 编号精确获取单篇论文的元数据；编号不存在时返回空结果。"""
    url = "http://export.arxiv.org/api/query?" + urllib.parse.urlencode(
        {"id_list": arxiv_id, "max_results": 1})
    try:
        with urllib.request.urlopen(url, timeout=20) as r:
            root = ET.fromstring(r.read())
    except Exception as exc:                       # 网络失败要显式报告，不许静默
        return json.dumps({"error": f"arXiv 查询失败: {exc}"}, ensure_ascii=False)
    entries = root.findall(f"{ATOM}entry")
    if not entries:
        return json.dumps({"found": False, "arxiv_id": arxiv_id}, ensure_ascii=False)
    e = entries[0]
    return json.dumps({
        "found": True,
        "arxiv_id": arxiv_id,
        "title": " ".join(e.findtext(f"{ATOM}title", "").split()),
        "authors": [a.findtext(f"{ATOM}name", "") for a in e.findall(f"{ATOM}author")],
        "published": e.findtext(f"{ATOM}published", "")[:10],
        "summary": " ".join(e.findtext(f"{ATOM}summary", "").split()),
        "url": "https://arxiv.org/abs/" + arxiv_id,
    }, ensure_ascii=False)


@mcp.tool()
def to_bibtex(arxiv_id: str, citekey: str = "") -> str:
    """把 arXiv 元数据转成 BibTeX 条目；元数据取自 arXiv，不凭记忆生成。"""
    meta = json.loads(get_paper(arxiv_id))
    if not meta.get("found"):
        return json.dumps({"error": f"未找到 {arxiv_id}，无法生成 BibTeX"}, ensure_ascii=False)
    key = citekey or meta["authors"][0].split()[-1].lower() + meta["published"][:4] + \
          meta["title"].split()[0].lower()
    authors = " and ".join(meta["authors"])
    return json.dumps({"citekey": key, "bibtex": (
        f"@misc{{{key},\n"
        f"  title  = {{{meta['title']}}},\n"
        f"  author = {{{authors}}},\n"
        f"  year   = {{{meta['published'][:4]}}},\n"
        f"  eprint = {{{arxiv_id}}},\n"
        f"  url    = {{{meta['url']}}}\n"
        "}")}, ensure_ascii=False)


@mcp.tool()
def save_note(title: str, summary: str, arxiv_id: str = "") -> str:
    """把一条文献笔记追加到本地 library/notes.jsonl（写操作，需在客户端侧确认）。"""
    rec = {"ts": datetime.now(timezone.utc).isoformat(timespec="seconds"),
           "title": title, "summary": summary, "arxiv_id": arxiv_id}
    with NOTES.open("a", encoding="utf-8") as f:
        f.write(json.dumps(rec, ensure_ascii=False) + "\n")
    return json.dumps({"saved": str(NOTES), "title": title}, ensure_ascii=False)


@mcp.resource("notes://recent")
def recent_notes() -> str:
    """返回最近 20 条文献笔记，供 Agent 作为上下文读取。"""
    if not NOTES.exists():
        return "[]"
    lines = NOTES.read_text(encoding="utf-8").strip().split("\n")[-20:]
    return "[" + ",".join(lines) + "]"


if __name__ == "__main__":
    mcp.run(transport="stdio")
```

服务器的三条实现约定：工具返回值统一为字符串化的 JSON，便于客户端解析与日志留档；网络失败时返回显式的 `error` 字段而不是空字符串，避免模型把失败当作"没有相关论文"；元数据一律来自真实查询，`to_bibtex` 不接受模型传入的作者与标题，从源头上杜绝编造引用。

### 21.4.6 工作流编排

端到端流程用 ReAct 循环由模型驱动，而不是写死的脚本。编排层只负责三件事：重试、回退与审批。下面是一个不依赖任何编排框架的极简实现，便于看清结构；生产环境可用 LangGraph 或 LangChain 的状态图机制替代（具体 API 以各自官方文档为准）。

```python
# orchestrator.py：检索 -> 抽取 -> 导出 -> 人工确认 -> 落盘
# 前置条件：安装 mcp 包、网络可访问 arXiv API，且为交互式终端（含人工确认输入）；
# 预期输出：先打印待写入条目清单，确认后写入 library/notes.jsonl，最后打印条目 JSON 的前 500 字符。
import asyncio
import json

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

MAX_RETRY = 2


async def call_with_retry(session, name: str, args: dict) -> dict:
    """工具调用的重试与回退：失败重试若干次，仍失败则回退为人工处理标记。"""
    for k in range(MAX_RETRY + 1):
        try:
            res = await session.call_tool(name, args)
            return json.loads(res.content[0].text)
        except Exception as exc:
            if k == MAX_RETRY:
                return {"_failed": True, "tool": name, "error": str(exc)}
            await asyncio.sleep(2 ** k)
    return {"_failed": True, "tool": name, "error": "unreachable"}


async def run(topic: str, keep: int = 5) -> list[dict]:
    params = StdioServerParameters(command="python", args=["lit_server.py"])
    async with stdio_client(params) as (r, w):
        async with ClientSession(r, w) as s:
            await s.initialize()
            found = await call_with_retry(s, "search_arxiv",
                                          {"query": topic, "max_results": keep})
            if found.get("_failed"):
                return [found]
            picked = [p for p in found.get("papers", [])][:keep]
            for p in picked:
                b = await call_with_retry(s, "to_bibtex", {"arxiv_id": p["arxiv_id"]})
                p["bibtex"] = b.get("bibtex", "")
                p["_bibtex_failed"] = b.get("_failed", False)
            # 审批节点：写操作前由人确认，此处打印待确认内容并等待输入
            print("待写入条目：")
            for p in picked:
                print(" -", p["arxiv_id"], "|", p["title"][:60])
            if input("确认写入文献库? [y/N] ").strip().lower() != "y":
                print("已取消写入")
                return picked
            for p in picked:
                await call_with_retry(s, "save_note",
                                      {"title": p["title"],
                                       "summary": p["summary"][:300],
                                       "arxiv_id": p["arxiv_id"]})
            return picked


if __name__ == "__main__":
    print(json.dumps(asyncio.run(run("conformal prediction")), ensure_ascii=False)[:500])
```

| 状态 | 条件 | 转移 |
|---|---|---|
| 检索 | 初始 | 成功进入抽取；连续失败进入人工标记 |
| 抽取 | 检索成功 | 逐条生成 BibTeX；单条失败只标记该条，不中断 |
| 导出 | 抽取完成 | 打印待确认清单 |
| 审批 | 等待人工输入 | 确认则写入；取消则终止且不落盘 |
| 结束 | 写入完成 | 输出条数与文件位置 |

编排设计中最重要的一点：**单条失败不中断整体流程，但要被显式标记**。若一条论文的 BibTeX 生成失败却不被标记，最终文献库中会出现静默缺失，而使用者往往在投稿前才发现。

### 21.4.9 踩坑记录与经验总结

| 现象 | 原因 | 处置 |
|---|---|---|
| 客户端看不到工具 | 配置路径错误或脚本启动即崩溃 | 先单独运行脚本看是否能启动，再查配置 |
| 参数类型错误 | JSON 中数字被传成字符串 | 在工具函数内做显式类型转换与范围校验 |
| 上下文溢出 | 一次返回过多摘要 | 工具内截断摘要长度，分页返回 |
| Agent 循环卡死 | 工具失败后模型反复重试同一调用 | 编排层设最大轮次；工具返回明确错误而非空结果 |
| 幻觉调用不存在的工具 | 模型按想象的工具名调用 | 工具名保持简短具体；在系统提示中列出可用工具 |
| 多步任务中途丢失目标 | 上下文过长，早期目标被挤出 | 每轮在状态中重述目标；关键结果落盘而非只留在上下文 |
| 引用编号编造 | 模型凭记忆生成 arXiv 编号 | 编号一律由工具从真实查询获得，禁止模型自填 |

MCP 实践中最值得记住的一条是：**工具返回空结果与返回错误是两回事**。返回空结果会被模型理解为"这个方向没有文献"，而真实情况是网络超时。让工具显式区分二者，能消除一类很难排查的静默错误。

### 21.4.10 常见失败与排查

以下是笔者在调试这个 MCP 服务器时遇到的问题，多数可以通过"先在命令行单独运行"来缩小范围。

- 客户端里看不到任何工具——服务器脚本启动即崩溃。排查步骤：在命令行直接运行 `python lit_server.py`，看是否有 import 错误或语法错误；确认修复后再查客户端配置的路径与 `cwd`。
- `ModuleNotFoundError: No module named 'mcp'`——客户端子进程用了另一个 Python 解释器。排查步骤：配置里 `command` 写成虚拟环境内解释器的绝对路径；用 `which python` 核对开发与运行环境是否同一个。
- `TimeoutError` 或调用长时间挂起——arXiv 接口超时或代理未配置。排查步骤：确认 `urlopen` 带 `timeout` 参数；在浏览器或 curl 里试同一查询；检查代理环境变量是否传给了子进程（`env` 字段）。
- `json.decoder.JSONDecodeError: Expecting value`——编排层把工具返回的非 JSON 文本当结果解析。排查步骤：确认所有工具返回值统一为字符串化 JSON；解析失败时走重试与标记分支，而不是让整个流程崩溃。
- 服务器进程残留，下次启动异常——客户端断开后子进程未正常退出。排查步骤：调试期用任务管理器或 `ps` 检查残留的 python 进程；确认使用 stdio 传输时客户端正常关闭了管道，必要时在服务器里处理 SIGTERM。

## 21.5 实践四：用AI辅助解决一个统计问题

### 21.5.1 问题选择与背景

考虑线性模型

$$
y_i = x_i^\top\beta + \varepsilon_i,\qquad \mathbb{E}[\varepsilon_i \mid x_i] = 0,\qquad \operatorname{Var}(\varepsilon_i \mid x_i) = \sigma_i^2 ,
$$

其中误差独立但不要求同方差。OLS 估计量 $\hat\beta = (X^\top X)^{-1}X^\top y$ 在 $\mathbb{E}[\varepsilon\mid X]=0$ 与矩存在条件下仍是无偏且一致的，但常规标准误所依赖的 $\operatorname{Var}(\hat\beta) = \sigma^2 (X^\top X)^{-1}$ 不再成立。异方差一致（heteroskedasticity-consistent，HC）协方差估计量用残差平方 $e_i^2$ 代替未知的 $\sigma_i^2$：

$$
\widehat{\operatorname{Var}}(\hat\beta)_{\mathrm{HC0}} = (X^\top X)^{-1}\Big(\sum_i e_i^2 x_i x_i^\top\Big)(X^\top X)^{-1},
$$

并由此衍生出三个有限样本修正版本，记帽子矩阵 $H = X(X^\top X)^{-1}X^\top$ 的对角元为 $h_{ii}$：

$$
\text{HC1}: \tfrac{n}{n-p}\,\text{HC0};\qquad
\text{HC2}: \sum_i \tfrac{e_i^2}{1-h_{ii}} x_i x_i^\top ;\qquad
\text{HC3}: \sum_i \tfrac{e_i^2}{(1-h_{ii})^2} x_i x_i^\top ,
$$

三个式子均省略前后的 $(X^\top X)^{-1}$ 因子。本实践要回答的问题可以精确表述为：

> 在若干样本量 $n$、设计矩阵结构（含高杠杆点）与异方差强度的组合下，基于常规标准误与 HC0–HC3 的 $t$ 检验在名义水平 $\alpha = 0.05$ 上的实际拒绝率是多少？wild bootstrap 能在多大程度上修正残余失真？在什么边界上所有 HC 类方法都会失效？

这个问题适合作为全书落点，理由有四：第一，它的正确答案是已知的定性方向（HC0 在小样本高杠杆设计下过度拒绝，HC3 明显改善，wild bootstrap 进一步改善，聚类相关下 HC 类全部失效），因此可以检验 AI 给出的结论是否可信；第二，它完全可复现，全部代码在一台笔记本上几分钟可跑完；第三，它涉及估计、检验、渐近理论与蒙特卡洛实验设计——统计学者的全部核心工具；第四，它的每一个环节都能明确划分"AI 能做"与"AI 不能做"。

验证标准事先写定，不得事后修改：

| 指标 | 定义 | 判定标准 |
|---|---|---|
| 实际拒绝率 | $R$ 次重复中拒绝 $H_0$ 的比例 $\hat p$ | 报告 $\hat p$ 与蒙特卡洛标准误 $\sqrt{\hat p(1-\hat p)/R}$ |
| 水平失真 | $\hat p$ 的 95% 蒙特卡洛置信区间是否覆盖 0.05 | 区间完全落在 $[0.04, 0.06]$ 之外即判定为失真 |
| 覆盖率 | 95% 置信区间覆盖真值的比例 | 同上判定 |
| 标准误比值 | $\text{median}(\widehat{se}) / \text{sd}(\hat\beta)$ | 系统性地小于 1 意味着标准误低估 |
| 功效 | $\beta_1 \neq 0$ 设定下的拒绝率 | 在水平可比的口径下比较 |

### 21.5.2 文献调研与知识库构建

文献调研用两条路径并行：一条是结构化数据库检索（Semantic Scholar、arXiv、Google Scholar），另一条是让模型给出候选文献清单。两条路径的结果必须交叉核对，因为模型的召回有系统性偏差——它倾向于给出被引最多、最"经典"的条目，而遗漏较新的修正工作。

本节参考的核心文献（均为该领域的标准引用）：

- White H. (1980). A heteroskedasticity-consistent covariance matrix estimator and a direct test for heteroskedasticity. *Econometrica*, 48(4): 817–838. 提出 HC0。
- MacKinnon J. G., White H. (1985). Some heteroskedasticity-consistent covariance matrix estimators with improved finite sample properties. *Journal of Econometrics*, 29(3): 305–325. 提出 HC1–HC3 的三个变体。
- Wu C. F. J. (1986). Jackknife, bootstrap and other resampling methods in regression analysis. *Annals of Statistics*, 14(4): 1261–1295. wild bootstrap 的早期形式。
- Long J. S., Ervin L. H. (2000). Using heteroskedasticity consistent standard errors in the linear regression model. *The American Statistician*, 54(3): 217–224. 建议在一般情形下使用 HC3。
- Cameron A. C., Gelbach J. B., Miller D. L. (2008). Bootstrap-based improvements for inference with clustered errors. *Review of Economics and Statistics*, 90(3): 414–427. 聚类相关误差下的 bootstrap 修正。
- Imbens G. W., Kolesár M. (2016). Robust standard errors in small samples: some practical advice. *Review of Economics and Statistics*, 98(4): 701–712. 小样本下的实用建议。

知识库构建方式：把上述 PDF 放入本地目录，用支持 RAG 的工具建立索引，检索时要求每段回答附带出处与页码。事实核查采用两条独立手段：一是用第二个模型对同一问题作答并比对（Self-Consistency）；二是把模型给出的每条引用拿去数据库按标题精确检索（查引）。后者尤其重要——**模型生成的 arXiv 编号、卷期与页码是最容易出错的部分，必须逐条核验**。

一条不可省略的原则：模型给出的公式必须与原始文献核对。本实践中 HC2 与 HC3 的分母（$1-h_{ii}$ 与 $(1-h_{ii})^2$）极易被记混，若直接采用模型给出的版本而不核对，整个模拟的结论就建立在一个错误的估计量上。

### 21.5.3 问题拆解与方法设计

问题被拆为五个子问题，每个子问题都有明确的交付物与负责人（人 / AI）。

| 子问题 | 交付物 | 主要承担 | 人的复核点 |
|---|---|---|---|
| 估计量与检验统计量的正确形式 | HC0–HC3 的矩阵表达式 | AI 起草，人对公式逐项核对 | 与 MacKinnon–White (1985) 原文比对 |
| 数据生成过程的设计 | 三个设计 × 四个样本量 × 三档异方差强度 | 人确定，AI 提出补充 | 高杠杆设计是否真的产生高杠杆点 |
| 模拟代码 | 可运行的 Python | AI 起草，人逐行审查 | 小样本手算核对、边界测试 |
| 结果判读 | 拒绝率表 + 结论边界 | 人 | 是否超出模拟覆盖的范围 |
| 失效边界搜索 | 反例设计 | AI 提出候选，人筛选与验证 | 反例是否真属于该方法的适用范围内 |

方法路线的取舍按 Tree-of-Thoughts 的方式展开后收敛：路线一是纯解析推导（有限样本分布难以得到闭式解，放弃）；路线二是蒙特卡洛（可行，选为主路线）；路线三是形式化验证（只能覆盖代数恒等式，不能覆盖有限样本分布性质，作为补充）。被放弃的路线与放弃理由都要记录，这是第 17 章"研究者自由度留痕"的要求。

设计的关键决策由人做出，具体包括：名义水平取 0.05；临界值用 $t_{n-p}$ 分布（Long 与 Ervin 的建议）；wild bootstrap 的权重取 Rademacher（$\pm 1$ 等概率）；bootstrap 统计量沿用与原检验相同的方差估计形式（HC3），因为只有同口径才能得到渐近精化。这四条决策都不是 AI 能替人做出的——它们涉及"在什么意义上算正确"这一判断。

### 21.5.4 代码生成与数值验证

```python
#!/usr/bin/env python3
"""异方差下 t 检验的水平失真：HC0–HC3 与 wild bootstrap 的蒙特卡洛比较。

用法：
    python sim.py --n 50 --design B --lam 3.0 --R 2000 --Bboot 199 \
                  --seed 20260101 --out runs/n50_B_lam3.json
"""
from __future__ import annotations

import argparse
import hashlib
import json
import platform
import time
from pathlib import Path

import numpy as np
from scipy import stats

J = 1  # 待检验的系数下标：0 为截距，1 为 x1


def make_X(rng, n: int, design: str) -> np.ndarray:
    one = np.ones(n)
    if design == "A":                       # 标准正态设计，杠杆值均匀
        x1, x2 = rng.normal(size=n), rng.normal(size=n)
    elif design == "B":                     # 高杠杆设计：x1 对数正态，右尾重
        x1 = np.exp(rng.normal(size=n)) - np.exp(0.5)
        x2 = rng.normal(size=n)
    elif design == "C":                     # 含一个稀疏二元变量
        x1 = (rng.random(n) < 0.1).astype(float)
        x2 = rng.normal(size=n)
    else:
        raise ValueError(design)
    return np.column_stack([one, x1, x2])


def draw_errors(rng, n: int, dist: str) -> np.ndarray:
    if dist == "normal":
        z = rng.normal(size=n)
    elif dist == "t5":
        z = rng.standard_t(5, size=n) / np.sqrt(5 / 3)   # 标准化到单位方差
    elif dist == "lognormal":
        z = (np.exp(rng.normal(size=n)) - np.exp(0.5)) / np.sqrt(np.e ** 2 - np.e)
    else:
        raise ValueError(dist)
    return z


def fit(X: np.ndarray, Y: np.ndarray):
    """Y 可以是 n×m 矩阵：单列是常规拟合，多列用于一次算完所有 bootstrap 复制。"""
    XtX_inv = np.linalg.pinv(X.T @ X)
    B = XtX_inv @ (X.T @ Y)
    return B, Y - X @ B, XtX_inv


def hc_se(X: np.ndarray, E: np.ndarray, XtX_inv: np.ndarray, kind: str, j: int = J) -> np.ndarray:
    """返回第 j 个系数在多种 HC 形式下的标准误；E 为 n×m，返回长度 m 的向量。"""
    n, p = X.shape
    h = np.einsum("ij,jk,ik->i", X, XtX_inv, X)          # 杠杆值 h_ii
    u = E ** 2
    if kind == "OLS":
        s2 = u.sum(axis=0) / (n - p)
        V = s2 * XtX_inv[j, j]
        return np.sqrt(np.repeat(V, E.shape[1]))
    if kind == "HC0":
        w = np.ones(n)
    elif kind == "HC1":
        w = np.full(n, n / (n - p))
    elif kind == "HC2":
        w = 1.0 / (1.0 - h)
    elif kind == "HC3":
        w = 1.0 / (1.0 - h) ** 2
    else:
        raise ValueError(kind)
    W = u * w[:, None]                                    # n×m
    M = np.einsum("ia,im,ib->mab", X, W, X)               # m×p×p 肉矩阵
    V = np.einsum("ac,mcd,db->mab", XtX_inv, M, XtX_inv)  # m×p×p 三明治
    return np.sqrt(V[:, j, j])


def wild_bootstrap_p(X, y, rng, B: int = 199, kind: str = "HC3", j: int = J) -> float:
    """Rademacher wild bootstrap：在原假设下重抽样，统计量与待精化的检验同口径。"""
    n, p = X.shape
    XtX_inv = np.linalg.pinv(X.T @ X)
    b, e, _ = fit(X, y[:, None])
    keep = [k for k in range(p) if k != j]
    br, er, _ = fit(X[:, keep], y[:, None])               # 受约束拟合
    mu = X[:, keep] @ br[:, 0]                            # 原假设下的均值结构
    t_obs = b[j, 0] / hc_se(X, e, XtX_inv, kind, j)[0]
    Wg = rng.integers(0, 2, size=(n, B)) * 2 - 1          # Rademacher 权重
    Bs, Es, _ = fit(X, mu[:, None] + er * Wg)
    t_star = Bs[j, :] / hc_se(X, Es, XtX_inv, kind, j)
    return (1 + np.sum(np.abs(t_star) >= abs(t_obs))) / (B + 1)


def one_rep(rng, n, design, lam, effect, dist, Bboot, kinds):
    X = make_X(rng, n, design)
    beta = np.array([1.0, effect, 0.5])
    sigma = np.sqrt(1.0 + lam * X[:, 1] ** 2)             # 异方差与 x1 绑定
    y = X @ beta + sigma * draw_errors(rng, n, dist)
    XtX_inv = np.linalg.pinv(X.T @ X)
    b, e, _ = fit(X, y[:, None])
    df = n - X.shape[1]
    crit = stats.t.ppf(0.975, df)                          # 双侧 5%，t_{n-p} 临界值
    out = {"beta_hat": float(b[J, 0])}
    for k in kinds:
        se = hc_se(X, e, XtX_inv, k, J)[0]
        out[f"se_{k}"] = float(se)
        out[f"rej_{k}"] = int(abs(b[J, 0] / se) > crit)
        out[f"cov_{k}"] = int(abs(b[J, 0] - beta[J]) <= crit * se)
    out["rej_WB"] = int(wild_bootstrap_p(X, y, rng, Bboot) < 0.05)
    return out


def main() -> int:
    ap = argparse.ArgumentParser()
    ap.add_argument("--n", type=int, default=50)
    ap.add_argument("--design", default="A", choices=["A", "B", "C"])
    ap.add_argument("--lam", type=float, default=1.0, help="异方差强度")
    ap.add_argument("--dist", default="normal", choices=["normal", "t5", "lognormal"])
    ap.add_argument("--effect", type=float, default=0.0, help="beta_1 真值；0 用于测水平")
    ap.add_argument("--R", type=int, default=2000, help="蒙特卡洛重复次数")
    ap.add_argument("--Bboot", type=int, default=199)
    ap.add_argument("--seed", type=int, default=20260101)
    ap.add_argument("--out", default=None)
    args = ap.parse_args()

    kinds = ["OLS", "HC0", "HC1", "HC2", "HC3"]
    children = np.random.SeedSequence(args.seed).spawn(args.R)   # 与并行顺序无关
    rows, bh, ses = [], [], {k: [] for k in kinds}
    t0 = time.time()
    for r in range(args.R):
        o = one_rep(np.random.default_rng(children[r]), args.n, args.design,
                    args.lam, args.effect, args.dist, args.Bboot, kinds)
        rows.append({k: v for k, v in o.items() if not k.startswith(("se_", "beta_"))})
        bh.append(o["beta_hat"])
        for k in kinds:
            ses[k].append(o[f"se_{k}"])
    bh = np.asarray(bh)

    def rate(key: str) -> dict:
        p = float(np.mean([r[key] for r in rows]))
        mcse = float(np.sqrt(p * (1 - p) / args.R))
        return {"rate": round(p, 4), "mcse": round(mcse, 4),
                "lo": round(p - 1.96 * mcse, 4), "hi": round(p + 1.96 * mcse, 4)}

    res = {"config": vars(args), "R": args.R,
           "reject": {k: rate(f"rej_{k}") for k in kinds} | {"WB": rate("rej_WB")},
           "coverage": {k: rate(f"cov_{k}") for k in kinds},
           "se_ratio": {k: round(float(np.median(ses[k]) / bh.std(ddof=1)), 4) for k in kinds},
           "meta": {"python": platform.python_version(), "numpy": np.__version__,
                    "seed": args.seed, "wall_sec": round(time.time() - t0, 1),
                    "config_sha": hashlib.sha256(json.dumps(vars(args), sort_keys=True)
                                                 .encode()).hexdigest()[:16]}}
    s = json.dumps(res, ensure_ascii=False, indent=2)
    if args.out:
        Path(args.out).parent.mkdir(parents=True, exist_ok=True)
        Path(args.out).write_text(s, encoding="utf-8")
    print(s)
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

第一层的意义在于：手算或独立实现能在 AI 生成的代码有系统性偏差时立刻暴露问题。曾出现的典型偏差包括：把 HC2 的分母写成 $(1-h_{ii})^2$、把 $n/(n-p)$ 的 HC1 修正漏掉、把残差用了未中心化的版本。这些错误在"跑得通"的意义下都不会报错，只会给出偏小的标准误与偏高的拒绝率——也就是让结论看起来"更有意思"。笔者核对这一段时，statsmodels 与自实现的 HC3 标准误在小样本上完全一致（0.0622），杠杆值之和精确等于 $p$，这两条通过后才敢往下跑模拟。

#### 21.5.4.1 补充：一个最小闭环演示

在进入全因子网格之前，笔者先写了一个更小的自足脚本，用一份日志同时看到"水平失真、稳健修正、水平恢复"三个阶段。它不依赖 `sim.py`，单独保存为 `closed_loop_demo.py` 即可运行；$R = 1000$、$B = 199$，在普通笔记本 CPU 上约 2 秒跑完，固定种子，结果可复现。

```python
# closed_loop_demo.py：异方差下 OLS 检验水平失真、稳健标准误修正与 wild bootstrap 恢复
import numpy as np
from scipy import stats

R, B, J = 1000, 199, 1          # 重复次数、bootstrap 次数、待检验系数下标
n = 30                          # 小样本 + 高杠杆设计，失真最明显的组合
rng = np.random.default_rng(20260105)   # 固定种子
rej = {k: 0 for k in ("OLS", "HC0", "HC3", "WB")}

for r in range(R):
    x1 = np.exp(rng.normal(size=n)) - np.exp(0.5)      # 对数正态，右尾重，产生高杠杆点
    X = np.column_stack([np.ones(n), x1, rng.normal(size=n)])
    y = X @ np.array([1.0, 0.0, 0.5]) + np.sqrt(1 + 3 * x1 ** 2) * rng.normal(size=n)
    XtX_inv = np.linalg.pinv(X.T @ X)
    b = XtX_inv @ (X.T @ y)
    e = y - X @ b
    h = np.einsum("ij,jk,ik->i", X, XtX_inv, X)
    crit = stats.t.ppf(0.975, n - 3)
    hinv2 = 1.0 / (1.0 - h) ** 2                        # 杠杆值修正因子
    for k, w in (("OLS", (e @ e) / (n - 3)),
                 ("HC0", e ** 2),
                 ("HC3", e ** 2 * hinv2)):
        se = np.sqrt(w * XtX_inv[J, J]) if k == "OLS" else \
             np.sqrt((XtX_inv @ (X.T @ (X * w[:, None])) @ XtX_inv)[J, J])
        rej[k] += int(abs(b[J] / se) > crit)
    # wild bootstrap：原假设下重抽样，统计量与被精化的检验同为 HC3 口径
    Xk = X[:, [0, 2]]
    br = np.linalg.pinv(Xk.T @ Xk) @ (Xk.T @ y)
    mu = Xk @ br                                        # 原假设下的均值结构
    er = y - mu
    Wg = rng.integers(0, 2, size=(n, B)) * 2 - 1        # Rademacher 权重
    Ys = mu[:, None] + er[:, None] * Wg
    Bs = XtX_inv @ (X.T @ Ys)
    Es = Ys - X @ Bs
    t_star = Bs[J] / np.sqrt((XtX_inv @ np.einsum("ia,im,ib->mab", X, Es**2 * hinv2[:, None], X)
                              @ XtX_inv)[:, J, J])
    t_obs = b[J] / np.sqrt((XtX_inv @ (X.T @ (X * (e**2 * hinv2)[:, None])) @ XtX_inv)[J, J])
    pval = (1 + np.sum(np.abs(t_star) >= abs(t_obs))) / (B + 1)
    rej["WB"] += int(pval < 0.05)

print(f"名义水平 0.05，R = {R}，B = {B}，n = {n}，lambda = 3，高杠杆设计")
for k, v in rej.items():
    p = v / R
    print(f"{k}: 拒绝率 {p:.3f}（蒙特卡洛标准误 {np.sqrt(p * (1 - p) / R):.3f}）")
```

### 21.5.5 蒙特卡洛模拟与一致性检验

实验设计用一个全因子网格，参数与取值如下。

| 因子 | 取值 | 统计含义 |
|---|---|---|
| 样本量 $n$ | 25, 50, 100, 400 | 有限样本性质的收敛速度 |
| 设计 | A（标准正态）、B（高杠杆）、C（稀疏二元） | 杠杆值分布 $h_{ii}$ 的形态 |
| 异方差强度 $\lambda$ | 0, 1, 3 | $\sigma_i^2 = 1 + \lambda x_{i1}^2$ |
| 误差分布 | 正态、$t_5$、对数正态 | 检验对误差尾部与偏度的敏感性 |
| 效应 $\beta_1$ | 0（测水平）、0.3（测功效） | 两类误差的区分 |
| 方法 | OLS、HC0、HC1、HC2、HC3、wild bootstrap | 方差估计方式 |
| 重复次数 $R$ | 2000（水平）、2000（功效） | 蒙特卡洛误差控制在 0.01 以内 |

重复次数的选择可以量化说明：在 $p \approx 0.05$、$R = 2000$ 时，蒙特卡洛标准误为 $\sqrt{0.05 \times 0.95 / 2000} \approx 0.0049$，95% 蒙特卡洛区间半宽约 0.0096。这意味着单次模拟能分辨的最小失真在 1 个百分点量级；若要分辨 0.5 个百分点的差异，需要 $R \approx 8000$。**报告拒绝率时不附重复次数与标准误的结果，在统计上不构成证据**——这一点在任何涉及 AI 的评测中同样适用，只是实践中常被忽略。

随机性控制采用两条措施：一是用 `SeedSequence(seed).spawn(R)` 给每次重复分配独立子流，使得结果与并行执行的顺序无关；二是对同一次重复内的所有方法使用同一份数据（共同随机数），从而降低方法间比较的方差。第二点直接借用实验设计中的区组化思想：比较 A 与 B 时，让它们在相同的随机背景下竞争。

```bash
# 全网格扫描（约 4×3×3×2 = 72 组配置；单机串行，按配置耗时估算总时长）
for n in 25 50 100 400; do
  for d in A B C; do
    for l in 0 1 3; do
      python sim.py --n $n --design $d --lam $l --R 2000 --Bboot 199 \
```

### 21.5.6 形式化验证（可选）

本实践的结论主体是有限样本分布性质，这类性质无法被形式化证明——形式化的适用对象是**代数恒等式与结构性引理**，例如帽子矩阵的性质与残差的代数关系。因此形式化在本实践中是补充环节，用于保证代码所依赖的代数前提成立。

数学验证的工具体系按能力分为四层：

| 层次 | 代表工具 | 验证对象 | 正确性保证 |
|---|---|---|---|
| 交互式定理证明器 | Lean 4、Coq、Isabelle | 定理与引理的形式化证明 | 编译（检查）通过即逻辑正确 |
| 神经符号证明系统 | AlphaProof、DeepSeek-Prover-V2、LeanDojo | 证明搜索与候选构造 | 生成的证明仍需经内核检查 |
| 符号计算引擎 | Wolfram/Mathematica、SymPy | 精确符号与数值计算 | 计算结果精确，但命题陈述由人给出 |
| SMT 求解器 | Z3 | 约束满足与反例搜索 | 对可判定片段给出确定答案 |

这四者与"直接问模型"存在本质差异：

| 维度 | 直接向模型提问 | 模型加符号计算 | 模型加形式化验证 |
|---|---|---|---|
| 输出性质 | 自然语言推导，可能跳步 | 计算结果精确，推理链仍由模型生成 | 形式化代码，每步经检查器验证 |
| 正确性保证 | 无 | 计算部分有，命题陈述部分无 | 命题与推理均有机械检查 |
| 可复现性 | 同一问题多次提问结果可能不同 | 计算可复现，推理不可复现 | 代码与证明均可机械复现 |
| 能否发现反例 | 偶然 | 可做数值反例搜索 | 可系统性搜索 |
| 适用环节 | 理解、草稿、灵感 | 数值验证、公式代入 | 定理证明、论文级严谨性 |

学界已有结论指出，模型的幻觉在原理上不可完全消除——不存在一个能学习所有可计算函数的语言模型，因此对复杂定理证明而言，"直接问"在原理上就不可靠。即便模型给出了形式化证明，仍需检查其命题陈述是否忠实于原问题：模型可能在形式化阶段改变了定理的含义，这种偏差不会被内核检查发现。

本实践用属性测试替代大部分形式化工作，这是性价比更高的选择：

```python
# 属性测试：验证代码所依赖的代数性质在小规模随机情形下恒成立
import numpy as np
rng = np.random.default_rng(20260104)
for _ in range(200):
    n = rng.integers(6, 60); p = rng.integers(2, 6)
    X = np.column_stack([np.ones(n), rng.normal(size=(n, p - 1))])
    if np.linalg.matrix_rank(X) < p:
        continue
    XtX_inv = np.linalg.pinv(X.T @ X)
    H = X @ XtX_inv @ X.T
    h = np.diag(H)
    assert np.allclose(H @ H, H, atol=1e-8)                 # 幂等
    assert np.allclose(H, H.T, atol=1e-8)                   # 对称
    assert abs(np.trace(H) - p) < 1e-8                      # 迹等于秩
    assert (h >= -1e-10).all() and (h <= 1 + 1e-10).all()   # 0 <= h_ii <= 1
    y = rng.normal(size=n)
    b = XtX_inv @ (X.T @ y); e = y - X @ b
    assert np.allclose(X.T @ e, 0, atol=1e-8)               # 残差与列空间正交
print("属性测试通过：帽子矩阵与残差的代数性质成立")
```

### 21.5.10 踩坑记录与经验总结

| 现象 | 识别方法 | 处置 |
|---|---|---|
| AI 给出错误的 HC2/HC3 公式 | 与原始文献逐项比对 | 以文献为准；代码中用属性测试护栏 |
| 幻觉引用（不存在的卷期页码） | 按标题精确检索数据库 | 逐条查引；不确定的引用直接删除 |
| 数值精度问题（$1-h_{ii}$ 接近零） | 检查 $h_{ii}$ 的最大值 | 高杠杆接近 1 时 HC2/HC3 方差膨胀，需在报告中说明 |

| 蒙特卡洛收敛慢 | 观察不同 $R$ 下结果是否稳定 | 用共同随机数降低比较方差；必要时提高 $R$ |
| 结论外推 | 检查结论是否超出网格 | 报告中显式写出适用范围 |
| 形式化瓶颈 | Mathlib 缺少相应引理 | 降级为属性测试，或只形式化核心引理 |

有效与无效的环节可以明确划分：

- AI 有效的环节：文献召回与整理、代码骨架生成、网格扫描脚本、属性测试用例生成、报告初稿、反例候选的提出。
- AI 不可靠的环节：公式的最终正确性、引用信息的准确性、结论的统计解释、外推范围的判断。
- 必须由人承担的环节：问题定义、数据生成过程的设计、名义水平与临界值的选择、"是否算失真"的判定标准、最终结论的表述。

**反例搜索**是 AI 在统计研究中最有价值的用法之一。本实践中可以提出这样的问题："在什么数据生成过程下，HC3 也会失效？"模型通常会给出聚类相关误差这一方向。笔者按这个方向写第一版反例时，让误差含簇随机效应、但回归量在个体间独立，实测拒绝率 OLS 0.058、HC3 0.066——失效并没有出现。排查后确认了原因：回归量独立时，同簇观测的交叉项 $\mathbb{E}[x_i x_j^\top]\,(i \neq j)$ 为零，三明治方差中被忽略的项恰好消失，HC 类标准误仍然渐近正确。把回归量 $x_1$ 改成簇级取值（同簇观测取相同值）后，失效如预期出现：修正后的版本如下，实测（$G=20$、$m=20$、$\rho=0.5$、$R=500$、种子 7）拒绝率为 OLS 0.508、HC3 0.526，远高于名义水平。此时正确的做法是改用聚类稳健方差或 wild cluster bootstrap（Cameron, Gelbach & Miller, 2008）。这个反例的价值不在"发现"本身（它是文献中已知的），而在于它清晰地划出了方法的适用边界——失效需要误差与回归量在簇内同时相关——而划边界正是统计学者的工作。

```python
# 反例：误差组内相关 + 回归量组内相关（簇级变量）时 HC3 的失效
import numpy as np
from scipy import stats
from sim import fit, hc_se, J

def cluster_case(G=20, m=20, rho=0.5, R=500, seed=7):
    """G 个簇、每簇 m 个观测，误差含簇随机效应，回归量 x1 取簇级取值。
    预期：HC3 的拒绝率远高于名义水平——HC 类方法假设观测独立，
    簇级回归量与簇随机效应的组合使独立假设下的三明治"肉"被系统性低估。"""
    rng = np.random.default_rng(seed)
    rej_hc3, rej_ols = [], []
    for _ in range(R):
        g = np.repeat(np.arange(G), m)
        x1 = np.repeat(rng.normal(size=G), m)              # 簇级回归量：同簇取值相同
        X = np.column_stack([np.ones(G * m), x1])
        u = rng.normal(scale=np.sqrt(rho), size=G)[g]      # 簇随机效应
        v = rng.normal(scale=np.sqrt(1 - rho), size=G * m)
        y = X @ np.array([1.0, 0.0]) + u + v               # H0: beta_1 = 0 成立
        XtX_inv = np.linalg.pinv(X.T @ X)
        b, e, _ = fit(X, y[:, None])
        crit = stats.t.ppf(0.975, G * m - 2)
        rej_ols.append(abs(b[J, 0] / hc_se(X, e, XtX_inv, "OLS", J)[0]) > crit)
        rej_hc3.append(abs(b[J, 0] / hc_se(X, e, XtX_inv, "HC3", J)[0]) > crit)
    return {"OLS": round(float(np.mean(rej_ols)), 3),
            "HC3": round(float(np.mean(rej_hc3)), 3), "R": R}

print(cluster_case())
```

### 21.5.11 常见失败与排查

以下是笔者在这个实践中实际踩过的坑，多数属于"能跑通但结果错"的类型，比报错更危险。

- `numpy.linalg.LinAlgError: Singular matrix`——设计矩阵列秩不足。常见于哑变量陷阱或完全共线的构造。排查步骤：检查 `np.linalg.matrix_rank(X)` 是否等于列数；确认分类变量的参照组处理；必要时改用 `pinv` 并在报告里说明。
- `ValueError: operands could not be broadcast together`，或在方差处出现负数开根号的 `RuntimeWarning`——多维张量的索引或形状错了。笔者曾把 $(m, p, p)$ 的 bootstrap 方差张量用 `[j, j]` 索引，得到长度 $p$ 的向量而不是各复制的方差。排查步骤：对每个中间张量打印 `.shape`，对角元应当用 `[:, j, j]` 取；出现负方差通常意味着权重里混入了不该有的残差平方。
- 蒙特卡洛结果与文献方向相反——先怀疑实现，再谈发现。排查步骤：跑 $\lambda = 0$ 的同方差对照（各方法拒绝率应接近名义水平）；做 $n=5$ 的手算核对；与 statsmodels 的独立实现对同一份数据比对标准误。
- 拒绝率随小改动大幅波动——蒙特卡洛重复次数不足。排查步骤：报告 $R$ 与蒙特卡洛标准误；用共同随机数比较方法间差异；只有当区间不覆盖名义水平时才下"失真"的结论。
- `MemoryError`（$n=400$ 且 $R$ 很大时）——把所有重复的中间量堆在内存里。排查步骤：改为逐配置落盘再汇总；bootstrap 的 $n \times B$ 矩阵按块生成；必要时降低 $R$ 分批跑。

| 主要风险 | 工程不稳定、成本高、结论难推广 | 维护负担、触发不可靠 | 工具幻觉、权限与副作用 | 幻觉引用、结论外推、实现错误 |
| 失败后可恢复性 | 重跑代价高 | 重跑代价低 | 重跑代价低 | 重跑代价低 |

### 21.6.1 成本对比

| 实践 | GPU 费用 | API 费用 | 人力时间 | 合计量级 |
|---|---|---|---|---|
| 21.2 低算力路线 | 数元至数十元（自持设备则仅电费） | 无 | 4–8 小时 | 百元级 |
| 21.2 标准路线 | 数十至数百元 | 无（本地推理） | 1–2 天 | 千元级 |
| 21.3 | 无 | 每次调用千 token 级 | 半天至 1 天 | 近乎零边际成本 |
| 21.4 | 无 | 每任务数千至数万 token | 1 天 | 十元级 |
| 21.5 | 无 | 数元至数十元 | 2–3 天 | 十元级 |

成本对比的口径必须一致：人力时间是否计入、自持 GPU 是否按折旧计、数据获取成本是否计入，三者的处理方式会显著改变排序。对统计学者而言，21.5 是性价比最高的实践——它的边际成本最低而可发表性最高。

### 21.6.2 时间对比

| 阶段 | 21.2 | 21.3 | 21.4 | 21.5 |
|---|---|---|---|---|
| 环境准备 | 1–3 小时（最不可预测） | 15 分钟 | 30 分钟 | 15 分钟 |
| 主体实现 | 2–4 小时（训练等待为主） | 3–6 小时 | 半天 | 3–5 小时 |
| 验证 | 1–2 小时 | 1–2 小时 | 1–2 小时 | 2–4 小时 |
| 文档与发布 | 1 小时 | 1 小时 | 半小时 | 2–3 小时 |
| 最耗时环节 | 环境配置与训练等待 | 契约设计与测试 | 协议调试 | 结果判读与复核 |

四个实践中最耗时的环节各不相同：训练是环境配置，Skill 是契约设计，Agent 是协议调试，统计问题是判读与复核。共同点是——**验证环节在四个实践中都占到总时间的四分之一以上**，这是可信研究无法压缩的固定成本。

### 21.6.3 验证方式对比

| 实践 | 主验证 | 辅验证 | 验证的局限 |
|---|---|---|---|
| 21.2 | 评测基准分数、loss 曲线 | 人工抽查生成样例 | 小规模模型基准分数可比性差 |
| 21.3 | 契约测试（已知 DGP 的断言） | 触发路由测试 | 覆盖不了开放式输入的全部情形 |
| 21.4 | 协议层冒烟测试、端到端运行 | 引用真实性的逐条核对 | 工具返回正确不代表 Agent 编排正确 |
| 21.5 | 蒙特卡洛、手算对照、属性测试 | 形式化（可选） | 结论只在所覆盖的网格内成立 |

### 21.6.4 失败模式对比

| 实践 | 主要失败模式 | 根因 | 通用对策 |
|---|---|---|---|
| 21.2 | 训练不稳定、显存不足、部署失败 | 工程复杂度与环境的乘积 | 小步验证、每阶段存档、记录环境指纹 |
| 21.3 | 未触发、误触发、输出不符合契约 | 自然语言路由的模糊性 | 收紧 `description`、写"何时不使用"、输出用机器可解析格式 |
| 21.4 | 工具幻觉、循环卡死、静默失败 | 模型对工具边界的误解 | 工具显式区分空结果与错误、编排层设轮次上限 |
| 21.5 | 幻觉引用、错误公式、结论外推 | 模型输出与真值之间无机械保证 | 逐条查引、独立实现对照、显式写适用范围 |

四类失败模式有一个共同结构：都是"看起来成功但实际错误"。loss 在下降不代表模型学到了东西，Skill 被触发不代表执行了正确步骤，Agent 返回了 BibTeX 不代表编号真实，模拟跑通不代表公式正确。因此四个实践的验证都必须包含**独立于被验证对象的第二重检查**。

### 21.6.5 可复现性对比

| 实践 | 复现难度 | 依赖锁定 | 随机性来源 | 第三方复现所需条件 |
|---|---|---|---|---|
| 21.2 | 高 | 锁文件 + 镜像摘要 | 初始化、数据顺序、GPU 归约 | 同等显存的 GPU 与相同 CUDA 版本 |
| 21.3 | 中 | 依赖清单 + 版本 tag | 脚本确定，模型部分不确定 | 支持同一标准的 Agent 客户端 |
| 21.4 | 中 | 依赖清单 + 配置片段 | 工具返回、模型编排 | 网络可访问（arXiv API） |
| 21.5 | 低 | 依赖清单 + 种子 | 伪随机数生成器（已显式控制） | 任何带 NumPy 的环境 |

21.5 的可复现性最高，因为它只依赖伪随机数生成器与确定性数值计算；21.2 最低，因为它依赖硬件相关的浮点归约顺序。这解释了为什么统计学者更适合以 21.5 类型的实践为重心：它落在可复现性最容易保证的区间，而可复现性恰是统计学科的核心规范。

### 21.6.6 选型建议与经验总结

| 读者背景 | 首选实践 | 次选 | 理由 |
|---|---|---|---|
| 统计学博士生 | 21.5 | 21.3 | 21.5 直接产出可发表的方法比较；21.3 把重复劳动固化，长期收益高 |
| 青年教师（带学生、课时紧） | 21.3 | 21.5 | Skill 可分发给课题组，边际成本最低；21.5 可作为研究生训练材料 |
| 有工程基础者 | 21.2 | 21.4 | 已具备环境调试能力，全栈训练的理解收益最大；MCP 是自然的下一步 |
| 算力受限（无 GPU） | 21.5 | 21.3 | 两者均可在笔记本完成 |
| 需要工具落地（课题组共用） | 21.4 | 21.3 | MCP 服务器可被多人复用 |

跨实践有效的做法有三条：小步验证（每完成一环就存档并核验，而不是最后统一检查）、契约先行（先写输入输出再写实现）、独立复核（用第二个实现或第二个模型交叉检查）。只在特定场景有效的做法包括：梯度检查点（只用于训练）、渐进式披露（只用于 Skill）、共同随机数（只用于蒙特卡洛比较）。

必须保留人工的环节在四个实践中是一致的：问题定义、判定标准的选择、结论的表述与边界。工具可以加速这些环节的信息准备，但不能替代判断本身。

## 21.7 从实践到日常科研工作流

### 21.7.1 可复用的模板与脚本

四个实践沉淀出的可复用资产按使用频率排列如下。

| 资产 | 来源 | 复用方式 |
|---|---|---|
| 验证日志字段表（10 项） | 21.1.3 | 每个项目根目录放 `VERIFY.md`，逐项填写 |
| 蒙特卡洛骨架（种子子流、MCSE、共同随机数） | 21.5.5 | 新模拟直接复制 `sim.py` 的框架，只改 DGP 与统计量 |
| 属性测试脚本 | 21.5.6 | 每实现一个估计量就加一组代数性质断言 |
| Skill 目录骨架（SKILL.md + scripts + references + tests） | 21.3.3 | 新 Skill 只替换脚本与契约 |
| MCP 服务器骨架（工具 + 资源 + 错误处理） | 21.4.3 | 新工具只加 `@mcp.tool()` 函数 |
| 训练配置与成本核算模板 | 21.2.14 | 记录每次训练的小时数与 token 数 |
| 报告模板（结果表 + 复核清单） | 21.5.7 | 每个模拟项目复用同一张表结构 |

按时间尺度的使用规范：

| 尺度 | 动作 | 产出 |
|---|---|---|
| 每日 | 当天运行的实验写入验证日志；代码提交带类型前缀 | 一条 commit、一条日志记录 |
| 每周 | 回顾本周失败记录；把重复三次以上的流程记为 Skill 候选 | 候选清单 |
| 每项目 | 建立 `VERIFY.md`、锁文件、种子表；项目结束做一次干净环境复现 | 可交付的复现包 |
| 每半年 | 升级依赖并重跑关键结果；核对 Skill 与 MCP 服务器是否仍可用 | 一份回归测试报告 |

### 21.7.2 可固化为 Skill 的流程

判断一个流程是否值得固化，用三条标准：是否有明确阈值、是否有固定输出格式、是否重复出现。四个实践中符合三条的流程包括：回归诊断与稳健性检查（21.3）、蒙特卡洛水平与功效验证（可固化为 `mc-validation` Skill，输入估计量与 DGP，输出拒绝率表与 MCSE）、论文复现检查（输入论文的方法与结果表，输出复现差异清单）、数据清洗审计（输出过滤前后的统计量）。

不符合三条标准的流程（探索性数据分析、文献阅读、研究选题）不应固化。把它们写成 Skill 会导致每次都要绕过 Skill 的限制，反而降低效率。

### 21.7.3 验证日志的标准字段

与 21.1.3 的字段表一致，落到文件层面建议采用下列结构，一个实验一个目录：

```text
runs/2026-01-15-n25-B-lam3/
├── manifest.json      # 代码 commit、环境、数据哈希、种子、提示词哈希
├── config.yaml        # 完整配置，含未走命令行的默认值
├── metrics.json       # 结果
├── stdout.log
└── failures.md        # 失败记录，含未成功的尝试
```

`failures.md` 是这一结构中最容易被省略、也最不该省略的部分。它记录的是"试过但没成功"的路径，包括被放弃的方法路线、跑崩的参数组合、AI 给出的错误建议。没有它，复现者会重复踩同样的坑；有了它，负面结果也成为可传递的知识。

### 21.7.4 防止能力退化的做法

工具提升效率的同时会侵蚀基础能力，这在统计学者身上表现为三个具体征兆：不再能手算一个小样本的回归系数、看到模拟结果不再能判断数量级是否合理、面对一个检验不再能说出它的假设条件。三条对应的预防措施：

| 征兆 | 预防做法 | 频率 |
|---|---|---|
| 手算能力退化 | 每个新项目开工前手算一个 $n \leq 5$ 的最小例子，与代码结果对照 | 每项目一次 |
| 数量级直觉退化 | 在看模拟结果前先写下预期数量级，再与结果比对 | 每次模拟 |
| 假设条件记忆退化 | 维护一张"方法—假设—失效情形"对照表，手写更新 | 每季度 |
| 推导能力退化 | 每周手推一个经典结果（如 OLS 的无偏性、$t$ 统计量的构造） | 每周 |

这些做法的共同点是：它们都要求人在看到 AI 或代码的答案**之前**先给出自己的答案。顺序很关键——先看到答案会产生锚定效应，人会把自己的判断向答案靠拢，从而失去独立检验的能力。

### 21.7.5 后续可扩展的实践方向

| 方向 | 门槛 | 预期成本 | 说明 |
|---|---|---|---|
| 更大规模训练 | 多卡、分布式训练经验 | 高 | 需要掌握数据并行、张量并行与通信优化 |
| Skill 库建设 | 已有一个可用 Skill | 低 | 把课题组流程逐个固化，形成内部标准 |
| 更复杂的统计问题 | 扎实的推断理论基础 | 中 | 如因果推断中的双重稳健估计、高维推断 |
| 形式化验证深入 | Lean 4 与 Mathlib 使用经验 | 高 | 建议从一条核心引理开始，而非整篇论文 |
| 多智能体协作 | Agent 编排经验 | 中 | 角色分工与结果汇总的可靠性是主要难点 |

## 21.8 自动化工作流 Agent：从单次问答到持续协作者

本章前四节实践的共同前提，是有一个能"读上下文、调工具、跑代码、留下记录"的协作者。第 7 章讲了这类系统的原理（工具调用、Skill、编排），本节把它们落到具体产品：国内外主流的自动化工作流 Agent 各自是什么、适合什么场景、如何安装配置。产品迭代很快，具体界面、命令与计价以各官方文档的当期版本为准，这里只记录相对稳定的定位与选型逻辑。

### 21.8.1 三类产品形态

```text
+---------------------+  IDE/终端内工作  +---------------------+
| 编码类 Agent        |  读写代码仓库、跑测试、开 PR | GitHub Copilot / Codex / Claude Code / Cursor / OpenCode
+---------------------+                  +---------------------+
+---------------------+  本地解释执行    +---------------------+
| 通用执行类 Agent    |  Python/Shell 即写即跑      | Open Interpreter
+---------------------+                  +---------------------+
+---------------------+  图形化编排      +---------------------+
| 平台型工作流        |  拖拽节点、插件、知识库、发布 | Coze(扣子) / Dify / WorkBuddy
+---------------------+                  +---------------------+
```

三类的分界不在模型，而在**运行环境与信任边界**：编码类绑定代码仓库（改动可 diff、可回滚、可 CI 检查），通用执行类直接操作本机（灵活但风险面大，需要沙箱），平台型把编排固定为可视化的图（适合稳定复用的流程，不适合探索）。

### 21.8.2 编码类 Agent

**GitHub Copilot**（https://github.com/features/copilot ）。最早普及的 AI 编程助手，从行内补全发展为对话与 agent mode：给定一个 issue 描述，可以在仓库内自主修改多个文件并发起 PR。适合已经深度使用 GitHub 的团队；个人科研代码仓库同样适用。安装以 IDE 插件为主（VS Code、JetBrains 系），CLI 形式亦有提供。

**OpenAI Codex**（https://github.com/openai/codex ）。OpenAI 的编码 Agent 家族：ChatGPT 内的云端任务（给它一个仓库，它在隔离环境里跑完并给出 diff）与开源的 Codex CLI（`npm install -g @openai/codex`，以终端交互为主）。CLI 的好处是与第 8 章"验证闸门"工作流天然契合——它跑的每条命令都在你的终端里，可记录、可审计。

**Claude Code**（https://code.claude.com ）。Anthropic 的终端 Agent，本书第 21.4 节的 MCP 实践即按其生态编写。特点是 MCP 客户端实现成熟、Skill 与 CLAUDE.md 项目约定机制完善（安装：`npm install -g @anthropic-ai/claude-code`）。配置时注意其文档已迁移至 code.claude.com 域名。

**Cursor**（https://cursor.com ）。AI 原生 IDE（VS Code 分支），把补全、对话、多文件改写与终端集成在同一界面。适合偏好图形界面的用户；仓库级理解依赖其索引机制，大型数据文件建议加入索引排除列表。

**OpenCode**（https://opencode.ai ）。开源的终端编码 Agent，多模型可切换（服务商中立），适合不想把工作流绑在单一模型供应商上的用户；配置文件随仓库分发即可让协作者获得一致的 Agent 环境。

这一类的共同使用要点：先读第 8 章的失败模式清单再放权——变量名幻觉、API 版本不匹配、随机种子缺失等问题在所有编码 Agent 上都会出现，验收靠测试与数值复算，不靠读起来顺。

### 21.8.3 本地执行类：Open Interpreter

**Open Interpreter**（https://github.com/openinterpreter/openinterpreter ）。以"在本地解释执行 Python、JavaScript 与 Shell 命令"成名的通用 Agent（`pip install open-interpreter`，在终端以自然语言驱动）。项目近年有较大变动：原 Python 版本转为社区维护，组织现维护的是基于 OpenAI Codex 分支的 Rust 重写版，安装与用法以仓库当前 README 为准。它的价值在于"探索式数据分析"：让它读一个 CSV、试几种变换、画出图来，全程在本机完成，数据不出门。相应地，它也是三类中风险面最大的：默认能读写文件系统、能联网，使用前应配置沙箱或至少限制工作目录（第 18 章威胁模型直接适用）。可以把本章实践二的 regression-diagnostics 脚本挂给它，观察它在真实数据上是否遵守 SKILL.md 的"禁止行为"清单——这本身就是一次不错的 Agent 可靠性实验。

### 21.8.4 平台型工作流：Coze、Dify 与 WorkBuddy

**Coze（国内版"扣子"）**（https://www.coze.cn ）。字节跳动出品的低代码智能体与工作流平台：拖拽节点编排流程（LLM 节点、插件节点、条件分支）、挂知识库、发布为对话 Bot、API 或小程序。适合把一个已经验证过的流程（如"每日 arXiv 摘要推送"）固化给非编程的协作者使用；其编排图与第 21.4.6 节的 orchestrator 结构一一对应，先写代码版再迁移到平台上，调试成本最低。

**Dify**（https://github.com/langgenius/dify ）。开源的 LLM 应用与工作流平台，可自托管（`docker compose up` 一套即起），提供工作流编排、RAG、模型路由。与 Coze 的主要差别在数据主权：实验数据不适合出内网时，Dify 是平台型方案里的默认候选。统计分析场景里，它适合做"文献监测流水线""问卷初筛"这类以文本为主的工作。

**WorkBuddy**（https://www.workbuddy.cn ）。桌面端 AI 工作台，本书的修订与本章全部实证复现即在其会话内完成。特点是把 Skill 生态（与第 21.3 节的 Agent Skills 目录结构同源）、MCP 连接器（与 21.4 节同协议）、定时自动化与文件系统集成在一个客户端里，支持 Agent/Plan/Ask 三种介入深度。对统计科研的日常价值在于：跨项目的长期记忆（评估口径、期刊模板）可以沉淀在工具侧，而不必每次重述。

### 21.8.5 选型对比与安装速查

| 产品 | 形态 | 安装/接入 | 模型绑定 | 与本书的交叉点 |
|---|---|---|---|---|
| GitHub Copilot | IDE 插件 + agent mode | IDE 插件市场 | OpenAI 系为主 | 第 8 章验证闸门 |
| OpenAI Codex | 云端任务 + 开源 CLI | `npm i -g @openai/codex` | OpenAI | 第 8 章、第 19 章成本 |
| Claude Code | 终端 Agent | `npm i -g @anthropic-ai/claude-code` | Anthropic | 21.3 Skill、21.4 MCP |
| Cursor | AI 原生 IDE | 官网安装包 | 多模型 | 第 8 章 |
| OpenCode | 终端 Agent（开源） | 官网/包管理器 | 多模型 | 第 8 章 |
| Open Interpreter | 本地执行 | `pip install open-interpreter` | 多模型 | 第 18 章安全边界 |
| Coze（扣子） | 云端编排平台 | 网页注册 | 平台提供 | 21.4.6 编排结构 |
| Dify | 自托管平台 | `docker compose` | 多模型 | 第 17 章可复现 |
| WorkBuddy | 桌面工作台 | 官网安装包 | 多模型 | 全书工作流 |

选型不必追求"最强"，建议按两个问题收敛：第一，**改动是否发生在代码仓库里**——是则选编码类（改动可 diff 可回滚），否则才考虑执行类或平台型；第二，**数据能否出本机**——不能出则把 Dify 自托管、Open Interpreter 加沙箱或纯本地模型（21.2 节的 Qwen 端点）纳入候选。最后一件事比选型本身更重要：无论用哪一款，都按第 17 章的规范留验证日志，Agent 的产出与人的产出适用同一套可复现标准。

## 本章小结

- 四个实践分别落在三条主线上：21.2 对应模型原理线，21.3 与 21.4 对应工具与编排线，21.5 对应研究与验证线；四者的共同评价标准是可复现、可审计、可反思。
- 全栈训练的成本门槛已被 MiniMind 一类项目压到单次百元以内、数小时量级，代价是结果只具备教学与工程验证价值；标准路线（LoRA 微调开源基座）在 24 GB 单卡上可行，产出具备实际用途。
- Skill 的价值不在提示词本身，而在可版本化的契约、可测试的脚本与"禁止行为"条款；同一份 SKILL.md 目录可在遵循 Agent Skills 标准的多个平台间直接复用。
- MCP 把工具能力从 Agent 代码中解耦，其工程质量的关键在于工具显式区分"空结果"与"错误"，并对写操作设置人工审批节点。
- 异方差下 $t$ 检验的水平失真问题可以用蒙特卡洛完整刻画：HC0 在小样本与高杠杆设计下存在可见的过度拒绝，HC3 明显改善，wild bootstrap 进一步接近名义水平，而在聚类相关误差下 HC 类方法全部失效。
- 蒙特卡洛结论必须附带重复次数与蒙特卡洛标准误；只给点估计的拒绝率不构成证据。共同随机数与种子子流划分分别降低方法间比较的方差与并行执行的不确定性。
- AI 在统计研究中最有效的环节是文献召回、代码骨架、网格扫描与反例候选提出；不可靠的环节是公式的最终正确性、引用信息准确性与结论解释；问题定义、判定标准选择、结论边界三项必须由人承担。
- 工作流 Agent（21.8 节）的选型依据是运行环境与信任边界，而非模型强弱：改动发生在代码仓库里选编码类，数据不能出本机则自托管或用本地模型；无论哪一款，Agent 的产出与人的产出适用同一套可复现标准。
- 四个实践的验证成本均占总时间四分之一以上，且四类失败模式的共同结构是"看起来成功但实际错误"，因此每个实践都需要独立于被验证对象的第二重检查。
