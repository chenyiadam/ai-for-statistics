# 第18章 安全、伦理、合规与学术诚信

> **本章定位**：本章位于"怎么研究 AI"主线的约束侧。前序各章解决"能不能做出来"，本章解决"该不该做、能不能合法合规地做、做完之后如何自证清白"：威胁建模、大模型应用的已知风险清单、数据隐私与本地部署、隐私保护技术的统计代价、版权与许可、AI 使用披露、人类受试者保护、公平与环境成本、权限与审计。
> **关键词**：威胁模型、OWASP LLM Top 10、差分隐私、联邦学习、许可兼容性、学术诚信、群体公平、审计日志

## 本章导读

AI 进入研究工作流之后，统计学者面对的风险种类发生了结构变化。传统统计研究的风险集中在数据侧：受试者隐私、知情同意、数据保存期限。引入大模型后，风险沿着三条新的路径扩散——数据可能经由提示词离开本地，结论可能被不可复现的模型调用所影响，成果的知识产权与署名边界变得模糊。这三类风险的共同点是：它们不产生任何错误信息，因此不会被常规的统计检验发现。

本章按"识别—防护—合规—留证"的顺序展开。18.1 与 18.2 处理识别：先建立针对科研场景的威胁模型，再逐项对照 OWASP 的 LLM 风险清单，把每一类风险映射到具体的科研动作上。18.3 与 18.4 处理防护：前者划定数据不得外传的边界与本地部署的实际能力，后者给出差分隐私与联邦学习的数学定义与统计代价，这一节是全章公式最密集的部分，因为隐私保护技术的选择本质上是一个偏差—方差权衡问题。两节各配有一个可在本机复现的数值模拟：准标识符唯一记录比例随属性数上升的模拟（18.3.3），以及 Laplace 机制下噪声—样本量权衡的模拟（18.4.4）；18.4.8 另有一个成员推断攻击的玩具实验。18.5 至 18.7 处理合规：许可兼容性、AI 使用披露、人类受试者保护。18.8 处理两个容易被忽略的外部性：公平性定义之间的不相容与能耗核算。18.9 回到留证，给出权限、审批与审计日志的最小要求。

对统计学读者的提示是：本章的技术内容多数可以还原为统计问题。差分隐私是给统计量加一个已知分布的噪声并重新推导方差；联邦学习是非独立同分布样本上的分布式估计；公平性定义的不可兼得是一组条件概率约束的不相容；审计日志的完整性是一个覆盖率估计问题。用这些既有语言理解它们，比记忆名词更有利于做出正确判断。

关于政策的一个总说明：本章涉及的法律、期刊与机构政策更新频繁，凡涉及具体条款、适用范围与判定的内容，本章只给出通行做法与判断框架，**具体执行以所在机构的现行规定与出版方的当期作者指南为准**。

## 18.1 威胁模型

### 18.1.1 三要素

威胁模型（threat model）由三要素构成：**资产**（需要保护什么）、**攻击面**（从哪里可能进来）、**攻击者能力**（对手能做什么）。三者缺一，安全讨论就会退化为泛泛而谈。

资产清点的产出是一张清单，而不是一句"数据很重要"。科研项目中的典型资产及其损失后果见下表。

| 资产 | 具体内容 | 泄露或被篡改的后果 |
|---|---|---|
| 未发表数据 | 原始观测、中间结果、未发布的估计值 | 优先权丧失，结论被抢发 |
| 人类受试者数据 | 个人标识、健康记录、问卷回答 | 法律责任，伦理批件失效，参与者受损 |
| 分析代码与管道 | 未公开的方法实现 | 知识产权流失，方法被抢先 |
| 提示词与 Skill | 内部方法学、评审标准、标注规则 | 方法被复制，评审标准被针对性规避 |
| 模型权重与适配器 | 微调产物、LoRA 权重 | 商业价值与学术优先权损失 |
| 密钥与访问凭据 | API 密钥、云控制台口令、SSH 私钥 | 算力被盗用，数据被批量拉取 |
| 在审稿件与审稿意见 | 未公开的手稿、同行评审内容 | 违反审稿保密义务 |
| 算力配额与预算 | GPU 小时、账户余额 | 经济损失，项目中断 |

攻击面是资产与外界发生交互的所有接口。AI 工作流的攻击面比传统统计项目宽，因为多出了提示词通道、检索通道与工具调用通道。

| 攻击面 | 典型形态 | 可能的后果 |
|---|---|---|
| 提示与上下文 | 用户输入、网页内容、PDF 正文、邮件 | 提示注入，模型执行非预期动作 |
| 检索语料 | 向量库中的文档、参考文献全文 | 语料投毒，结论被操纵 |
| 工具与插件 | Shell、文件读写、数据库、HTTP 请求 | 越权操作，数据外传 |
| 依赖供应链 | PyPI/npm/conda 包、容器基础镜像、模型权重文件 | 供应链攻击，后门 |
| 模型端点 | 推理服务、API 网关 | 越狱、拒绝服务、凭证泄露 |
| 协作平台 | 共享文档、代码托管、实验追踪系统 | 权限配置错误导致越权访问 |
| 日志与追踪系统 | 运行日志、提示与响应记录 | 日志本身成为泄露源 |

攻击者能力按强弱分四级：**被动观察者**（只能看到流经的流量，如同一网络下的其他用户）、**主动注入者**（能构造输入内容，如论文 PDF 的作者、网页的发布者）、**内部人**（拥有部分合法权限，如合作者、临时助研）、**供应链上游维护者**（能修改被依赖的包或镜像）。同一资产对四级攻击者的暴露程度不同，缓解措施也不同。

把资产、攻击面与攻击者能力放进同一张图，可以得到一个按信任边界分层的示意。层级越靠外，防护越依赖组织与流程手段；层级越靠内，防护越依赖工程手段。一个真实的安全事件往往自外向内穿过多个边界：恶意 PDF 中的隐藏指令（第 1 层的外部文本）触发提示注入（第 2 层的模型缺陷），进而驱动智能体的 shell 工具（第 3 层的系统权限）把数据传出本机——这意味着防护不能只押在某一层上。

```text
第 4 层  人
  合作者、助研、审稿人、供应链维护者、平台管理员
  威胁：误操作、越权访问、主动泄密、社会工程
  ---- 信任边界 B3：权限分离、审批流、保密协议（见 18.9）----
第 3 层  系统
  操作系统、容器、包管理器、云服务、日志与追踪系统
  威胁：供应链攻击、配置错误、日志泄露（对应 LLM05）
  ---- 信任边界 B2：锁定依赖、最小权限、出网审计 ----
第 2 层  模型
  权重、提示与上下文、插件与工具调用
  威胁：提示注入、越狱、过度代理、训练数据复述（LLM01/06/07/08）
  ---- 信任边界 B1：输出校验、动作白名单、高风险动作人工确认 ----
第 1 层  数据
  原始数据、中间结果、提示中携带的外部文本
  威胁：外泄、篡改、重识别（链接攻击，见 18.3.3）
```

图注：层级自下而上聚合，外层包含内层；虚线为信任边界，边界上标注的是该层可用的主要缓解手段。上图是示意而非完备分类，具体项目应按 18.1.3 的流程画出自己的版本。

### 18.1.2 科研场景的五类威胁

**数据外泄。** 把未发表数据或受试者数据粘贴进对话框、上传给在线服务、或写进提示词，是最常见也最不可逆的一类。不可逆的原因是：多数服务会保留请求日志，删除对话不等于删除服务方记录。

**结果篡改。** 攻击者（或无意的操作）改变中间数据、替换权重文件、修改评估脚本中的一行，使最终数字改变而表面无异常。这类威胁的检测手段是哈希与签名，而非人工检查。

**知识产权流失。** 未公开的方法、提示词与数据经由第三方服务被留存，或被合作者带走。治理手段是分级访问与保密协议，技术手段为辅。

**提示注入导致的误判。** 这是 AI 工作流特有的一类：模型读取的外部内容（待分析的文件、检索到的网页）中嵌入了指令性文本，模型据此改变行为，产出看似合理但被操纵的结论。对统计学者而言，这一威胁的危险之处在于它污染的是"解读"环节而非"计算"环节——计算过程可能完全正确，结论却已被带偏。

**算力与额度滥用。** 密钥泄露导致的批量调用。治理手段是配额、预算告警与密钥轮换。

### 18.1.3 威胁建模的操作步骤

一个可执行的最小流程是六步：列出资产并标注敏感度等级 → 画出数据流图（数据从哪里来、经过哪些系统、到哪里去，跨过哪些信任边界）→ 对每个接口枚举威胁（可借用 STRIDE 的六类：仿冒、篡改、否认、信息泄露、拒绝服务、权限提升）→ 按影响与可能性评级 → 制定缓解措施并指定责任人 → 在流程改变后复评。

评级中的"可能性"一项值得统计学者的特别注意：实操中它常被填成一个凭感觉的概率，而这类数字会直接决定资源的分配方向。可行的改进是给可能性找依据——同类事件的历史发生频率、公开的事件统计、或系统自身的日志；找不到依据时就标记为"未知"，并把未知本身作为提高防护等级的理由。风险评级的不确定性应被记录并在复评时修正，形式上与先验敏感性分析相同。

## 18.2 OWASP LLM Top 10

### 18.2.1 清单的定位与版本

OWASP（Open Web Application Security Project）维护的 LLM 应用风险清单是业界最常被引用的十项风险列表，其定位是**风险意识清单**而非合规标准：它告诉你容易出问题的地方，不提供通过或不通过的判定。清单会随技术演进而重排，2023 版与后续版本在条目划分上有明显差异，**引用时应以 OWASP 官方当期发布的清单为准**。

下表按 2023 版的十项给出定义、科研场景实例与缓解措施。

| 编号 | 风险 | 定义 | 科研场景实例 | 缓解措施 |
|---|---|---|---|---|
| LLM01 | 提示注入 | 攻击者通过输入内容改变模型行为 | 让模型总结的论文 PDF 中隐藏白色文字指令，使摘要结论被改写 | 外部内容视为数据而非指令；指令与数据用明确分隔符隔离；对产出做独立校验 |
| LLM02 | 不安全输出处理 | 模型输出未经校验直接传给下游系统 | 模型生成的字符串被直接拼进 SQL 或 shell 命令 | 输出视为不可信输入；白名单校验、参数化查询、禁用直接执行 |
| LLM03 | 训练数据投毒 | 训练或微调数据被植入恶意样本 | 公开爬取的语料中被混入带有特定触发词的错误结论 | 数据溯源与抽样人工核查；哈希锁定；异常样本检测 |
| LLM04 | 模型拒绝服务 | 通过超长输入或高频请求耗尽资源 | 一次提交超长上下文导致 GPU 显存溢出，共享集群上影响他人 | 输入长度与速率限制；超时与配额；资源隔离 |
| LLM05 | 供应链漏洞 | 依赖的包、模型、插件被植入后门 | 安装了名称相似的仿冒包，或拉取了被替换的权重文件 | 锁定版本与哈希；私有镜像源；依赖审计；权重校验和核对 |
| LLM06 | 敏感信息泄露 | 模型输出或系统中泄露了不应公开的信息 | 模型在回答中复述了训练数据中的受试者信息 | 训练前清洗；输出过滤；涉密数据不上公有服务 |
| LLM07 | 不安全插件设计 | 插件缺乏输入校验与权限控制 | 一个"运行代码"插件接受任意 shell 字符串 | 插件最小权限；参数化接口而非自由文本；沙箱执行 |
| LLM08 | 过度代理 | 模型被赋予超出需要的自主行动权 | 智能体被允许在无人确认下删除文件或发起付款 | 高风险动作人工确认；权限分级；动作白名单 |
| LLM09 | 过度依赖 | 使用者不加核验地采信模型输出 | 直接把模型给出的文献引用写进论文，引用并不存在 | 强制核验；要求给出可查来源；把模型输出当作待检验的假设 |
| LLM10 | 模型盗窃 | 模型权重或训练数据被非法获取或复制 | 私有微调权重被未授权下载 | 访问控制与水印；模型仓库权限审计；出网审计 |

### 18.2.2 逐项说明

**LLM01 提示注入。** 模型无法从原理上区分"指令"与"被处理的文本"，这是架构层面的限制，不是配置错误可以消除的。因此缓解措施只能是工程性的：把外部内容明确标记为待处理的数据、用不可混淆的分隔方式隔离指令、对模型产出的关键结论做独立于模型的校验。统计学者尤其要注意文献处理场景：待总结的 PDF 与网页都是攻击者可写入的通道。

**LLM02 不安全输出处理。** 与传统的输入校验是同一件事，只是攻击者换成了模型。若模型输出被拼进 SQL、shell、HTML 或文件路径，就等于把模型的自由文本当作可信输入。缓解方式是白名单校验与参数化接口：模型的输出应当是"选择哪个枚举值"或"填入哪个参数槽"，而不是"生成一段可执行文本"。

**LLM03 训练数据投毒。** 在自建数据集或微调语料来自公开来源时，投毒是现实威胁。缓解依赖数据治理：记录每个样本的出处、对来源做可信度分级、抽样人工核查、以及保存语料的哈希快照以便事后追溯。

**LLM04 模型拒绝服务。** 影响的不只是自身：在共享 GPU 集群上，一次显存溢出或高频请求会影响同一节点的其他用户。缓解手段是配额与隔离，这一项通常由集群管理员而非研究者实施，但研究者应在脚本中设置输入长度上限。

**LLM05 供应链漏洞。** 科研 Python 生态中，仿冒包名（typosquatting）与被劫持的维护者账号都发生过。缓解方式是锁定版本与哈希、使用机构私有镜像源、以及把拉取的权重文件按校验和核对。第 17 章 17.1 与 17.2 给出的锁定手段在此直接适用。

**LLM06 敏感信息泄露。** 两个方向：模型在输出中复述训练数据中的个人信息；以及系统层面的泄露（日志、上下文缓存、错误消息）。前者依赖训练前的数据清洗与输出过滤，后者依赖日志脱敏与访问控制。

**LLM07 不安全插件设计。** 判断标准是插件接口是否接受自由文本。接受任意字符串的"执行命令"类插件，等价于把 shell 权限交给模型的输出。应改为参数化接口并对参数取值做白名单校验。

**LLM08 过度代理。** 与最小权限原则（18.9）是同一条原则在智能体上的应用。判定方法是列出智能体能执行的动作，逐项问"这个动作若被错误触发，损失是否可逆"；对不可逆动作一律要求人工确认。

**LLM09 过度依赖。** 这一项与统计学的关联最直接：模型输出的置信度与正确率之间的关系是校准问题（第 16 章），而多数使用者默认模型是校准的。缓解手段是把模型输出当作待检验的假设而不是结论，并对关键事实要求可查证来源。

**LLM10 模型盗窃。** 科研场景中主要表现为未授权访问私有权重与训练数据。缓解手段是访问控制、出网审计与水印；其中水印技术的有效性取决于具体方案与攻击方式，不宜作为唯一防线。

## 18.3 数据隐私与本地部署

### 18.3.1 数据分级与"不得外传"的判定

数据是否可以被上传到第三方服务，取决于它属于哪一级。下表给出一个可操作的分级与判定。

| 级别 | 内容 | 能否上传公有服务 | 依据 |
|---|---|---|---|
| 公开数据 | 已发表论文中的表格、公开基准数据集 | 可以 | 无保密义务 |
| 内部未发表数据 | 自己的中间结果、未投稿的估计值 | 原则上不 | 优先权与保密义务 |
| 项目约定保密数据 | 合作方提供、签有使用协议的数据 | 不 | 数据使用协议条款 |
| 个人可识别信息 | 含标识符或准标识符的记录 | 不 | 个人数据保护法规 |
| 人类受试者数据 | 健康记录、问卷回答、影像 | 不 | 伦理批件与知情同意范围 |
| 涉密与受管制数据 | 涉密科研数据、出口管制物项 | 不 | 法律法规 |

判定可用三问：**是否含个人信息**（含则受个人数据保护法规约束）、**是否负有保密义务**（协议、伦理批件、审稿保密）、**是否已公开**（未公开则有优先权风险）。三问中任一为是，就不应上传公有服务。需要注意，这一判定针对的是"上传"这一动作，与服务方声明的保留政策无关：即使服务方声明不用于训练，数据在传输与日志环节已经离开控制范围。

### 18.3.2 本地部署的边界

本地部署（on-premises / local deployment）是涉密数据场景的标准解法，但"本地"不等于"安全"。残留风险至少包括四类：本地服务的遥测与更新请求可能出网、本地服务默认监听地址可能暴露给局域网、日志与缓存写入磁盘后受本机其他进程访问、以及本地权重文件本身可能来自不可信来源。

因此本地部署应配合一份离线运行清单：关闭或确认出网策略、把服务绑定到回环地址、禁用遥测与自动更新、检查日志写入位置并设置权限、核对权重的校验和。

|---|---|---|---|
| 公有云 API | 是 | 服务方留存、跨法域传输 | 公开数据 |
| 机构私有部署 | 否（在机构网络内） | 机构内部越权访问、日志留存 | 内部与保密数据 |
| 单机本地推理 | 否 | 本机其他进程、遥测出网、磁盘缓存 | 受试者数据 |
| 完全离线（air-gapped） | 否 | 供应链（安装介质） | 涉密数据 |

### 18.3.3 去标识化的统计界限

去标识化（de-identification）与匿名化（anonymization）不是同一件事。前者移除了直接标识符但保留了准标识符（年龄、性别、邮编、就诊日期等），记录仍可通过链接攻击被重识别；后者要求在考虑"合理可能的手段"后无法识别到个人，标准显著更高。在不少法域的法律框架下，去标识化后的数据仍然属于个人数据，只是处理要求有所降低。

重识别风险可以用统计量刻画。**k-匿名（k-anonymity）**要求任意一条记录在准标识符上与至少 $k-1$ 条其他记录不可区分，即等价类大小至少为 $k$。它抵御的是基于准标识符精确匹配的链接攻击，但不抵御等价类内属性同质的攻击（由此引出 l-多样性与 t-接近性）。

更根本的界限来自高维稀疏性：准标识符的维度增加时，记录唯一的比例迅速上升。已有研究在移动轨迹与消费记录等高维数据上给出过很高的唯一性比例——少量时空点或少量交易记录即足以让个体在群体中变得唯一。这提示一条实践规则：**准标识符维度越高，删除直接标识符的保护作用越弱**，此时必须靠抑制（删除或泛化变量）、聚合（降低粒度）或正式的隐私保护机制（18.4）。

这个界限可以用一个最小模拟直观化。生成 $n=10000$ 条合成记录，逐个加入五个常见准标识符（性别、五岁一组的年龄段、邮编前两位、就诊月份、初诊科室），统计唯一记录比例（等价类大小为 1 的记录占比）随属性数的变化。以下代码仅依赖 numpy，实测环境为 Python 3.10.20 与 numpy 1.26.4。

```python
# kanon_risk.py：准标识符组合的唯一化率随属性数上升的模拟
import numpy as np

rng = np.random.default_rng(7)
n = 10000
sex   = rng.integers(0, 2, n)          # 性别
age5  = rng.integers(0, 16, n)         # 年龄（5 岁一组，0-79）
zip2  = rng.integers(0, 50, n)         # 邮编前两位（50 个区域）
month = rng.integers(0, 12, n)         # 就诊月份
dept  = rng.integers(0, 8, n)          # 初诊科室

attrs = [("性别", sex), ("年龄段", age5), ("邮编前2位", zip2),
         ("就诊月份", month), ("初诊科室", dept)]

cols = []
print(f"{'k':>2} {'added':<8} {'n_cells':>8} {'max_class':>9} {'unique_rate':>11}")
for k, (name, col) in enumerate(attrs, start=1):
    cols.append(col)
    mat = np.column_stack(cols)
    _, counts = np.unique(mat, axis=0, return_counts=True)
    uniq = np.mean(counts == 1)
    print(f"{k:>2} {name:<8} {len(counts):>8} {counts.max():>9} {uniq:>11.3f}")
```

 2 年龄段            32       349       0.000

解读这组数字：只用性别时，任何一条记录都与数千条记录不可区分，唯一化率为零；加到三项准标识符时仍接近零（1.3%）；加到四项时约 76% 的记录已唯一，五项时约 97%——此时最大等价类也只剩 3 条记录，k-匿名的 $k$ 名存实亡。也就是说，"删除了姓名与身份证号"不等于"无法识别到个人"，准标识符取值组合的基数才是决定性的。读者在发布数据集之前，或许可以用这段代码（换成自己数据集的真实准标识符）做一次成本最低的自查：唯一化比例若不可忽略，就需要泛化、抑制或改用 18.4 的形式化机制。需要说明的是，本模拟假定准标识符相互独立，真实数据的属性间相关性会改变具体数值，但"唯一化率随属性数快速上升"的趋势是结构性的。

从统计角度看，去标识化是有代价的：泛化与抑制改变了变量的测量尺度，引入与经典测量误差类似的衰减效应，并降低估计的有效性。因此去标识化的程度应与再识别风险的评估结果相匹配，而不是一律最大化。

## 18.4 差分隐私与联邦学习

### 18.4.1 $(\epsilon,\delta)$-差分隐私的定义

称两个数据集 $D$ 与 $D'$ 为**相邻（adjacent）**，若二者相差且仅相差一个个体的记录（增加、删除或替换其一）。一个随机算法 $\mathcal M$ 满足 $(\epsilon,\delta)$-差分隐私，若对任意相邻数据集 $D,D'$ 与任意可测输出集合 $S\subseteq\mathrm{Range}(\mathcal M)$，有

$$\Pr[\mathcal M(D)\in S]\le e^{\epsilon}\,\Pr[\mathcal M(D')\in S]+\delta .$$

定义包含三层含义。$\epsilon\ge 0$ 是隐私预算：它约束了输出分布在有无某一个体时的最大对数似然比，$\epsilon$ 越小，单个个体对输出的影响越小。$\delta\in[0,1]$ 是失败概率：允许定义以不超过 $\delta$ 的概率被违反；纯 $\epsilon$-DP 对应 $\delta=0$。第三，该保证对任意输出集合 $S$ 成立，因而**不依赖于攻击者的辅助信息**——这是它相对于 k-匿名一类基于等价类定义的根本优势，也解释了为什么不需要假定攻击者知道哪些准标识符。

### 18.4.2 基本性质

**后处理免疫（post-processing immunity）。** 若 $\mathcal M$ 满足 $(\epsilon,\delta)$-DP，则对任意（可能随机化的）函数 $g$，$g(\mathcal M(D))$ 仍满足 $(\epsilon,\delta)$-DP。这一性质保证了隐私保证不会因为后续分析而损失，是 DP 可用的关键。

**串行组合（basic composition）。** 若 $\mathcal M_1,\ldots,\mathcal M_k$ 分别满足 $(\epsilon_i,\delta_i)$-DP，且依次作用于同一数据集，则组合后满足 $(\sum_i\epsilon_i,\ \sum_i\delta_i)$-DP。

**高级组合（advanced composition）。** 上述线性累积是宽松的。更强的结论是：在自适应组合下，总预算的增长约为 $\epsilon\sqrt{k}$ 量级而非 $k\epsilon$，代价是 $\delta$ 相应增加。实际实现中通常使用 Rényi 差分隐私（RDP）：RDP 在各阶 $\alpha$ 下可加，组合后统一换算回 $(\epsilon,\delta)$，得到的预算远小于串行组合的朴素结果。

**群隐私（group privacy）。** 由定义可推，若两个数据集相差 $c$ 个个体，则保证退化为 $(c\epsilon,\ c\delta e^{c\epsilon})$ 量级。这一条的实际含义是：隐私预算应按"可能被同时影响的最大群体规模"来解释，而非仅按单条记录。

### 18.4.3 基本机制

**Laplace 机制。** 对实值查询 $f:\mathcal D\to\mathbb R^{d}$，定义 $\ell_1$ 敏感度 $\Delta_1 f=\max_{D\sim D'}\|f(D)-f(D')\|_1$。输出 $f(D)+\mathrm{Lap}(\Delta_1 f/\epsilon)$ 满足 $\epsilon$-DP。

**Gaussian 机制。** 用 $\ell_2$ 敏感度 $\Delta_2 f$ 时，加 $\mathcal N(0,\sigma^2)$ 噪声，取

$$\sigma\ge \frac{\Delta_2 f\sqrt{2\ln(1.25/\delta)}}{\epsilon}$$

可满足 $(\epsilon,\delta)$-DP（要求 $\epsilon<1$、$\delta>0$）。Gaussian 机制需要 $\delta>0$，但噪声在高维情形下增长慢于 Laplace，是深度学习场景的常用选择。

### 18.4.4 隐私噪声的统计代价

把 DP 还原为一个统计问题是理解其代价的最直接方式。设要发布样本均值 $\bar X=\frac1n\sum_i X_i$，其中 $X_i\in[l,u]$。相邻数据集使一个 $X_i$ 改变，故 $\Delta_1 f=(u-l)/n$。Laplace 机制加入的噪声方差为 $2(\Delta_1 f/\epsilon)^2=\dfrac{2(u-l)^2}{n^2\epsilon^2}$。把它与抽样方差 $\sigma^2/n$ 比较：

$$\frac{\text{隐私噪声方差}}{\text{抽样方差}}=\frac{2(u-l)^2}{n\,\epsilon^2\,\sigma^2}.$$

这一比值随样本量 $n$ 增大而**下降**。也就是说，在大样本下隐私噪声相对于抽样误差的代价较小，而在小样本下隐私噪声可能主导总方差——这与统计实践中"小样本研究受隐私保护约束更紧"的直觉一致，也给出了量化依据。

由此得到三条可直接用于研究设计的结论：

其一，**置信区间必须同时包含两项**。DP 下的区间宽度不再是 $z_{\alpha/2}\sigma/\sqrt n$，而是 $\sqrt{\sigma^2/n+\tau^2(\epsilon,\delta,n)}$，其中 $\tau^2$ 是隐私噪声方差。只报告抽样误差会低估不确定性。

其二，**样本量需要重新规划**。给定目标区间半宽 $d$，所需样本量由 $n\approx z^2\sigma^2/d^2$ 变为解 $\sqrt{\sigma^2/n+\tau^2(n)}=d$。由于 $\tau^2$ 通常随 $n$ 增大而减小（$1/n^2$ 量级），方程有解，但所需 $n$ 严格大于无隐私约束的情形；在 $\epsilon$ 很小时增幅显著。

其三，**功效必须在设计阶段估计**。隐私噪声降低检验的功效；在预算受限、样本量固定的情形下，某些效应量将不再可检测。此时应报告最小可检测效应量，而不是简单报告"未发现显著差异"。

上述方差分解可以用一个最小模拟验证。设定与本节开头的推导一致：$X_i\sim N(5,\ 2^2)$，取值区间 $[l,u]=[0,10]$，基线样本量 $n_0=1000$。表中第一列是隐私预算 $\epsilon$；第二列是在 $n_0$ 处隐私噪声方差与抽样方差之比；第三列 $n_{\mathrm{required}}$ 是解析解出的样本量——把 $\sqrt{\sigma^2/n+\tau^2(\epsilon,n)}$ 代回 $n_0$ 处的总方差所对应的 $n$；第四列是在 $n_{\mathrm{required}}$ 下重复 2000 次模拟得到的 $|\hat{\bar X}_{\mathrm{DP}}-\mu|$ 的 95% 分位数，用来与无隐私约束时的正态近似半宽 0.1240 对照。

```python
# laplace_tradeoff.py：Laplace 机制下均值估计的噪声—样本量权衡
import numpy as np

rng = np.random.default_rng(2026)
lo, hi, sigma, n0, reps = 0.0, 10.0, 2.0, 1000, 2000
mu = 5.0

def dp_mean(x, eps):
    sens = (hi - lo) / len(x)          # 均值的 l1 敏感度
    return np.clip(x, lo, hi).mean() + rng.laplace(0.0, sens / eps)

def required_n(eps, v):
    """解 sigma^2/n + 2(u-l)^2/(eps^2 n^2) = v 的正根，v 为目标总方差"""
    a = 2.0 * (hi - lo) ** 2 / eps ** 2
    return (sigma ** 2 + np.sqrt(sigma ** 4 + 4 * v * a)) / (2 * v)

v0 = sigma ** 2 / n0                    # 无隐私约束时 n=1000 的抽样方差
base_hw = 1.96 * np.sqrt(v0)
print(f"baseline: n0={n0}, var={v0:.5f}, 95% half-width={base_hw:.4f}")
print(f"{'eps':>5} {'var_ratio@n0':>12} {'n_required':>11} {'sim_95hw':>9}")
for eps in (0.1, 0.5, 2.0):
    n_star = int(np.ceil(required_n(eps, v0)))
    errs = np.empty(reps)
    for r in range(reps):
        x = rng.normal(mu, sigma, n_star)
        errs[r] = dp_mean(x, eps) - mu
    hw = np.percentile(np.abs(errs), 95)
    ratio = (2 * (hi - lo) ** 2 / (eps ** 2 * n0 ** 2)) / v0
    print(f"{eps:>5} {ratio:>12.3f} {n_star:>11} {hw:>9.4f}")
```

实测环境为 Python 3.10.20 与 numpy 1.26.4，输出如下：

```text
baseline: n0=1000, var=0.00400, 95% half-width=0.1240
  eps var_ratio@n0  n_required  sim_95hw
  0.1        5.000        2792    0.1285
  0.5        0.200        1171    0.1212
  2.0        0.013        1013    0.1235
```

解读：$\epsilon=0.1$ 时隐私噪声方差是抽样方差的 5 倍，样本量需要从 1000 增加到约 2800（约 2.8 倍）才能把区间半宽拉回原水平；$\epsilon=0.5$ 时隐私噪声只占两成，样本量多约 17% 即可；$\epsilon=2$ 时几乎不需要额外样本。这正是本节开头"隐私噪声方差随 $n$ 以 $1/n^2$ 下降"的数值体现：样本量规划若忽略隐私噪声项，得到的置信区间会系统性偏窄。模拟的 95% 分位数与正态近似值 0.1240 之间有小幅出入，来源是 2000 次重复的蒙特卡洛误差与 Laplace 噪声的重尾（方差相同时重尾分布的分位数更高），不影响量级判断；更精确的区间可以直接用解析式 $\sqrt{\sigma^2/n+\tau^2}$ 构造。

### 18.4.5 DP-SGD 与隐私会计

在深度学习中使用 DP 的标准做法是 DP-SGD，它在普通 SGD 上加了两个步骤：**逐样本梯度裁剪**（把每个样本的梯度范数截断到常数 $C$，从而把敏感度限制为 $C$ 量级）与**加噪**（在聚合后的梯度上加入方差为 $\sigma^2C^2$ 的高斯噪声）。训练过程中隐私预算随步数累积，因此需要隐私会计（privacy accounting）来跟踪总消耗。

Moments Accountant 与 RDP 是两种主流会计方法，后者因在各阶下可加、实现简单而被广泛采用。RDP 的核心性质是：若机制 $\mathcal M$ 满足 $(\alpha,\varepsilon_{\mathrm{RDP}})$-RDP，则它同时满足 $(\varepsilon_{\mathrm{RDP}}+\frac{\log(1/\delta)}{\alpha-1},\ \delta)$-DP，对任意 $\alpha>1$ 成立；$k$ 次组合只需把各阶的 $\varepsilon_{\mathrm{RDP}}$ 相加，再对所有 $\alpha$ 取最小的换算结果。工程实现上不必自己写：PyTorch 生态有 Opacus，TensorFlow 生态有相应的隐私库，另有面向经典统计与机器学习算法的通用库。使用时的三个要点是：噪声乘子 $\sigma$ 与裁剪范数 $C$ 是要调的超参数并影响效用；预算消耗随训练轮数增长，因此"多训几轮"在 DP 下不是免费的；参与率（采样率 $q$）进入预算计算，采样率越低每轮消耗的预算越少。

```python
# RDP 会计：把 (alpha, eps_rdp) 换算为 (eps, delta)，并对 alpha 取最优
import numpy as np

def rdp_to_dp(eps_rdp: float, alpha: float, delta: float) -> float:
    """RDP 到近似 DP 的标准换算：eps = eps_rdp + log(1/delta)/(alpha-1)"""
    return eps_rdp + np.log(1.0 / delta) / (alpha - 1.0)

def eps_from_rdp_curve(rdp_curve, delta=1e-5, alphas=None):
    """rdp_curve: dict{alpha: eps_rdp}（已含 k 次组合的累加）；返回最小的换算 eps"""
    if alphas is None:
        alphas = np.arange(1.1, 64.0, 0.1)
    return min(rdp_to_dp(rdp_curve[a], a, delta) for a in alphas)

# 高斯机制在采样率 q、噪声乘子 sigma、步数 T 下的 RDP 曲线（示意，实际请用库实现）
def gaussian_rdp(q, sigma, T, alphas):
    return {a: T * q**2 * a / (2 * sigma**2) for a in alphas}

alphas = np.arange(1.1, 64.0, 0.1)
curve = gaussian_rdp(q=0.01, sigma=1.1, T=3000, alphas=alphas)
print("eps =", round(eps_from_rdp_curve(curve, delta=1e-5, alphas=alphas), 3))
```

```text

```

### 18.4.6 联邦学习的分类

联邦学习（federated learning）指数据保留在本地、只交换模型参数或统计量的一类分布式训练方式。按数据在各参与方之间的划分方式分为三类。

| 类型 | 数据划分 | 典型场景 | 主要估计偏差来源 |
|---|---|---|---|
| 横向联邦（horizontal） | 各方样本不同、特征空间相同 | 多家医院的同类电子病历 | 各站点人群构成不同（分布异构） |
| 纵向联邦（vertical） | 各方样本重叠、特征不同 | 同一批客户在银行与电商的特征 | 样本对齐误差、特征缺失 |
| 联邦迁移（federated transfer） | 样本与特征都重叠很少 | 跨领域、跨地区协作 | 领域偏移，迁移假设的成立性 |

横向联邦的标准目标是

$$\min_{w}\ F(w)=\sum_{k=1}^{K} p_k\,F_k(w),\qquad p_k=\frac{n_k}{n},\quad F_k(w)=\mathbb E_{z\sim\mathcal D_k}\big[\ell(w;z)\big],$$

其中 $K$ 为参与方数，$n_k$ 为第 $k$ 方的样本量，$\mathcal D_k$ 为该方的局部数据分布。FedAvg 通过多轮"本地多步更新 + 服务端加权平均"来近似求解。

### 18.4.7 统计异构带来的偏差

当各方分布 $\mathcal D_k$ 不同（统计异构，statistical heterogeneity）时，上面这个加权目标的最优解 $w^\star$ 有三重身份需要区分：它既不是任何一个 $\mathcal D_k$ 上的局部最优，也未必等于把全部数据集中起来后按混合分布 $\bar{\mathcal D}=\sum_k p_k\mathcal D_k$ 所得到的最优——后者才是"数据若能集中"时的目标。当 $\mathcal D_k$ 差异显著时，单一全局模型对部分参与方的效用会明显下降，这是联邦学习的核心统计困难。

误差可以分解为三个来源（下列分解用于说明结构，具体项的阶依赖算法与假设）：

$$\hat w^{\mathrm{FL}}-w^\star \;\approx\; \underbrace{\text{客户端漂移偏差}}_{\text{本地多步更新 + 异构，不随轮数消失}}
\;+\; \underbrace{\text{客户端抽样方差}}_{\text{每轮仅部分参与，量级 }O(1/\sqrt{CK})}
\;+\; \underbrace{\text{本地样本方差}}_{\text{量级 }O(1/\sqrt{n_k})}.$$

第一项是偏差项，来源是本地多步更新把各方的参数推向各自的局部最优，服务端平均后又拉回，形成围绕 $w^\star$ 的偏移；通信频率越低（本地步数越多）或异构越强，该项越大。缓解方法是加近端项约束本地更新不远离全局参数，或用控制变量修正漂移方向。第二项来自每轮只抽取一部分客户端参与，性质上与整群抽样中的群间方差相同：参与率越低、各方数据量越不均衡，方差越大；不均衡还会使加权平均被大站点主导，此时 $p_k$ 的定义方式（按样本量还是按站点等权）直接决定目标函数估计的是哪个总体。第三项与集中式训练相同。

对统计学者的实践含义是三条：一是报告联邦模型的效果时必须分站点报告，全局指标会掩盖站点间的巨大差异；二是参与率与加权方案属于估计目标的定义，应在方法部分写明而不是留给实现细节；三是把"站点"作为随机效应或固定效应纳入分析，与 17.2.1 处理环境漂移的做法同构——二者都是把一类非抽样变异显式建模，而不是假定它不存在。

### 18.4.8 隐私保护的边界

联邦学习常被误认为"天然满足隐私保护"，这是不成立的。参数交换本身可以泄露信息：已有研究表明，从共享的梯度中可以在一定条件下反推出训练样本的部分信息。因此联邦学习通常需要配合两项额外措施：**安全聚合**（服务端只能解密各方更新之和，无法看到单个参与方的更新）与**差分隐私**（在共享的更新上加噪）。前者防的是诚实但好奇的服务端，后者防的是对最终模型的推断攻击。二者防的威胁不同，不可互相替代。

"对最终模型的推断攻击"最典型的形态是成员推断攻击（membership inference attack）：攻击者能查询模型（或读到输出的置信度），对某条具体记录计算一个分数——最常用的是逐样本损失或置信度——再依据"训练集成员的损失通常更低"来判断该记录是否参与过训练。这一攻击的可行性完全来自模型的记忆：模型在训练样本上的表现系统性优于同分布的新样本。下面用仅依赖 numpy 的玩具实验演示这一点。

设定：150 维二分类合成数据，标签带不可消除的噪声（贝叶斯误差大于零）。对比两种情形：训练样本量 $n=100$ 小于维度 $d=150$，逻辑回归可以把训练集的交叉熵拟合到近零（插值，即记忆）；$n=5000$ 远大于 $d$，模型只能泛化。攻击者的分数取逐样本负交叉熵，用秩和法计算 AUC（ROC 曲线下面积，0.5 等于随机猜测）。

```python
# member_inference_toy.py：成员推断攻击的玩具实验（仅 numpy）
import numpy as np

rng = np.random.default_rng(3)
d = 150
w_true = rng.normal(0, 1, d)

def make_data(m):
    X = rng.normal(0, 1, (m, d))
    logits = X @ w_true + rng.normal(0, 1.0, m)   # 标签噪声：贝叶斯误差不可消除
    y = (logits > 0).astype(float)
    return X, y

Xte, yte = make_data(2000)                        # 非成员池

def fit_logistic(X, y, lr=0.5, epochs=3000):
    n = len(X)
    Xb = np.hstack([X, np.ones((n, 1))])
    theta = np.zeros(d + 1)
    for _ in range(epochs):
        p = 1.0 / (1.0 + np.exp(-np.clip(Xb @ theta, -30, 30)))
        grad = Xb.T @ (p - y) / n
        theta -= lr * grad
    return theta

def per_nll(theta, X, y):
    """逐样本交叉熵（数值稳定），即攻击者可得的逐样本损失"""
    Xb = np.hstack([X, np.ones((len(X), 1))])
    z = np.clip(Xb @ theta, -30, 30)
    return np.logaddexp(0.0, z) - y * z

def auc(scores, members):
    """秩和法 AUC：分数越大越像成员；0.5 等于随机猜测"""
    order = np.argsort(scores)
    ranks = np.empty(len(scores))
    ranks[order] = np.arange(1, len(scores) + 1)
    n1, n0 = members.sum(), (~members).sum()
    return (ranks[members].sum() - n1 * (n1 + 1) / 2) / (n1 * n0)

# 两种情形：d > n_train（可插值，记忆训练集）对比 d 远小于 n_train（泛化）
for n_train, lr, ep in [(100, 0.5, 3000), (5000, 0.5, 200)]:
    Xtr, ytr = make_data(n_train)
    theta = fit_logistic(Xtr, ytr, lr, ep)
    members = np.concatenate([np.ones(n_train, bool), np.zeros(len(Xte), bool)])
    scores = np.concatenate([-per_nll(theta, Xtr, ytr), -per_nll(theta, Xte, yte)])
    print(f"n_train={n_train}: train_NLL={per_nll(theta, Xtr, ytr).mean():.4f} "
          f"test_NLL={per_nll(theta, Xte, yte).mean():.4f} "
          f"attack_AUC={auc(scores, members):.3f}")
```

实测环境为 Python 3.10.20 与 numpy 1.26.4，输出如下：

```text
n_train=100: train_NLL=0.0007 test_NLL=1.0661 attack_AUC=0.777
n_train=5000: train_NLL=0.1171 test_NLL=0.1372 attack_AUC=0.509
```

解读与两点保留。可插值情形下，训练集交叉熵被压到 0.0007 而测试集为 1.0661，攻击者仅凭逐样本损失就把成员与非成员区分开（AUC 0.78，显著高于随机的 0.5）；泛化情形下训练与测试损失几乎相等，攻击退化到随机猜测（AUC 0.51）。这印证了记忆是攻击的根源。保留之一：AUC 0.78 只是这个玩具设定下的数值，成员仅 100 条、分布完全已知，不能直接外推为真实大模型的泄露率；真实攻击评估见延伸资源中 Shokri 等人的原始论文。保留之二：在调试这个玩具的过程中笔者观察到，即便加大正则化、或把训练停得很早，逐样本损失在训练集上仍然系统性偏低——经验风险最小化本身就会给训练样本留下痕迹，仅靠"不要过拟合"的直觉不足以消除信号。这正是 18.4.1 的形式化保证（DP 训练）比启发式缓解更值得依赖的原因，也是 18.7.3 的表中把 DP 单列为"有形式保证"一行的原因。另外要注意环节的分工：安全聚合保护的是参数传输环节，成员推断风险评估针对的是最终模型的发布环节，模型对外提供置信度输出时后者尤其需要单独评估。

## 18.5 版权、许可与训练数据

### 18.5.1 常见许可与兼容性

开源许可按限制强度可以分为宽松型（permissive）、弱 copyleft 与强 copyleft 三类。下表给出常见许可的关键条款与混用时的注意点。

| 许可 | 类型 | copyleft | 专利授权 | 混用时的主要注意事项 |
|---|---|---|---|---|
| MIT | 宽松 | 无 | 无明示 | 保留版权声明即可，可并入专有项目 |
| BSD（2/3 条款） | 宽松 | 无 | 无明示 | 3 条款版禁止用作者名义背书 |
| Apache-2.0 | 宽松 | 无 | 有明示授权 | 需保留 NOTICE；与 GPL-2.0 不兼容，与 GPL-3.0 兼容 |
| GPL-2.0 | 强 copyleft | 有 | 无明示 | 分发衍生作品须以同许可开源 |
| GPL-3.0 | 强 copyleft | 有 | 有 | 同上，且对硬件限制有额外条款 |
| LGPL | 弱 copyleft | 有（按库边界） | 依版本 | 动态链接通常不传染主程序 |
| AGPL | 强 copyleft | 有（含网络服务） | 有 | 通过网络提供服务也触发开源义务 |
| CC0 | 公有领域贡献 | 无 | 无 | 数据可自由使用，无须署名 |
| CC-BY | 数据/内容 | 无 | 无 | 使用须署名 |
| CC-BY-SA | 数据/内容 | 有（相同方式共享） | 无 | 衍生作品须以相同许可发布 |

判定兼容性时的三条经验规则：宽松许可之间可自由合并；copyleft 许可的"传染性"沿衍生作品的边界发生，判定的关键是是否构成衍生作品；Apache-2.0 与 GPL-2.0 的不兼容来自附加条款，与 GPL-3.0 则兼容。这些规则的适用依赖于具体的使用方式（复制、修改、链接、再分发），**涉及时应以许可原文与机构法务意见为准**。

### 18.5.2 权重许可与数据许可的分离

模型权重与其训练数据受各自的许可约束，且二者经常不同：一个以宽松许可发布的模型，其训练数据可能受 CC-BY-NC 或专有条款限制；一个"开放权重"（open weights）的模型也可能附带用途限制（如禁止用于某些领域、超过一定规模需另行授权），这类许可不属于严格意义上的开源许可。

由此产生三个必须分别检查的对象：模型权重的许可、训练数据的许可、以及所使用代码与依赖的许可。三者的交集才是实际可行的使用范围。检查动作包括：查看模型仓库中的 LICENSE 与模型卡中的许可声明、查看数据集的许可与获取条款、用工具生成依赖的许可清单并核对。

### 18.5.3 训练数据的获取与爬取

训练数据的三个合规要点：一是**抓取行为本身**是否违反目标站点的 robots.txt 或服务条款；二是对**数据库特殊权利**与内容版权的尊重（不同法域规定差异较大）；三是**个人数据**在语料中的存在——即使页面公开，其中的个人信息仍受个人数据保护法规约束。

研究用途并不自动构成免责。不同法域对文本与数据挖掘有各自的例外条款，适用条件（研究机构身份、非商业目的、数据来源合法）各不相同，**具体适用应以所在法域的现行法规与机构法务意见为准**。

### 18.5.4 输出物的归属

AI 生成内容的著作权地位在不同法域差异较大，且仍在演进，本章不给出具体判定。可操作的两条建议是：在论文与代码中标明生成部分及其使用的工具与版本，避免后续争议；在涉及第三方模型时，遵守其许可中对输出物的条款（部分许可对输出物有附加条件）。

## 18.6 AI生成内容声明与期刊政策

### 18.6.1 披露的四要素

规范的 AI 使用披露应包含四个要素：**用途**（哪个环节用了：文献检索、语言润色、代码生成、数据分析、图表制作）、**工具**（名称与版本或访问日期）、**日期**（使用时间，因为模型行为随时间变化）、**范围**（生成了什么内容，以及作者对生成内容做了哪些核验）。四项齐全的披露才能让读者判断可信度；只写"使用了 AI 辅助"没有信息量。

下表按环节给出披露建议。

| 使用环节 | 是否需要披露 | 建议写在何处 | 常见误区 |
|---|---|---|---|
| 语言润色与翻译 | 是（多数机构要求） | 致谢或方法节的声明段 | 认为润色不需披露 |
| 文献检索 | 建议 | 方法节 | 把模型给出的引文直接写入而未核验 |
| 代码生成与调试 | 建议 | 代码可用性声明或方法节 | 忽略对生成代码的复核责任 |
| 数据分析与统计建模 | 是 | 方法节，写明具体步骤 | 不说明哪些分析由模型建议 |
| 图表生成 | 是（若图像为生成式产出） | 图注或方法节 | 未标明图像为生成而非实拍/实测 |
| 撰写正文段落 | 是 | 方法节或声明段 | 大段采用而不声明 |
| 同行评审 | 依出版方规定 | 评审系统内的保密声明 | 把在审稿件上传给第三方服务 |

把上表压缩成一个决策流程，可以画成下图。流程的第一道岔口是保密而非披露——上传在审稿件或未发表数据给第三方服务的做法没有"补披露"的补救方式，只能换用满足 18.3 要求的部署形态。

### 18.6.2 署名与责任

AI 系统不能作为论文作者，这是出版界较为一致的立场，理由是作者身份伴随对内容的责任与对诚信调查的可问责性，而这一责任无法由非人类的系统承担。由此推出的两条规则：作者对其提交的文本负全部责任，包括由 AI 生成的那一部分；作者必须能够说明并复现分析过程，不能以"模型给出的"作为对错误的解释。

### 18.6.3 保密义务

与披露同样重要的是保密：在审稿件、审稿意见、未发表数据与合作者的未公开材料，不得上传到第三方服务。这条义务的来源是审稿保密与数据保密，与服务方声明的数据处理政策无关。在需要 AI 处理在审材料时，应使用机构批准的内部部署方案（18.3）。

### 18.6.4 政策差异与查阅

各出版机构、学会与会议对 AI 使用的政策更新频繁，且在细节上存在差异：有的要求声明具体工具与版本，有的禁止生成图像，有的对评审环节有专门规定，有的要求填写标准化披露表。本章不对任何一家机构的具体条款作断言。**投稿前必须查阅目标出版方的当期作者指南**，并在有疑问时向编辑部询问；同一份稿件投往不同期刊时应分别核对。

查阅本身可以按一个固定顺序进行，避免漏项：

1. 在目标出版方官网的作者指南（Author Guidelines / Editorial Policies 类页面）中检索"AI""生成式""generative"等关键词，确认是否有专门章节；
2. 检查投稿系统中是否有标准化的 AI 使用声明字段，有则按字段填写，字段之外的补充写进稿件；
3. 会议稿件另查会议自身的政策页——会议政策常与所属学会的政策不一致，且可能仅适用于某一届；
4. 同行评审环节单独确认：是否允许审稿人用 AI 处理在审稿件，与作者侧政策是两回事；
5. 找不到明确条款时，向编辑部书面询问并保存回复全文，口头或社交媒体答复不作数；
6. 每次查阅记录日期与页面标题。政策更新频繁，查阅记录本身是 18.9 留证体系的一部分。

以上步骤的输出是一份随稿件归档的核查记录：查了哪里、查到什么、没查到什么、何时查的。所有条款性判断均以对方当期官方文本为准。

### 18.6.5 可复制的披露模板

以下四份模板分别对应期刊投稿（中文稿）、期刊投稿（英文稿）、课程作业与代码仓库 README 四种场景，均按 18.6.1 的四要素组织，使用时逐字复制后替换尖括号内的占位内容，删去不适用的条目，并按目标期刊或课程的当期要求调整措辞与位置。模板本身不能替代 18.6.4 的政策核查。

**模板一：期刊投稿用（中文稿）。**

## 18.7 人类受试者与伦理审查

### 18.7.1 伦理审查的范围

涉及人类受试者的研究需经机构审查委员会（Institutional Review Board, IRB；国内称伦理委员会）审查。审查类型通常分为免于审查（exempt）、快速审查（expedited）与全体会议审查（full board），三者的适用条件由各机构自行规定并受当地法规约束，**具体适用以所在机构的规定为准**。判断的一般依据是研究中涉及的风险水平、是否涉及弱势群体、以及数据是否可识别到个人。

使用 AI 本身通常不触发额外的伦理审查，但下列情形会改变审查判断：把受试者数据传给第三方服务（数据流向变化，需更新知情同意与协议）、用模型对个人做出影响其利益的判断（风险水平上升）、以及对已有数据做超出原知情同意范围的新用途（需重新评估或申请豁免）。

### 18.7.2 知情同意的要素

知情同意文件应覆盖：研究目的、参与者的具体任务与耗时、可预见的风险与不适、预期受益（若无可声明无直接受益）、自愿参与与随时退出且不受不利后果、数据的用途与保存期限、是否用于二次研究、以及隐私保护措施与残余风险。

当研究涉及 AI 处理时，还应在同意书中说明数据是否会被传输出机构、由哪些系统处理、以及处理方是谁。若原同意书未涵盖此类处理，则需要修订协议或申请豁免，而不能用"数据已去标识化"自行替代——如 18.3.3 所述，去标识化不等于匿名化。

### 18.7.3 去标识化的统计界限

措施与残余风险的对应关系见下表。

| 措施 | 降低的风险 | 残余风险 | 统计代价 |
|---|---|---|---|
| 删除直接标识符 | 直接识别 | 准标识符链接攻击 | 低 |
| 泛化（年龄分组、日期粗化） | 唯一性 | 分组过粗导致信息损失 | 中（效应估计精度下降） |
| 抑制（删除稀有取值） | 小等价类 | 样本减少，选择性偏差 | 中高（可能引入偏差） |
| k-匿名（等价类 $\ge k$） | 精确匹配链接 | 等价类内同质攻击 | 中 |
| 数据合成 | 记录级泄露 | 分布泄露、效用损失 | 高（需评估分布保真度） |
| 差分隐私机制 | 推断攻击（有形式保证） | 预算过大时保证弱 | 可量化（见 18.4.4） |

需要强调最后两行的区别：合成数据与匿名化提供了"看起来安全"的结果，其保护强度依赖于攻击者的能力与数据的具体结构；差分隐私给出的是在定义下成立的形式保证，代价是效用损失且损失可被计算。选择哪一个取决于威胁模型与可接受的效用损失。

### 18.7.4 数据使用协议与访问审批

外部数据的获取通常伴随数据使用协议（Data Use Agreement, DUA），其中规定允许的分析类型、禁止的再分发、保存环境与期限、以及销毁要求。审批环节应记录：申请人、用途、涉及的数据字段、分析环境是否满足协议要求（例如是否禁止云上处理）、以及到期后的销毁计划。这些记录构成 18.9 审计日志的一部分。

## 18.8 偏见、公平与环境成本

### 18.8.1 群体公平的定义

设 $A\in\{0,1\}$ 为群体属性（如性别、族裔），$\hat Y\in\{0,1\}$ 为预测，$Y$ 为真实结果，$S$ 为模型给出的风险分数。三个最常用的群体公平准则为：

**统计均等（statistical parity / demographic parity）**：
$$\Pr[\hat Y=1\mid A=0]=\Pr[\hat Y=1\mid A=1].$$

**均衡赔率（equalized odds）**：
$$\Pr[\hat Y=1\mid A=a, Y=y]\ \text{对 } a\in\{0,1\}\text{ 相同，且对每个 } y\in\{0,1\}\text{ 分别成立}.$$

**校准（calibration）**：
$$\Pr[Y=1\mid S=s, A=a]=s,\quad \forall s,\ a .$$

三者的含义不同：统计均等要求不同群体获得正向预测的比例相同；均衡赔率要求真阳性率与假阳性率在群体间相同；校准要求分数本身在所有群体中具有相同的条件概率含义。

### 18.8.2 不可兼得的结果

三个准则在一般情况下不能同时满足，这一结论来自两项相互独立的工作：Kleinberg、Mullainathan 与 Raghavan（2016）在风险评分的语境下证明，校准、真阳性率平衡与假阳性率平衡三者不能同时成立，除非各群体的基率相等或预测器达到完美；Chouldechova（2017）给出了校准与错误率平衡在不同基率下的不相容性。

直觉可以这样理解：若两个群体的结果基率 $\Pr[Y=1\mid A=a]$ 不同，则要在所有分数段上都保持校准，各群体的分数分布形状必须不同；而均衡赔率要求两个群体的假阳性与真阳性比例一致，这恰恰对分数分布施加了另一种约束。两组约束只有在退化情形下才能同时满足——要么基率本来相等，要么预测器足够准确以至于约束变得平凡。

这一结果与统计学中的若干经典结论同构：它是一组条件概率约束的不相容，性质上与 Simpson 悖论、条件独立与边缘独立不能互推属于同一类现象。实践含义是明确的：**不存在"同时满足所有公平准则"的模型，选择哪一个准则是一个必须被显式论证的价值判断**，而不是一个技术调优问题。论文中应写明选择了哪个准则、为什么、以及这一选择对各群体的具体影响。

### 18.8.3 公平性指标的估计问题

公平性准则是关于分布的量，实践中只能用样本估计，因此附带抽样误差。两个常被忽略的问题：

其一，小群体上的公平指标方差很大。若某群体样本量为数十，则其真阳性率的置信区间可以宽到使"是否存在差异"这一问题无法回答。分群体报告时必须同时给出样本量与置信区间，否则"某群体表现较差"可能只是噪声。

其二，在多个群体或多个准则上分别检验会引入多重比较问题，需要用第 16 章的方法校正。此外，若在模型选择阶段依据公平性指标反复调参并在同一份数据上评估，会重演选择性推断的问题，应留出独立的评估集。

### 18.8.4 环境成本的核算

算力消耗的环境成本通常换算为电能与碳排放。核算分为三层，精度与所需数据各不相同。

| 层次 | 方法 | 精度 | 所需数据 | 主要不确定性 |
|---|---|---|---|---|
| 直接测量 | GPU/整机功率采样后积分 | 高 | 功率采样序列 | 分摊口径（多任务共享一台机器） |
| 估算 | 硬件功耗模型 × 利用率 × 时长 | 中 | 型号、利用率、时长 | 功耗模型的代表性 |
| 粗算 | GPU 小时 × 型号标称功耗 | 低 | 型号与时长 | 实际利用率与标称值差异大 |

由电能换算碳排需要两项外部参数：数据中心的电能使用效率（PUE，即总设施能耗与 IT 设备能耗之比）与所在电网的碳强度（单位电能的碳排放，随地区与时间变化）。两项取值可以相差数倍，因此碳排估算应连同假设一起报告，并给出区间而非单点值。

统计学者在此可以贡献两点：一是把能耗与碳排当作带测量误差的量来处理，报告估算的不确定来源与量级，而不是给出一位有效数字的确定值；二是区分三个阶段的消耗——训练（一次性）、推理（随使用量累积）、以及实验与调参（常被忽略，但在探索性研究中可能超过最终训练）。第 17 章 17.3.4 给出的采样与估算命令在此直接适用。

## 18.9 权限、审批与审计日志

### 18.9.1 最小权限与密钥管理

最小权限原则（principle of least privilege）要求每个主体只被授予完成其任务所必需的最小权限，并在任务结束后收回。落实在科研项目上的具体动作是：按角色分离权限（数据访问、模型训练、部署发布分属不同角色）、给临时成员设置明确到期时间、以及为自动化流程使用独立的机器账号而非个人账号。

密钥管理的四条硬性要求：密钥不进代码仓库、不进容器镜像、不进日志与错误消息、不通过聊天工具传输；密钥存放于密钥管理器或环境变量注入；按固定周期轮换并在人员变动时立即轮换；为密钥设置最小作用域与配额上限。第 17 章 17.8.2 提到的"先清理后保存镜像"正是这一要求在云环境上的体现。

### 18.9.2 审批流

三类动作建议设置审批：数据访问（尤其是涉密与受试者数据）、外部服务的使用（涉及数据出域）、以及模型与数据的对外发布。审批记录应包含申请人、用途、涉及的数据与范围、审批人、有效期与到期处置方式。审批的价值不在于流程本身，而在于它强制产生一份可回溯的决策记录，使责任边界清晰。

### 18.9.3 审计日志

审计日志记录"谁、在什么时间、对哪个对象、执行了什么操作、结果如何"。完整性要求包括：追加写入（append-only，禁止修改历史记录）、防止删除（一次写入多次读取介质或异地留存）、以及定期用哈希链或摘要比对检查是否被篡改。

| 控制项 | 实施手段 | 检查方式 | 常见疏漏 |
|---|---|---|---|
| 数据访问 | 角色授权 + 访问日志 | 定期抽样核对授权名单与实际访问 | 临时账号到期未回收 |
| 密钥使用 | 密钥管理器 + 使用日志 | 检查是否有超范围调用与异常地域 | 密钥硬编码在脚本中 |
| 模型发布 | 发布审批 + 版本登记 | 核对已发布版本与审批记录 | 通过个人账号绕过流程 |
| 数据外发 | 出网审计 + 审批 | 检查出网流量与外发记录 | 通过网盘或个人邮箱外发 |
| 日志留存 | 追加写入 + 异地备份 | 定期做完整性与覆盖率检查 | 日志本身含个人信息未脱敏 |

```python
# 审计日志的哈希链：追加写入并在链中嵌入上一条记录的哈希
import hashlib, json, pathlib, datetime

LOG = pathlib.Path("audit/log.jsonl")
PREV = pathlib.Path("audit/chain.head")

def append_event(actor: str, action: str, obj: str, result: str, note: str = ""):
    prev = PREV.read_text().strip() if PREV.exists() else "genesis"
    ev = {"ts": datetime.datetime.now(datetime.timezone.utc).isoformat(),
          "actor": actor, "action": action, "object": obj,
          "result": result, "note": note, "prev": prev}
    body = json.dumps({k: v for k, v in ev.items() if k != "prev"},
                      ensure_ascii=False, sort_keys=True)
    ev["hash"] = hashlib.sha256((prev + body).encode()).hexdigest()
    with LOG.open("a", encoding="utf-8") as f:
        f.write(json.dumps(ev, ensure_ascii=False, sort_keys=True) + "\n")
    PREV.write_text(ev["hash"])
    return ev["hash"]

# 完整性校验：从头重算哈希链，任一行被改动都会导致校验失败
def verify_chain():
    head, prev = "genesis", "genesis"
    for line in LOG.read_text(encoding="utf-8").splitlines():
        ev = json.loads(line)
        body = json.dumps({k: v for k, v in ev.items() if k not in ("prev", "hash")},
                          ensure_ascii=False, sort_keys=True)
        if ev["prev"] != prev or ev["hash"] != hashlib.sha256((prev + body).encode()).hexdigest():
            return False, ev
        prev = ev["hash"]; head = ev["hash"]
    return True, head
```

两点容易被忽略。第一，**日志的覆盖率需要被估计**：日志系统可能因配置错误、磁盘写满或服务重启而缺失部分记录，缺失率未知时的日志不能作为完备证据。可行的检查方式是用一个独立的信号源（例如对象存储的访问记录）与审计日志做交叉比对，估计覆盖率。这与统计学中的捕获—再捕获（capture-recapture）思路相同。第二，**日志本身可能含个人信息**（操作记录中的文件名、数据片段、IP 地址），需要对日志做脱敏并设置独立的访问权限。

## 本章小结

1. 威胁模型由资产、攻击面与攻击者能力三要素构成；科研场景的五类主要威胁是数据外泄、结果篡改、知识产权流失、提示注入导致的误判、算力滥用。
2. OWASP LLM Top 10 是风险意识清单而非合规标准，条目随版本重排，引用时以官方当期发布为准；其中提示注入源于模型无法区分指令与数据的架构限制，只能靠工程手段缓解。
3. 本地部署解决数据出域问题，但残留遥测出网、监听暴露、磁盘缓存与供应链四类风险；去标识化不等于匿名化，准标识符维度越高，删除直接标识符的保护作用越弱——18.3.3 的最小模拟显示，五个常见准标识符加到四项时唯一记录比例已约 76%。
4. $(\epsilon,\delta)$-DP 的保证不依赖攻击者的辅助信息；其统计代价可量化，对有界区间上的均值发布，隐私噪声方差与抽样方差之比为 $2(u-l)^2/(n\epsilon^2\sigma^2)$，随样本量增大而下降。
5. DP 下的置信区间必须包含隐私噪声项，样本量规划与功效计算需在 $(\epsilon,\delta)$ 约束下重做；DP-SGD 的预算随训练步数累积，需隐私会计跟踪。
6. 联邦学习按数据划分分为横向、纵向与联邦迁移三类；统计异构引入不随通信轮数消失的客户端漂移偏差，部分参与引入类似整群抽样的客户端抽样方差，站点应作为随机或固定效应显式建模。
7. 模型权重许可、训练数据许可与代码依赖许可是三个独立对象，可行使用范围取三者的交集；宽松许可与 copyleft 的兼容性判定取决于是否构成衍生作品。
8. AI 使用披露的四要素是用途、工具、日期与范围；AI 系统不能作为作者；各出版机构政策更新频繁，投稿前须按 18.6.4 的顺序查阅当期作者指南，并可用 18.6.5 的模板逐字填写声明。
9. 群体公平的三个常用准则（统计均等、均衡赔率、校准）在各群体基率不同时不可兼得，准则的选择是必须显式论证的价值判断；公平指标在小群体上方差大，需报告样本量与置信区间。
10. 审计日志需保证追加写入与异地留存，其覆盖率本身应被估计；日志含个人信息时需脱敏并设置独立权限。
